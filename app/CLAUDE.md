# Swift macOS app (MLX Core) — AI context

Compressed rules. Full war stories: `../docs/gotchas/app.md`. Full service contracts: `../docs/reference.md`. Repo-wide policy (TDD, release, conventions): root `../CLAUDE.md`.

## Build

- ALWAYS ship via `bash app/build.sh` (signs, entitlements, links Zig artifacts, keeps MLXCore + mlx-serve in lockstep); dev: `SKIP_NOTARIZE=1`. Swift-only fast iteration escape hatch: `cd app && swift build -c release -Xswiftc -swift-version -Xswiftc 5` (flag vestigial since swift-sdk 0.12.1 — keep sdk >= 0.12.1; 0.10.x cannot compile in the MAS Xcode project).
- The .app bundles TWO binaries (MLXCore UI + mlx-serve server) — always update together; a stale sibling is the classic "still doesn't work".
- Agent Sandbox needs `com.apple.security.virtualization` in BOTH signing branches of build.sh (ad-hoc included) or VZ refuses to boot. `swift build` binaries / xctest can't boot VMs; live guard = `SANDBOX_SMOKE=1 <MLXCore binary>`.

## Rules

- **Per-chat tool switches SUBTRACT at the resolution chokepoint, never at a turn site** (Tools pill → chevron menu): `AppDefaultsSnapshot.disabledTools` is removed from whatever the agent (or the app defaults) already allowed, so a chat tab can never grant a capability an agent forbids — forbidden rows render disabled rather than offering a switch the resolver would ignore. Turning everything off makes the turn plain chat (`loopRuns`: advertising nothing while still looping is a dead offer). `searchDocuments` is exempt from BOTH the menu and the subtraction — its gate is the attached folder, which is stronger — and `AgentToolKind.chatToggleable` × `AgentToolGroup` are pinned against each other (a tool in no group is unreachable from the UI; one in two renders twice). Stored on the session as RAW STRINGS so a retired tool leaves an unknown name instead of failing the whole session's decode. Guards: `SessionToolDisableTests`.
- **The chat generates media itself, at PREVIEW settings, one per message** (`generate_image` / `generate_speech` / `generate_music` / `generate_video`): speech and music are separate tools because music IS audio and one overloaded tool makes a 2B guess (`generate_audio` was split — `Agent.renamedTools` maps the old name, since the capability decoder DROPS names it doesn't know and a plain rename would silently strip the capability from every agent that had it). The model picks nothing but the prompt: which model comes from the user's saved settings for that modality, the step/duration knobs from `MediaChatDefaults` (a chat generation blocks chat decode on the one GPU, so it is a preview and the tray window stays the place for full-quality work), and every number it CAN send is clamped in `MediaToolArgs` — a 4B asking for 30 seconds of video is not hypothetical (measured: clamped to 4.0s). Read the spellings models actually emit: asked for "widescreen" a model sends `{"size":"16:9"}`, and an aspect resolves against the user's OWN size (an exact-ratio match escalated a preview to the model's largest 16:9, 8× the pixels). **One generation per USER TURN**, keyed by a turn TOKEN the driver passes rather than a `reset()` it must remember — as a reset call, the headless harness (a second driver on the same engine) inherited a spent budget and silently refused every generation forever. The refusal leads with **"NOT GENERATED"** and the words to relay: with the rule first and the fact second, a refused 4B told the user both items had been made. Music takes the WHOLE knob set the engine reads (`bpm` 30–300 — outside it the server 400s, so it clamps; `keyscale`, `time_signature`, `vocal_language`), each validated against `MusicOptions` — the catalogue IS the accepted grammar — and OMITTED when unrecognised, because only `bpm` is checked server-side and an unknown `keyscale` goes into the conditioning as junk (an absent field is the engine's own "model decides"). Results ride `ChatMessage.media` as a PATH (`ChatMediaRef`) — a 30 s track is tens of MB and `chat-history.json` would carry it forever. An IMAGE carries both: the JPEG bytes the transcript draws AND a `.image` ref for the same Reveal-in-Finder row a track gets, which is why the ref line sits BETWEEN the caption and the data URI (after it, the caption swallows the whole base64) and why both land on ONE message. A missing file is its own row — except for an image, whose picture is still on screen, so the row just disappears. Guards: `MediaToolArgsTests`, `MediaGenProgressTests`, `AgentMediaInlineTests`.
- **A media generation shows a meter or it reads as a hang**: `ChatTurnEngine.mediaProgress` (ONE value — the inference thread serializes media gen) drives `MediaProgressCard`, determinate when the engine reports a total and indeterminate when it doesn't (TTS length is model-determined, so it sends a growing frame count against total 0 and a bar at 0/0 looks stuck). Elapsed time is a `TimelineView(.periodic)`, never a `repeatForever` animation or a `Timer` — that is the `VoicePulse` tray-wedge class. The four services' identical SSE parsing collapsed into `MediaSSE.classify`; each gained a `generateForAgent(_:server:onProgress:)` that runs the same load → stream → write → unload pipeline WITHOUT touching its pane's `phase`/`task`/`recent`, so a chat generation never hijacks the tray window.
- **A failure is its own transcript row, not text appended to the model's answer**: `[Error: …]` glued onto the assistant's own content read as something the model said and gave the user nothing to do. `ChatErrorNotice` classifies it — `.contextOverflow` (the one failure fixable from here) carries the server's real counts and offers "Increase Context Size"; everything else stays `.generic` and shows the server's wording verbatim, because guessing a diagnosis sends people to change settings that were never the problem. The notice message is `failedRetry`, so it renders but is excluded from the history sent back (an error card fed in as assistant output is how a model starts apologising for a server failure). The counts only exist because the server puts them in the 400 — see the root `## HTTP APIs` note. Guards: `ChatErrorNoticeTests`.
- **The context readout is UNCLAMPED; only the bar it sits next to is clamped** (`ContextWindowStats` vs `ContextMonitor.usedTokens`): the moment anyone looks at that number is the moment they went over, so it must be able to say 100.3%. After a REJECTED request the rejected request's own counts win over the last successful turn's, which are stale and read comfortably under the limit exactly when the user is trying to find out why it failed. The full-width bar above the composer is retired — it spent a permanent strip on a number that matters occasionally and still couldn't say what was in the context; the pill puts the breakdown one click away. Guards: `ContextWindowStatsTests`.
- **Code blocks are their own views; prose RUNS stay one text view** (`MarkdownSegmenter` splits at FENCES, not at markdown blocks): splitting per block is what broke drag-selection at every heading. The trade is deliberate — each block becomes its own selection island, and buys stable line numbers, per-token colour and a copy button that yields the code alone. The lexer emits **UTF-16** spans (a Character offset is short by one for every emoji earlier in the block and mis-colours everything after it), recognizes comments before strings and strings before everything else, and runs unterminated comments/strings to end-of-source because a streaming reply is in that state constantly. An unknown fence gets NO colour — guessing a language and painting prose as code reads worse than plain. Guards: `SyntaxHighlighterTests` (incl. a sorted/non-overlapping/in-bounds invariant over every language), `MarkdownSegmenterTests`, `CodeLayoutTests`.
- **The model picker rides its OWN leading toolbar item, width-capped**: the trailing cluster is at its budget and a model name is runtime-variable — precisely what re-triggers the » eviction class (see the NSToolbar rule below). Its tag semantics live in `ChatModelSelection`, shared with the tray, because a per-surface copy is how one picker silently stops honouring a LAN selection (same class as routing through `server.chatModelId`). Guards: `ChatModelSelectionTests`.
- **Web-search provenance is recovered from the HIDDEN tool results, and is never guessed**: the transcript filters those messages out, so without `WebSourceExtractor` the user reads a confident answer with no way to check it. A block counts as a source only when its second line is an http(s) URL — the handler falls back to dumping raw page text when a search returns nothing, and presenting that as sources would be fabricating citations. The walk stops at the previous user message so an earlier turn's search can't be cited by a later answer. Favicons are best-effort with a monogram fallback, attempted ONCE per domain (a retry-per-render hammers the host for as long as the chat is open). Guards: `WebSourceExtractorTests`.
- **The chat toolbar holds ONE floating cluster; everything that configures the MESSAGE lives in the composer**: model picker + voice + settings ride a single real `ToolbarItem` (that band's layer swallows clicks from anything else — a custom strip pulled in via ignoresSafeArea looked native and was completely dead), but the band's own 100%-width background is HIDDEN and the cluster carries its own material. That material is load-bearing: it is the reason content scrolling underneath doesn't bleed through the controls, which is what the old 0.8-opacity strip existed for. Think / Tools / MCP moved OUT to the composer row as icon-only discs — their captions were most of the cluster's width budget, and they configure the turn being written, not the window. Icon-only means state reads from COLOUR alone (`modeIcon`), and it means a bare glyph must not mean two things depending on WHERE you click — but it may mean two things by which BUTTON: Tools and MCP toggle on click (`Menu { … } primaryAction:`) and open their configuration list (per-tool switches + workspace / the Marketplace) on secondary-click, which is also where press-and-hold lands. These are the most-flipped controls in the composer, so on/off must not cost a click plus a scan down a menu; the menus carry NO on/off row (one boolean, one control) and the tooltip names the right-click, because nothing else announces it. Guard: `ComposerModeControlTests`. `ChatMetrics.togglePill*` is retired — those controls share `composerIconSize`/`composerControlSize` with the rest of the row.
- **An empty app opens a composer, not a wall**: with no valid session the detail pane creates one in `onAppear` (never during the view update) instead of showing "Start a conversation" + a button; `ChatDetailView` already renders the greeting above a centered composer while a conversation has no messages, so a fresh launch and a fresh chat look the same, and sending the first message moves it to the bottom.
- **Only the USER gets a bubble**: an assistant reply is the column's main content — long, formatted, full of code blocks and tables — and boxing it wastes the width and fights every block that wants the full measure. Tool-call summaries keep their card so they still read as machinery. The footer's actions are ALWAYS visible and pinned to the trailing edge past the stats: hover-reveal moved them under the pointer as the row re-rendered mid-stream and made them awkward to hit, and a trailing anchor puts them in the same place on every message rather than at a spot that shifts with the stats text's length. `deleteMessage` takes the turn's hidden tool results with it — an orphaned tool result is invisible, so nothing would ever clean it up, and the model can only be confused by it.
- **A turn site never reads a global setting directly — it reads `ResolvedAgentSettings`** (agents/personas). Five surfaces start turns (chat tab, voice tray, scheduled task, Telegram, Quick Launcher) and they all build their `TurnConfig` through the ONE builder `TurnConfig.from(resolved)` out of `AgentResolution.resolve(agent:defaults:)`; the surface's own toggles are the DEFAULTS the agent overrides. Same class as the LAN rule (`server.chatModelId`, never `modelInfo?.name` at a new surface): a per-surface read is exactly how one surface silently ignores the agent. Corollaries the wiring forced: **`agent == nil` must reproduce today's behavior field for field** (`AgentResolutionTests` asserts it; `ChatSession.agentId`/`ScheduledTask.agentId`/`telegram.agentId` all decode absent → nil), and **the two chat paths do NOT share a sampling default** (the tool loop's `agentLoopTemperature` 0.7 vs plain chat's `defaultTemperature`), so the resolution carries the agent's RAW `temperatureOverride`/`maxTokensOverride` alongside the decided values — a "decided" number in `TurnConfig` would silently move one of them for every user who never makes an agent. An agent owns everything EXCEPT the Agent Sandbox, which stays one global flag.
- **Every agent owns its own chat thread** (`AppState.sessionForAgent`): a voice turn routes by AGENT, not by whichever tab is open, so speaking to Chef continues Chef's conversation (created on first use) instead of talking into someone else's — and a spoken handover moves the conversation rather than rebranding the one you were having (no `setAgent` on the session it leaves). An ACTIVE thread of the same agent beats a more recently touched one (the user opened that one deliberately), and task-run / Telegram-bridge sessions are NEVER adopted — they carry an `agentId` now too, and they're hidden, transient or read-only. The chosen thread must also become `activeChatId`: the voice controller speaks the ACTIVE session's trailing assistant message, so a turn running anywhere else is never read aloud. Tray "New" creates a fresh thread for the SAME agent and leaves the old one in the sidebar; launching voice from a chat tab adopts that tab's agent, or a tray default would pull the conversation out of the tab you launched from. Guard: `AgentSessionThreadTests`.
- **Answer length is written INTO the prompt, not exposed as a knob**: a persona covers role, expertise, tone and priorities and says nothing about LENGTH, and outside voice mode nothing else does either (plain chat has no system message, the tool-loop prompt is about tools) — so agents answered at essay length. Fixed in the AI-WRITE path only: `AgentWriter.instructions` asks the model for its own brevity instruction, and `AgentWriter.concise(_:)` appends `brevityLine` when it didn't (`mentionsBrevity` covers the phrasings models actually use, so it's never doubled; the prose is trimmed first so a budget-filling prompt can't push the line off the end). The line is then ordinary prompt TEXT — visible in the editor, rewordable, deletable — instead of a setting to find, and a prompt the user typed is never rewritten. It's applied by `AgentComposer.draftAgent`, NOT by `parse`/`fallbackDraft`, which stay byte-identical to the iPhone's so the port keeps transplanting (three ported tests assert exact prompt equality — they're the tripwire). Starters carry the same expectation in their own wording. Guard: `AgentBrevityTests`.
- **Voice-mode guidance is appended LAST, so it must not claim an IDENTITY when a persona is present** (`VoicePrompt.speakingStyle(phrase:hasPersona:)`): it opened with "You are <wake-phrase name>, a friendly hands-free voice assistant", which — being last, deliberately, so its style rules win conflicts — overrode the agent above it and the agent introduced itself as Jarvis (live 2026-07-26). With a persona the prompt carries the DELIVERY rules only (one shared `deliveryRules` block, so the two modes can't drift) plus "stay exactly the assistant described above"; with no agent the old text is byte-identical. The phrase itself comes from `ResolvedAgentSettings.wakePhrase` via `TurnConfig`, not `serverOptions`, so an agent with its own phrase is named by it. Guard: `VoicePromptTests` persona cases.
- **The persona goes in the STABLE prefix, never the volatile tail** (`composeSystemPrompt(persona:stable:volatileTail:grounding:)`): the tail is re-prefilled every turn, so a persona there costs a re-prefill per MESSAGE instead of one per agent switch. Empty persona ⇒ byte-identical prompt to the pre-agents build. Plain chat has no system message by design, so a persona there is ONE synthesized system message shared with voice-style guidance (persona first), not a second one.
- **Gating the advertised tool list is not enough — dispatch refuses too** (models call tools that were never advertised): `AgentPrompt.toolDefinitionsJSON(allowing:)` filters the literal LINE-BASED (a JSONSerialization round-trip would reorder keys and lose `path` before `content`), and `AgentEngine.disallowedToolRefusal` runs at the TOP of `executeToolCall`, ahead of the meta-tools (`createTask`, `generate_*`) which aren't ToolHandlers. Same belt-and-braces shape as `FileToolSandboxGate`. `allowedTools: nil` gates nothing (TestServer, older surfaces). Two class guards: `AgentToolKind`'s raw values and the parsed `AgentPrompt.toolDefinitions` names must be equal BOTH ways (a tool in the JSON with no case is ungateable — a silent hole in every agent's capability list), and every kind must belong to a coarse group (`loopTools` / `webTools` / the docs gate) or it's unreachable from the UI. `searchDocuments` is deliberately outside the capability toggles — its gate is the attached folder, which is stronger — so it always rides `ResolvedAgentSettings.tools`.
- **An agent's model is never implicitly downloaded, and a spoken switch that can't happen is declined OUT LOUD** (`AgentModelSwitch`): pinned-but-missing ⇒ `.needsDownload` (greyed row + Download button), an unknown `id@peer` ⇒ `.unavailable`, a known LAN id passes through with no local load (`server.lanChatModelId`), and only `.load` calls `useModelAndAwaitReady`. `spokenDecline` is what the voice path says — silently answering as whoever was active is the failure the user can't see.
- **An agent switch remounts the sandbox like the Settings pick, and NEVER writes the global default workspace** (`AgentWorkspaceSwitch.decide` → `noteWorkspaceChanged(_:restartPinnedSessions: true)`): agents carry their own folders, so a switch can move the ground under a live pinned CLI session — that's EXPLICIT intent (restart the sessions in place), not the implicit chat-tab pick the pin declines. Writing `setDefaultAgentWorkspace` there would retarget every session still on the old default, with nothing in the UI to show it; a source audit pins that. Per-agent folders need per-agent bookmarks (`SecurityScopedBookmark.agentWorkspaceName(id)`) — the global default's slot can't stand in.
- **The clone model is resolved against the DISK, and the agent voice is published PER TURN** — two silent-fallback bugs from the same live report ("my uploaded wav isn't going through Qwen3-TTS"). (1) `VoiceCloneTTS` loaded `AudioGenSettings.resolvedModel`, which defaults to the 0.6B repo, so a machine holding only the 1.7B variants resolved no model, `synthesize` returned nil, and every sentence fell back to the system voice while the picker still ticked the clip: `VoiceCloneMenuModel.resolvedCloneModel` now prefers the configured preset when present and otherwise ANY downloaded cloning-capable one (never Kokoro — `ref_audio` there is a named 400), and `ttsModelDownloaded` reads the same answer so the UI can't offer what won't speak. (2) `ActiveAgentVoice` was set only on agent SELECTION, so editing the active agent's voice — or answering as a tab's agent that isn't the tray's — spoke in the app's voice; `runTurn` now publishes `config.voice` (the agent's RAW `voiceOverride`, nil when it has none, so the live per-utterance Settings read is untouched). Guards: `VoiceCloneModelResolutionTests`, `AgentTurnConfigTests` voice cases.
- **Uploaded voice clips are a LIBRARY, not one file** (`VoiceClipLibrary`, sharing `~/.mlx-serve/voice-clips` with the global Settings clip): every upload used to overwrite the single `voice-clone.wav`, which silently cost you the previous clip and would have let a Settings re-record change an agent's voice under it. Clips keep the picked file's own name (`basename`, deduped `morgan` → `morgan-2`, never the global clip's name), are normalized to the same 24 kHz mono wav the TTS reference path wants, and the global clip is filtered OUT of the listing so it can't appear twice. The Agents editor and Settings ▸ Voice read and write the one library, so a clip added in either is selectable in the other; the folder is Finder-managed (like skills), and the listing is snapshotted per appearance — never per render, since those menu bodies re-evaluate ~20 Hz while speaking. **Preview plays the FILE for a clone voice** (`VoicePreviewer.playClip`): auditioning a reference recording asks "is this the right take?", which the raw audio answers instantly and with no model downloaded — Kokoro still synthesizes a sample sentence and the system voice speaks one. Guards: `VoiceClipLibraryTests`, `VoicePreviewerTests` playClip cases.
- **A per-agent voice hangs on the synthesizer's per-utterance re-read, not on new plumbing**: `ClonedVoiceSynthesizer`'s production `voice:` closure already re-read `ServerOptions.load()` once per utterance, so `ActiveAgentVoice` (a lock-guarded holder, because the closure isn't main-actor bound) is consulted first and the voice applies from the very next sentence. `.system` must WIN rather than fall through — an agent asking for the plain Apple voice against a global Kokoro setting would otherwise still sound neural — while a half-saved empty value defers to the global setting instead of producing silence.
- **The Agents editor is Identity + Prompt; everything else is behind "More options"**: an agent is a name, a symbol, a wake phrase, a VOICE and a prompt — voice moved INTO Identity because how it sounds is the same kind of fact as what it's called. Capabilities / Model / Workspace / Sampling are real but rarely touched, and five sections of them between "what should this be?" and Delete made the editor read as a settings panel. Collapsing them creates one hazard — a setting that IS set but invisible, because nobody expands a row that looks empty — so the row carries `AgentAdvancedSummary.text(for:)`, naming every collapsed area that differs from the defaults (`web` defaults ON, so its ABSENCE is what's named; empty-string paths are not pins; the tri-state thinking/approval overrides count). The disclosure is a Button gating four `Section`s rather than a `DisclosureGroup` around them — nesting sections inside a disclosure loses their headers and grouped-form styling — and it resets on the agent-id change like `showAdvancedTools` (the editor is REUSED across selections). Guards: `AgentAdvancedSummaryTests`.
- **The voice-mode orb picks no voice**: the speaking voice belongs to WHO is answering, so it is set where that is decided — Settings ▸ Voice for the app's own, the Agents editor for an agent's — and `ClonedVoiceSynthesizer` re-reads it per utterance, so a change applies from the next sentence with no control in the orb. The sheet's `VoiceSelectorMenu` is deleted rather than hidden: a third picker could only disagree with the two that own the value. The sheet's height floor dropped with it (660 → 560).
- **The phrase hands-free LISTENS for follows the active agent, not just Settings** (`WakeWord.activePhrase`): voice launched from a chat adopts that chat's agent — persona, voice, tools — and the phrase has to come along, or an agent that introduces itself by name still only answers to "hey loki" while the "Say “…”" hint tells the user to say the wrong thing. The controller binds it to `serverOptions` × `defaultAgentId`, because that id is what EVERY route to "who is answering" already sets (tray pick, spoken handover via `selectAgent`, and `startVoiceMode` adopting the tab's agent) — so the phrase tracks a handover mid-session too. A blank or whitespace-only agent field defers to the global setting rather than producing a gate that never matches, and an empty global still resolves to `defaultPhrase` (`""` would make `strip` match everything). The agent's VOICE needs no new plumbing: `ChatTurnEngine.runTurn` publishes `config.voice` per turn and `defaultAgentId`'s didSet runs `applyAgentSelection`. Guards: `VoiceAgentWakePhraseTests`.
- **The sidebar is the conversation list — nothing else navigates from it**: Agents and Models are reached from the chat toolbar ("Manage Agents…" in the composer's agent chip, "Manage Models…" in the model picker), each next to the control it configures. A chat's agent shows on the row's TIMESTAMP line, never the title's: a long agent name would otherwise squeeze the title, which is what the row is for.
- **Hands-free listens for every agent's phrase at once, longest FIRST** (`WakeWord.match`): "hey loki" is a prefix of "hey loki coder", so a shortest-first sweep makes the specific agent unreachable by voice. `strip` is untouched (single-phrase), the Loki homophone table stays Loki-specific, and colliding phrases are refused at SAVE time (`WakeWord.collides`, keyed on the phrase's last word — greetings are universal, so two phrases ending in the same word are one gate) because there is nothing to see until you try talking.
- **An image preset DECLARES what the backend can do; the pane never guesses** (`ImageModelPreset.supportsImg2Img` / `supportsLoRA` / `supportsReferenceEdit` / `condWeightCount` / `stepsAreFixed`, each mirroring a concrete server fact). Mage-Flow shipped with FIVE dead controls — CFG, negative prompt, conditioning rebalance, LoRA and variation strength — that either did nothing or earned a 400. CFG and negative prompt turned out to be dead for EVERY image backend (`handleImage` parses neither, and `requestJson` never sent them), so both were RIPPED OUT end to end — control, `@State`, `ImageGenSettings`, `ImageQualitySettings`, `ImageGenRequest` — not just hidden. The wire body is unchanged (they never reached it), the tolerant decoder still eats the retired keys from an older build (`testImageSettingsIgnoresRetiredKeysFromOlderBuilds`), and 3D's `guidance` is untouched because `handleMesh` genuinely reads `guidance_scale`. Grep before assuming a field is view-local: the compiler found `ChatTurnEngine` building image requests too. A distilled model (`stepsAreFixed`) hides the quality tiers: they only bought time (measured 4/8/12 steps = 6/12/24 s for a different, not better, image). Where editing exists but img2img doesn't, a source image MEANS edit — `effectiveEditMode` must not depend on a toggle whose picker is hidden. Guards: `testMageFlowDeclaresTheCapabilitiesItActuallyHas`, `testMatchSourceIsOfferedOnlyWhenEditingAndSurvivesModeChanges`.
- **An audio preset DECLARES `supportsCloning`, and the catalog it lives in follows from it**: `AudioModelPreset.all` is the CLONING-CAPABLE media-gen catalog (AudioGenView's reference-clip control and AudioGenService both send `ref_audio`, and VideoGenView's "Speak text" composer picks from the same list), `allIncludingVoiceOnly` is the full list for the model browser and the catalogue guards. A non-cloning backend in `.all` reaches `ref_audio` and earns a named 400, so Kokoro is voice-mode only (Settings ▸ Voice, tray picker, web console) and every path that speaks with it names `.kokoro82M` DIRECTLY, meaning nothing in voice mode depends on `.all`.
