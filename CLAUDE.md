# mlx-serve — project context for AI

Native Zig server running MLX-format LMs on Apple Silicon; OpenAI/Anthropic/Ollama-compatible HTTP APIs + native media generation. No Python. This file is the COMPRESSED layer — telegraphic on purpose; detail lives one hop away.

## Stack

Zig 0.17 (nightly build required until 0.17.0 stable ships — homebrew's zig formula still tracks 0.16.0; see `build.zig`'s version-gate comptime block for why 0.16.0 stopped working: its bundled libc++ fails against the macOS 27 SDK); mlx + mlx-c PINNED SUBMODULES (`lib/mlx-src` v0.32.0, `lib/mlxc-src` fba4470 = brew 0.6.0_3 equivalent) self-built NAX-enabled by `scripts/build-mlx.sh` into `lib/mlx/` (FFI `src/mlx.zig`); llama.cpp C++17 Jinja2 pre-compiled as `lib/jinja_cpp/libjinja.a`; stb_image + libwebp (vision); safetensors; BPE tokenizers. Embedded engines: ds4 (`lib/ds4`, DSV4-Flash GGUF) + libllama (`lib/llama`, generic GGUF).

## Building

- **First-time setup**: `./scripts/fetch-zig.sh` stages the pinned Zig nightly at `.zig-toolchain/` (homebrew's `zig` formula still ships 0.16.0, which no longer builds — see the version-gate comptime block at the top of `build.zig`). Put it on PATH (`export PATH="$PWD/.zig-toolchain:$PATH"`) or invoke `.zig-toolchain/zig` directly. CI runs the same script (`.github/workflows/release.yml`). Retire this once 0.17.0 ships stable and homebrew catches up.
- **Zig 0.17 caches configure-time subprocess output in `.zig-cache`** (`b.runAllowFail` — e.g. build.zig's `xcrun --show-sdk-path`): after a toolchain/SDK change (a macOS upgrade removing the CLT), the link keeps referencing the GHOST path until `rm -rf .zig-cache`. build.sh/xcode-build-server.sh prefer the CLT SDK but fall back to `xcode-select -p` when it's absent (story: docs/gotchas/app.md).
- **ALWAYS `zig build -Doptimize=ReleaseFast` — never bare `zig build`** (Debug is 2–4× slower ⇒ fake regressions; ReleaseFast binary ≈ 7 MB, Debug ≈ 2×). Rebuild the exe before any live perf A/B — `zig build test` does NOT refresh `zig-out/bin/mlx-serve`.
- Swift app: `bash app/build.sh` (see app/CLAUDE.md). The two bundle binaries (MLXCore + mlx-serve) move together.
- mlx + mlx-c are NOT brew deps: pinned submodules built by `scripts/build-mlx.sh` (deployment target 26.2 → MLX's NAX kernels compiled in; script + `tests/test_mlx_staged_nax.sh` ASSERT the metallib contains `*_nax` — the CMake gate fails silently). The brew bottle is built at 26.0 and hard-wires `is_nax_available()` false even on M5. Effective min macOS is 26.2 everywhere (app `LSMinimumSystemVersion`, `Package.swift`, bundled dylibs). Bump = checkout new tag in submodule → rerun script → re-diff `src/mlx.zig` externs. Brew floor remaining: webp ≥ 1.6.0 (`verifyBrewDeps`). mlx v0.32.0 = the runtime the M5 NAX profile was calibrated on.
- Rebuild Jinja after `lib/jinja_cpp/*.cpp` changes: `cd lib/jinja_cpp && for f in jinja_wrapper caps lexer parser runtime jinja_string value; do clang++ -std=c++17 -O2 -DNDEBUG -I . -c $f.cpp -o obj/$f.o; done && ar rcs libjinja.a obj/*.o`

## Testing — TDD is mandatory for every change

Order is fixed: (1) failing test FIRST, failing for the right reason; (2) minimum code to green; (3) full suite (`zig build test` must be 6/6 steps, 0 fail + `cd app && swift test`/`build` + the relevant `tests/*.sh`); (4) then refactor under the tripwire. A live curl is a sanity check, NOT a test.

Per change class: feature = unit test that fails without it (+ integration script if HTTP-observable). Bug fix = regression test red→fix→green, verified red-on-revert. Cross-arch work = cover every touched arch (one arch's pass ≠ the suite's pass). Refactor = characterization test first if coverage is missing. UI/build scripts = factor a pure helper and test that.

**Class bugs get class guards — no whack-a-mole.** A live failure revealing a CLASS (escaping gap, format-family leak, dispatch hole) ships THREE things: the instance regression test; a corpus entry or universal invariant in `src/format_corpus_test.zig` so future families are covered automatically; and a 1–3-line rule in `## Rules` here + full story in `docs/gotchas/` (growth policy above).

Key hermetic suites: `zig build test -Dtest-filter="format corpus"` (captured model outputs × split/strip/parse + no-tag-leak + valid-JSON-args + declared-type + buried-param invariants), `-Dtest-filter="tool traffic"` (replay harness). Full script matrix: `tests/CLAUDE.md`.

## Releases & benchmarking

- Pre-release validation, CalVer versioning, CHANGELOG style: `/release` skill. Same process every time; the per-release perf gate is `./tests/bench.sh --family all` (mlx-serve only, ~4 min) diffed vs `docs/perf-csvs/all-<prev>.csv`; the 4-engine marketing chart only when an ENGINE version bumps. Each release ships exactly one bench CSV+chart and one ladder CSV+chart, generated on the FINAL tree (procedure in /release).
- Bench methodology + traps: `/bench` skill. Hard rules that live here: **diff only against same-methodology CSVs** (`all-*.csv` for `--family all`; 26.7.6 predates verifyQmm AND shared boots); **"reproducible ≠ not variance"** for spec-decode cells — sample across runs/boot-orders before any regression claim; controlled kill-switch A/Bs beat cross-version absolute diffs; **never quote a win without naming the engine it is over**; thermal soak lies harder than drift (same-session ratios only); a bench's port wait-list must equal its kill-list (`stop_all_engines` class); **an A/B arm is proven by ENGAGEMENT/no-engagement lines in its own log, never by its launch env** — zsh does not word-split `env $VAR`, so a multi-switch arm's first switch swallowed the rest as its value and the "composed" arm silently ran the fast path, reading a 2x win as "neutral" for half a session (single-switch arms stayed valid, which made the numbers look internally consistent; live 2026-07-30, story in docs/qwentts-cache.md). The record IS the artifacts: CSVs → `docs/perf-csvs/`, charts → `docs/perf-pngs/`, generated by `tests/bench.sh` + `tests/mtp_ladder_pair.sh` (`BenchmarkLog.md` is retired as a hand-maintained narrative — don't add entries).

## Conventions

- Minimal DRY Zig; tests at the bottom of each source file; shell integration tests in `tests/`.
- Inference thread is the SOLE mlx caller (even array frees) — media gen posts to `gen_queue`, never a gpu mutex. A long gen blocks chat decode (accepted; single GPU).
- Concurrent requests batch-decode on pure-attention archs; `--max-concurrent` sizes the submit queue, not a decode gate. Slots entering a batch mid-generation drain lazy pipeline state first (`drainPipelineForBatch`).
- KV reuse via prompt-prefix matching; invalidated after tool calls + pad-only gens; hot cache spills to the SSD tier; RAM invalidation propagates to disk.
- Chat templates live in model dirs; Jinja renders with fallback formatting.

## Tool calling (server pipeline)

With `tools` present, tokens buffer for detection (`<tool_call>`, Hermes XML, Gemma `<|tool_call>` incl. double-brace unwrap, hy3 suffixed tags, DSV4 wrappers, raw JSON); thinking buffered separately. Parse chain: strict → tolerant repairs → truncation salvage; then the per-request chokepoint `server.parseToolCallsForRequest` = parse → inferred-name filter → parallel clamp (`parallel_tool_calls:false` / Anthropic `tool_choice.disable_parallel_tool_use` keep ONLY the first parsed call — client-requested, so NOT autocorrect-gated; model re-issues the rest next round) → buried-param hoist → schema coercion (hoist+coercion gated by `--no-tool-autocorrect`; a final safety net guarantees emitted `arguments` are ALWAYS valid JSON). Serialization (`chat.serializeMessagesJson`): role "tool" passed natively (Gemma renders `<|turn>tool` — no `tool_responses` field, causes duplicates), args as JSON STRINGS, every arbitrary-byte string through `appendJsonString`. Streaming: full args in ONE SSE delta; thinking buffered until close, emitted as `reasoning_content`. Fallback (`fallbackFormatChat`): ChatML, Llama ipython, Gemma "Tool result:". Client side: `app/CLAUDE.md`.

## Rules (distilled gotchas — full stories in docs/gotchas/)

### Tool calling & formats (→ docs/gotchas/tool-calling.md)

- **Control bytes**: ONE raw byte <0x20 anywhere in history kills the strict nlohmann render → SILENT downgrade to `fallbackFormatChat` → wrong-family tags, model degenerates (loses its stop token). Every arbitrary-byte string goes through `appendJsonString`; render failure logs WARN. Wrong-family tags in output ⇒ suspect silent fallback before suspecting the model.
- **Model-mangled arg JSON**: after strict parse fails, `looseRepairToolCallJson` re-escapes ctl bytes / inner quotes / invalid backslashes, re-validated by strict re-parse; never drop the whole call (it leaks into content and wastes the turn). Model-agnostic; helps 1B models, leaves valid JSON untouched.
- **Truncated opener** (`close_rel==null`): try JSON shapes, then Hermes, then XML on the remainder; recover NAME + `{}` — NEVER ship partial content values (a half-written file is worse than a re-issued chunked write).
- **Delimiter-drop tolerance (hy3 class)**: a tag parser never bails a whole call on ONE missing/mismatched delimiter — name ends at the earliest structural marker, key-closes match tolerantly, plural-wrapper recovery keys strictly on the SUFFIXED `<tool_calls:` form (bare `<tool_calls>` belongs to DSV4).
- **Loop-stop cuts are truncations**: degenerate-tail cut ⇒ `finish_reason "length"` (`scheduler.loopStopReason`), logged `[loop-stop]`, and the Gemma truncation salvage ships NO fragment values (unterminated pairs dropped via `cut`; completed pairs survive). A tool-executor error must never infer "truncated" — only the loop knows `maxTokensHit`.
- **Types come from the SCHEMA, never the value's spelling**: `coerceToolArgsToSchema` coerces scalars BOTH ways ("False"→bool; literal-spelling strings stay strings); undecidable → untouched so client errors stay honest. ONE chokepoint `server.parseToolCallsForRequest` — never call `chat.parseToolCalls` directly from a handler (silent per-surface regression; output-equality tests can't see it).
- **Buried required params**: `hoistMisplacedRequiredParams` lifts a required top-level scalar buried in a container ONLY on all-schema-read conditions (required+absent at top, scalar, container items don't declare it, unanimous same typed value); ambiguity → untouched. The parse layer is innocent in this class — pristine correctly-escaped args are the tell.
- **Heuristic raw-JSON inference must name a DECLARED tool**: bare-JSON-born calls set `.inferred`; `filterInferredBySchema` drops undeclared names (truncated-data-script → "George Washington" call class; client "tool not found" right after max_tokens truncation is the signature). Explicit tag calls never filtered; new heuristics must set `.inferred`; deliberately NOT gated by `--no-tool-autocorrect`.
- **Hard invariants (replay-pinned)**: emitted args ALWAYS valid JSON (final safety net: loose-repair, else `{}` keeping the name); every tag converter escapes + dedups keys (build via ObjectMap/Stringify or hand escape+dedup); bare `<function=…>` with dropped `<tool_call>` still parses; coercion never worsens conformance; genuinely-broken output stays honest (never fabricate). Harness: `src/tool_traffic_replay_test.zig` + deterministic fuzz. KNOWN GAP: `parseHermesToolCall` trims parameter whitespace (meaningful leading indent lost).
- **Gemma dropped `<|"|>` on big content**: rich bare values (newline or `<`) run to the CONFIRMED closing delimiter or the top-level final `}`, never the first `,`/`}` inside markup. App-side chunking (~200 lines/call, `append`) is the complementary mitigation.
- **Think-tag leaks**: strip pos-0 unclosed openers (a re-opened `<|channel>thought` right after a close is never a content channel); `trimTrailingThinkClosers` loops off trailing `<channel|>` / `</think>` / orphan `<tool_call|>` closes (tool CLOSE with no opener is orphan by construction — parseToolCalls ran first). Universal no-tag-leak corpus invariant auto-covers new entries.
- **Unparsed tool markup never rides out as reasoning OR content** (`chat.trimLeakedToolMarkup`, live 2026-08-01): parse works on POST-think text, so a call the model emits INSIDE its think block is skipped — and leaked verbatim as `reasoning_content`, which the client round-trips into history and the model reads as an example (error-echo class). One cut at the first wrapper opener, applied ONCE in a wrapper around split/strip so a new arm can't forget it; the whole tail goes (an unparseable wrapper has no reliable end). `/v1/messages` non-streaming is the ONLY surface that parses FROM the split result — it takes `*KeepingMarkup` and cuts at emission. A marker can split across tokens (`<` + `｜DSML｜`), so the streaming end-flush concatenates BEFORE cutting; a per-token filter is blind to it. Guard: second universal corpus invariant over `reasoning_content`.
- **Streaming + tools + thinking**: buffer until pattern resolution; `<|channel>thought` held until close; `chat.streamThinkGate` pinned by the corpus streaming replay + `tests/test_messages_stream_thinking_tools.sh`. **Reasoning streams INCREMENTALLY on the tools path** (`.hold_thinking` arm, live 2026-08-04): the arm used to be an empty "keep buffering", so a tools request showed NOTHING until `</think>` — measured **4.40 s → 0.09 s** first-delta on a 2.6B (no-tools path was already 0.05 s; prefill is 8-52 ms, so the wait was pure buffering), and it scales with the thought. Safe by construction — `streamShouldBufferForTools` returned false immediately above, so the buffer holds no tool markup and no partial marker at its tail. Every later emit site sends only the remainder (`chat.unstreamedReasoning`, offset `reasoning_streamed`; a SHRINKING split — a marker appearing mid-thought moves `trimLeakedToolMarkup`'s cut — sends nothing more, never a resend, because a delta cannot be retracted). A reasoning BUDGET keeps the old buffering (capping what the client may see is incompatible with having sent it). Verified stream==non-stream BYTE-IDENTICAL on LFM2.5 + Gemma (a 4-bit spec-decode model can't be compared cross-run — documented INT4 temp-0 divergence — so Qwen was checked for self-duplication instead). This is a STOPGAP for the visible symptom; the real fix is the incremental diff-emitting parser in TODO.md.
- **Pythonic tool calls are a CALL-EXPRESSION grammar, and the value TYPES live in the spelling** (`parsePythonicToolCalls`, lfm2/LFM2.5): `<|tool_call_start|>[fn(city='Paris', days=3, metric=True, tags=['trip','eu'])]<|tool_call_end|>` — the model emits full Python repr (`True`, SINGLE-quoted lists) even though its own template renders history containers via `tojson`, so a JSON-only value reader mis-types the two commonest non-string args. Literals are parsed AT parse time (one quote/depth-aware scanner for the arg separator, the `=`, the dict `:` and the closing paren), so a declared `array`/`boolean` never reaches the client as a string and the schema is never consulted. Marker-gated ⇒ additive: `<|tool_call_start|>` is emitted by no other family and the generic `<tool` scan never sees it (Gemma keys the exact `<|tool_call>`); `streamShouldBufferForTools` + `tool_markup_openers` already cover it via the `<|tool_call` prefix. Truncation ships NAME + `{}`; a dropped `[` or end marker never costs the call; an undecidable value stays a verbatim string.
- **The streaming think gate must be told the PROMPT opened the block — a template can open `<think>` unconditionally** (live 2026-08-04): LFM2.5's template has no `enable_thinking` branch at all, so with thinking OFF the model still reasons and the opener is never in the OUTPUT — `streamThinkGate` saw tag-free prose and streamed the entire chain-of-thought as the visible answer, with AND without tools (non-streaming was always right: the `</think>` is present by the time the text is split). Whether a prompt ends inside a think block is a property of the RENDERED BYTES, so `server.promptOpensThink` is no longer ANDed with `enable_thinking`; it rides `chat.streamThinkGate2`'s 4th arg (the 3-arg form = "no prompt opener", so every existing call site pins its old behavior) and, with thinking off, a dedicated stream arm DROPS the block rather than widening the reasoning arm that emits it. Containment: the term can only fire on thinking-OFF + a literal open tag at the prompt tail — every other family renders the closed `<think></think>` signature there. Any new template ⇒ check whether its opener is conditional.
- **`in_think_block` must start from the PROMPT, not from the request flag** (`chat.streamTailIsReasoning`, live 2026-08-04): the stream loop inits it from `enable_thinking`, i.e. assumes the model begins inside a think block whenever thinking was asked for — true only for pre-injecting templates. Gemma renders a bare `<|turn>model` and lets the MODEL decide, so a turn it answers directly ("391") carries no think markup at all and the whole answer flushed as `reasoning_content` with EMPTY content, while non-streaming returned it correctly (`splitThinkBlock`: no opener + no close + not template-opened ⇒ content). The end-of-stream flush now demands POSITIVE evidence a block was open — prompt opener, or a model-emitted one (`saw_think_open`, set ONLY in the three branches that recognize a real opener; `skipped_think_open`'s else also fires for "assume the template injected one", which is the case being told apart). Truncated thoughts are unaffected (a pre-injecting template sets the prompt flag). Short answers hide it twice over: the opener-skip logic is gated on `len >= 7` and never ran.
- **An integration assertion that a MODEL must think / answer / call a tool is a checkpoint expectation in a server test's clothes**: three arms failed on correct behavior (Gemma answers directly; Laguna-XS spends >500 tokens thinking about 15x17 and ends `finish_reason: length` still inside the block; Laguna/LFM2.5 tool-call with an empty thought, LFM2.5 nondeterministically). Assert the INVARIANT and branch on the model's choice — the old "reasoning >50 chars" arm passed straight through the answer-filed-as-reasoning bug for as long as the model happened to think. Same session: `test_format_matrix.sh` skipped its gemma4-e4b arm because the checkpoint sat under the sibling model root (`~/.mlx-serve/models` vs `~/.lmstudio/models`) — a skip reads as a pass.
- **A contract COMMENT is read as a spec — pin it or it gets filed as a bug**: `coerceToolArgsToSchema`'s "only SCALARS are touched" survived the commit that added its array/object arm (60ba5ec, 2026-07-09) and was filed two weeks later as issue #94 against a gap that did not exist. Container coercion is now pinned by a test named for the issue, and the comment says what the code does.
- **Assistant-history reasoning round-trips**: client-returned `reasoning_content`/`reasoning` (chat) and `thinking` blocks (`/v1/messages`) ride `Message.reasoning_content` → `serializeMessagesJson` (key OMITTED when absent — templates gate on `is string`) → `TokenizeCache.keyFor`. A template that PERSISTS reasoning across turns (laguna, inkling) otherwise renders every prior turn as the empty `<think></think>` nothink signature and the model stops thinking from turn 2 — while the flag wiring reads perfectly (turn 1 thinks). Templates that strip history reasoning (Qwen/Gemma) never read the field; their prompts are unchanged.
- **A template can raise_exception on OUR extra-context values — and a raise is the silent-fallback class**: Inkling's template rejects any `reasoning_effort` outside its own map (hy3's "no_think" explodes it; `serializeExtraContext` sniffs the family and sends "none") and rejects tool-call `arguments` passed as a JSON STRING (we serialize objects; keep it that way). It also needs `tojson(sort_keys=true, separators=…)` — implemented in jinja_cpp 2026-07-30; the hermetic render test (`src/fixtures/inkling_chat_template.jinja`) pins all three. Serialized history tool_calls now carry `"id"` — Inkling names a tool RESULT by matching `message.tool_call_id` against it.
- **A transcribed chat template is worth what it is PINNED against, and its whitespace is a token-level contract** (dsv4, live 2026-07-31): checkpoints that ship no `chat_template` get OUR transcription of their encoder, so `tests/dsv4_template_ab.py` renders both sides over the shapes the server actually emits and demands BYTE equality (14/14; wired into `tests/test_dsv4.sh` step 0, so an encoder change is a diff, not a vague quality regression). It caught that DeepSeek's encoder reads `tools` off the FIRST message and renders them only from a system/developer turn — tools on a user message are SILENTLY DROPPED, and its canonical "tools, no system prompt" is an EMPTY system turn, i.e. `"" + "\n\n" + tools`. Our template omitted that `\n\n` when no system message existed, shifting every token after the bos for the very common user+tools request. Building such an A/B, convert the INPUT shapes to each side's contract (the reference `json.loads`es tool-call `arguments`, we pass objects — hand it a dict and it silently renders one parameter literally named "arguments", which reads as our bug).
- **Inkling channel markers are SINGLE special tokens — but marker filtering alone does NOT cover tool turns**: `chat.isChannelMarkerToken` (shared by every streaming flush path) plus the `splitInklingChannels` arm in splitThinkBlock/stripThinkBlock and the `parseInklingToolCalls` family (`NAME<|content_invoke_tool_json|>{…}` messages; truncation salvages NAME + `{}`). Corpus family "inkling" + the extended `leak_tags` + the streaming tool-buffer replay auto-cover new shapes.
- **An error echo teaches the model the error** (Inkling name-salvage loop, live 2026-07-30): the salvage NAME was "text since the last message boundary", which swallowed the `<|content_text|>` marker → pi replied "Tool <|content_text|>bash not found" → the model started emitting `{"name":"<|content_text|>bash"}` itself. NAME = the TRAILING IDENTIFIER RUN before the invoke marker (also sanitizes marker-echoed payload names); body = the BALANCED JSON object, never scan-to-`<|end_message|>` (the model drops that tag between back-to-back calls, and an end-bounded body swallows the next call whole); a parsed NAME must never contain `<|` (universal corpus invariant). The bare-JSON inference never runs on invoke-marker text — it resurrected a call the Inkling parser deliberately skipped. Inkling ships NO generation_config.json and TM publishes no recommendation, so `applyFamilySamplingDefaults` fills top_p 0.95 (OUR tail cut — pi omits sampling params, and wild 1.0/1.0/off produced duplicate-call degeneration).

### Server, HTTP, lifecycle (→ docs/gotchas/server-http.md)

- **Liveness is a property of the SOCKET, never the generator**: every streaming token loop calls `beatStreamKeepalive` at the BOTTOM of each iteration (or before an early `continue`); emits only when no bytes for 5 s (`Conn.heartbeat` stamped at the write sites). Buffered tool calls otherwise kill clients at their idle timeout (undici `terminated` at ~300 s, chunks=1, server finishes normally later). WS no-ops both senders. `StreamHeartbeat` (client protection, bytes) is the mirror of `StallClock` (server protection, tokens) — don't confuse them. KNOWN GAP: Ollama sink drops SSE comments (fix if reported: empty-content NDJSON line).
- **Teardown with detached workers**: `serve` drains conn threads (atomic `active_conn_threads` + `cancelAllInFlight`; `waitNext` returns `.done` on cancel) BEFORE `scheduler.deinit`. A `defer deinit()` after a spawn loop with dropped handles is the classic use-after-free shape.

- **A configless repo SHAPE must be taught to every "is this a model?" answer** (MageFlow discovery class): the shape was known to `peekConfig` (`peekMageFlowIndex`) but `tryAddModel` returned false on a missing root config.json BEFORE calling it, the byte scan only summed top-level `*.safetensors` (diffusers keeps weights in component subdirs → size null), and `cli.zig` had a THIRD private copy of the test — so every MageFlow checkpoint was invisible to `list`, `/v1/models` and the app picker while `--model <path>` worked fine. Guards: `discoverModels finds a MageFlow repo`, `cli: isModelDir accepts a MageFlow repo`. **Shipped twice**: `mlx-community/flux2-klein-9b-4bit` carries NEITHER file, so `peekMfluxFlux2` keys on the DiT's WEIGHT NAME (`double_stream_modulation_img`, from the shard index or the first safetensors header — bounded prefix via `readSliceShort`, never `allocRemaining`) — a directory shape would adopt half of diffusers. `gen.peekModelType` DELEGATES (model_discovery imports only std+log ⇒ no cycle, no third copy), and its bundle drops `config.json` from the ready markers or a complete 10 GB download reads as permanently incomplete (Kokoro-vs-`tts()` class).
- **A family's geometry comes from the CHECKPOINT the moment a second size exists** (FLUX.2 klein 4B/9B): `FluxConfig`'s defaults WERE the 4B and `loadDit` allocated from them, so a 9B would load 5 of its 8 double blocks and 20 of its 24 with NO error and generate a plausible wrong image. The whole delta is six numbers (blocks 5→8 / 20→24, heads 24→32, joint 7680→12288, TE 2560/9728→4096/12288); head_dim, in_channels, mlp_ratio, rope theta, the 36 TE layers and the 9/18/27 taps are shared, and the VAE/tokenizer are identical. `ditConfigFrom`/`teConfigFrom` derive from weight SHAPES — no json states them (the 9B has no config.json) and shapes cannot disagree with the tensors being loaded. TE head counts come from `q_proj`/`k_proj` ROWS, never hidden÷head_dim (right on the 9B by luck, wrong on the 4B); `ff.linear_in` is gate+up FUSED so mlp_ratio is rows÷2÷inner; a zero probe leaves the field alone rather than allocating 0 blocks. Verified no-op on the real 4B (identical numbers, image unchanged).
- **When an arch's reference implementation deliberately IGNORES a config field, that field is not the source of truth for that arch** (laguna YaRN class): Laguna's mscale is MLX's computed YaRN default `0.1*ln(factor)+1 = 1.3465735…` — both vendored MLX Laguna ports drop the HF `attention_factor` and poolside's fused kernel hardcodes the result. S ships that exact value so reading it matched BY LUCK; **XS ships `1.0`**, which would have run 10 of its 40 layers with unscaled YaRN RoPE — silent, no crash, and every benchmark on it measuring a different model than the reference. The `laguna` arm computes it (the generic nested-rope reader still honours the field); S's pre-existing config test is the unchanged-behaviour proof.
- **Read `text_config` FIRST, then root, PER FIELD** — every config reader (discovery stub meta AND `parseConfigFromJson`; the class shipped twice in opposite directions). Fields a minimal `text_config` omits need explicit per-arch HF defaults (gated on `get(field)==null`), else 12b-shaped struct defaults crash warmup (`Cannot reshape N into (1,1,H,D)` signature).
- **The WEIGHT PREFIX is a property of the checkpoint, not of the config keys** (`model.resolveWeightPrefix`, live 2026-08-04): `parseConfigFromJson` guesses `model` vs `language_model.model` from `text_config` presence, and mlx-community/LFM2.5-2.6B-{8bit,nvfp4} declare `Lfm2ForCausalLM` with NO text_config (just an EMPTY `vision_config`) while nesting every weight — the guess picked `model` and the load died on `MISSING WEIGHT: model.embed_tokens.weight`. Both trunk load sites now probe the loaded map and re-point when the configured prefix holds NOTHING and the other one has weights (never an arch with its own prefix — `backbone`/`model.llm`/`""` — so nothing that loads today can move). Any new prefix heuristic owes the same last word to the weights.
- **`*_text` siblings** (gemma3_text/gemma4_text/qwen…): accept the tag in the arm, collapse to the base type, pick weight prefix by `text_config` presence (`language_model.model` vs `model`), force `tie_word_embeddings` for Gemma (never ships lm_head), and add to BOTH visibility allowlists (`model_discovery.supported_model_types` + Swift `supportedModelTypes`).
- **Multi-converter MoE containers**: hy_v3 experts ship as `mlp.experts` (ox-ox) OR `mlp.switch_mlp` (mlx-lm) — resolve by probe (`hy3ExpertContainer`), never hardcode one name for an arch with multiple converters.
- **Gemma terminators merge ADDITIVELY** (`ensureGemmaTerminators`: adds 1+106 if absent, idempotent, all three arms) — never gate a known chat terminator on "config provided no eos" (a scalar `eos_token_id: 1` defeats it → `<end_of_turn>` leaks forever). Same class as the Qwen `<|im_end|>` load-path merge.
- **Quant modes resolve PER WEIGHT** (`computeQuantParams`; scales dtype decides: uint8 → config's fp8 mode, float → affine with (bits,gs) solved from the activation inner dim): mixed QAT checkpoints override individual layers; `.biases` mandatory under affine, OPTIONAL under non-affine (`getLayerBias`) — never skipped, and never infer fp8-vs-affine from `biases==null` alone.
- **Affine bits outside MLX's kernel set {2,3,4,5,6,8} must be rejected at config PARSE** (`parseConfigFromJson` → `UnsupportedQuantBits`): mlx only validates bits inside `quantize()`, so an already-quantized checkpoint (a "1-bit" conversion) loads fully and dies at warmup with an UNCATCHABLE `Unable to load kernel affine_dequantize_..._b_1` — one bad model killed the whole server. On an mlx bump that adds a width, extend this switch AND `affineParamsFromGeometry` together.
- **A GGUF folder is a SHELF of models, not a model**: one `LocalModel` per quant (path = the FILE; `id#<file>` suffix; display `repo · QUANT`), per-quant delete/cancel scoping, `existingModelDir` accepts config.json OR a servable .gguf, terminal-state-free quant menu, and the sidecar classifiers (Swift `isGgufSidecar` / Zig `isGgufSidecarBasename`: mmproj + tokenizer) MUST stay in sync — a new `.gguf` companion convention updates BOTH.
- **DiffusionGemma parity = converged-canvas self-consistency**, never random-canvas logit compare (garbage canvases put the sigma-MoE router on knife-edge ties; one bf16 kernel-order difference flips expert sets while both outputs are "valid"). Sliding prefill takes the `"causal"` fast path when `total_kv ≤ sw` (reference kernel/reduction parity affects convergence). Trace: `MLX_SERVE_DIFFUSION_TRACE=1`.
- **Optional per-token modulation over a scalar path (LTX I2V AdaLN class)**: gate entirely on the optional mask (`nv_pt==0` dispatches to the EXACT unchanged scalar code — zero t2v overhead) and pin with a uniform-mask self-equivalence test (per-token with all-ones mask MUST reproduce scalar; reference-equality tests cannot see a scalar-path regression). Audio/prompt/AV gates stay scalar for image-only conditioning.
- **Parity fixtures for deep ViTs/DiTs: dump fp32 on CPU** — torch fp16-on-MPS quietly decorrelates deep networks (cos ~0.3, no NaN — nothing "fails" at dump time; SD-class UNets/VAEs are fp16-safe). An oracle missing badly ⇒ suspect the FIXTURE before rewriting the port (numpy-spec repro from converted weights localizes in minutes). transformers ≥5.x materializes custom-model rotary `inv_freq` buffers as ZEROS (identity-RoPE fixtures): dump scripts assert rotary buffers non-zero + rebuild from fresh instances; an oracle that IMPROVES when you remove a transform = the fixture's transform was silently disabled.
- **TTS**: ECAPA/SpeechBrain `TimeDelayNetBlock` = conv + IMPLICIT ReLU — never drop it when fusing (0.9989 vs bit-exact). Embedding lookups reshape to the TABLE's native width via `getShape`, never a config dim (a projection between lookup and residual makes them diverge; wrong width = uncatchable reshape crash). Voice clone = ECAPA speaker embedding spliced as one codec-prefix position; `ref_text` ignored; no predefined voices on Base checkpoints.
