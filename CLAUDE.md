## Stack

Zig 0.17 (nightly build required until 0.17.0 stable ships — homebrew's zig formula still tracks 0.16.0; see `build.zig`'s version-gate comptime block for why 0.16.0 stopped working: its bundled libc++ fails against the macOS 27 SDK); mlx + mlx-c PINNED SUBMODULES (`lib/mlx-src` v0.32.0, `lib/mlxc-src` fba4470 = brew 0.6.0_3 equivalent) self-built NAX-enabled by `scripts/build-mlx.sh` into `lib/mlx/` (FFI `src/mlx.zig`); llama.cpp C++17 Jinja2 pre-compiled as `lib/jinja_cpp/libjinja.a`; stb_image + libwebp (vision); safetensors; BPE tokenizers. Embedded engines: ds4 (`lib/ds4`, DSV4-Flash GGUF) + libllama (`lib/llama`, generic GGUF).

## Building

- **First-time setup**: `./scripts/fetch-zig.sh` stages the pinned Zig nightly at `.zig-toolchain/` (homebrew's `zig` formula still ships 0.16.0, which no longer builds — see the version-gate comptime block at the top of `build.zig`). Put it on PATH (`export PATH="$PWD/.zig-toolchain:$PATH"`) or invoke `.zig-toolchain/zig` directly. CI runs the same script (`.github/workflows/release.yml`). Retire this once 0.17.0 ships stable and homebrew catches up.
- **Zig 0.17 caches configure-time subprocess output in `.zig-cache`** (`b.runAllowFail` — e.g. build.zig's `xcrun --show-sdk-path`): after a toolchain/SDK change (a macOS upgrade removing the CLT), the link keeps referencing the GHOST path until `rm -rf .zig-cache`. build.sh/xcode-build-server.sh prefer the CLT SDK but fall back to `xcode-select -p` when it's absent (story: docs/gotchas/app.md).
- **ALWAYS `zig build -Doptimize=ReleaseFast` — never bare `zig build`** (Debug is 2–4× slower ⇒ fake regressions; ReleaseFast binary ≈ 7 MB, Debug ≈ 2×). Rebuild the exe before any live perf A/B — `zig build test` does NOT refresh `zig-out/bin/mlx-serve`.
- Swift app: `bash app/build.sh` (see app/CLAUDE.md). The two bundle binaries (MLXCore + mlx-serve) move together.
- mlx + mlx-c are NOT brew deps: pinned submodules built by `scripts/build-mlx.sh` (deployment target 26.2 → MLX's NAX kernels compiled in; script + `tests/test_mlx_staged_nax.sh` ASSERT the metallib contains `*_nax` — the CMake gate fails silently). The brew bottle is built at 26.0 and hard-wires `is_nax_available()` false even on M5. Effective min macOS is 26.2 everywhere (app `LSMinimumSystemVersion`, `Package.swift`, bundled dylibs). Bump = checkout new tag in submodule → rerun script → re-diff `src/mlx.zig` externs. Brew floor remaining: webp ≥ 1.6.0 (`verifyBrewDeps`). mlx v0.32.0 = the runtime the M5 NAX profile was calibrated on.
- Rebuild Jinja after `lib/jinja_cpp/*.cpp` changes: `cd lib/jinja_cpp && for f in jinja_wrapper caps lexer parser runtime jinja_string value; do clang++ -std=c++17 -O2 -DNDEBUG -I . -c $f.cpp -o obj/$f.o; done && ar rcs libjinja.a obj/*.o`

## Testing — TDD is mandatory for every change

Order is fixed: (1) failing test FIRST, failing for the right reason; (2) minimum code to green; (3) full suite (`zig build test` must be 6/6 steps, 0 fail + `cd app && swift test`/`build` + the relevant `tests/*.sh`); (4) then refactor under the tripwire. A live curl is a sanity check, NOT a test.

Per change class: feature = unit test that fails without it (+ integration script if HTTP-observable). Bug fix = regression test red→fix→green, verified red-on-revert. Cross-arch work = cover every touched arch (one arch's pass ≠ the suite's pass). Refactor = characterization test first if coverage is missing. UI/build scripts = factor a pure helper and test that.

**Class bugs get class guards — no whack-a-mole.** A live failure revealing a CLASS (escaping gap, format-family leak, dispatch hole) ships THREE things: the instance regression test; a corpus entry or universal invariant in `src/format_corpus_test.zig` so future families are covered automatically; and a 1–3-line rule in `## Rules` here + full story in `docs/gotchas/` (growth policy above).

Key hermetic suites: `zig build test -Dtest-filter="format corpus"` (captured model outputs × split/strip/parse + no-tag-leak + valid-JSON-args + declared-type + buried-param invariants), `-Dtest-filter="tool traffic"` (replay harness). Full script matrix: `tests/CLAUDE.md`.

## Conventions

- Minimal DRY Zig; tests at the bottom of each source file; shell integration tests in `tests/`.
- Inference thread is the SOLE mlx caller (even array frees) — media gen posts to `gen_queue`, never a gpu mutex. A long gen blocks chat decode (accepted; single GPU).
- Concurrent requests batch-decode on pure-attention archs; `--max-concurrent` sizes the submit queue, not a decode gate. Slots entering a batch mid-generation drain lazy pipeline state first (`drainPipelineForBatch`).
- KV reuse via prompt-prefix matching; invalidated after tool calls + pad-only gens; hot cache spills to the SSD tier; RAM invalidation propagates to disk.
- Chat templates live in model dirs; Jinja renders with fallback formatting.

## Unified media generation

**OpenAI image-edit surface**: `POST /v1/images/edits` is the vendor multipart shape (the official SDK's `client.images.edit(image=…, prompt=…)`, `image[]` repeated for multi-reference), translated by `gen.openaiEditFormToJson` into the `/v1/images/generations` `mode:"edit"` body and served by the IDENTICAL path — pure translation, no second inference route (the ollama.zig principle). Works on any edit-capable backend (FLUX.2, Mage-Flow-Edit). Everything OpenAI accepts that we can't honor is a NAMED 400, never a silently ignored field: `mask` (our editors are maskless in-context models), `n>1`, `response_format:"url"`, `output_format` ≠ png, `stream`. `size:"auto"` is omitted so the edit path resolves geometry from the reference.

One server, one registry — image/audio/video/3D coexist with chat (standalone gen servers retired). Engine slots are MODALITY-named unions on `LoadedModel`; adding a backend = one union arm + impl file (established convention). Gen runs on the inference thread via `gen_queue`; default app flow load→generate→unload; headless boot (`--serve --model-dir`, no `--model`) starts idle, loads on demand. `model_discovery.isMediaModelType` and `gen.modalityFromType` are documented duplication — keep in sync. Downloads ride `DownloadManager` → `~/.mlx-serve/models` (SINGLE source of truth in both Swift and Zig resolvers); `MediaBundle` = primary + deps with per-engine `FileSelection` allowlists. Endpoint/request-field/backend detail (img2img/edit/multi-ref/LoRA/cond-rebalance, LTX pipelines/i2v/a2vid, 3D texture stage, music, TTS voice clone): `docs/reference.md`. Guards: `tests/test_unified_gen.sh` + per-modality scripts; parity via env-gated cos oracles fed by `tests/dump_*_fixtures.py`.

## HTTP APIs

- **OpenAI chat/completions + Responses**: chat usage ALWAYS carries `prompt_tokens_details.cached_tokens` (0 when cold; ONE `formatChatUsage` helper across non-stream/tool-call/stream-final — black-box tooling like llmprobe reads only this field, so an unreported cache scores as "no prompt caching"); chat thinking opt-ins = standard `reasoning_effort` string (none=off; effort→budget via shared `responses_mod.effortBudget`; unknown efforts enable at default budget) OR vendor `enable_thinking` bool — either enables; explicit `reasoning_budget_tokens` outranks the effort budget. `n>1` choices honestly 400 on chat+completions (`nChoicesRejectReason` — single-choice engine, silent one-choice no-op is the llmprobe-flagged class). `/v1/responses` envelope echoes request fields; every SSE event gets `sequence_number` (injected by `sendResponsesEvent`); `background:true` → honest 400; stateful chains via `ResponseStore`/`previous_response_id` (missing → 404, function_call_output → final-answer mode); compaction is pure data (no LLM call); WS transport = same endpoint via Upgrade, NO `[DONE]` on WS success (`[DONE]` is HTTP-SSE-only; a WS `[DONE]` breaks chained sessions).
- **Anthropic `/v1/messages`** (Claude Code): top-level `system` → system msg; typed blocks (`tool_result`→role tool, `thinking`→enable_thinking+budget, fake `signature`); `input_schema`→`parameters`; stop-reason map stop/length/tool_calls → end_turn/max_tokens/tool_use, a matched client stop sequence → `stop_sequence` + the sequence echoed (never masks max_tokens/tool_use — `anthropicStopReason`); full SSE content-block lifecycle. Launcher env: `ANTHROPIC_BASE_URL` + dummy keys + `ANTHROPIC_DEFAULT_*_MODEL=mlx-serve` + `CLAUDE_CODE_SUBAGENT_MODEL`.
- **Ollama `/api/*`**: pure translation (ollama.zig), NO duplicated inference — request → OpenAI body (`num_predict`→max_tokens, images→data URLs, `format`→response_format, `think`→enable_thinking, stream defaults TRUE), response re-framed by `Sink` on `Conn.ollama_sink` (SSE→NDJSON, args string→object, `reasoning_content`→thinking, usage→eval counts; glue clears `stream.ollama_sink` before `sink.finish()`). No-model endpoints answered pre-scheduler (never cold-load); `resolveName` handles `name:tag`. Discovery is two-level (`org/model`); one path must never register under TWO ids (`registry.peekByPath` — double-residency OOM class).
- **LAN sharing**: proxy is a TRANSPORT (no scheduler/MLX involvement); keyless-mode gate = `routeClass` allowlist × `SharedSet` (everything else non-loopback → 403; with `--api-key` set, key semantics rule unchanged); `<id>@<peer>` mirroring with `lan_peer` badge; byte-for-byte tunnel rewriting only the model field (decide+rewrite share ONE parsed slice); loops impossible by construction (TXT self-token + `X-MLX-LAN-Token` self-fetch check, remote entries never re-exported — marker-filtered lists + `lan_peer`-skip on mirror, one-hop bound via the `X-MLX-LAN` tunnel marker: tunneled requests never proxy again, any direct client may initiate the hop); load/unload on remote ids = 200 no-ops; distinct failure modes incl. a 15 s rediscovery wait. Full design: `docs/reference.md`.
- **Observability** (`--metrics`): zero cost when off (one null-check per request at `finishSlot`, never per token); `vllm:` + `mlx_serve:` names; TTFT captured exactly at prefill completion; live tok/s via ONE atomic published per decode tick (`inflight_generated_tokens`; excludes finished slots so live==total at rest); prefill liveness gauges (`prefill_tokens_live` per chunk + `requests_prefilling` at entry). `--api-key`: loopback TRUSTED and exempt; Bearer/x-api-key/Basic/`?api_key=`; `/health`+OPTIONS open; `constTimeEql`. No admin surface (deliberate). Panel/rate rules in ## Rules.

## Tool calling (server pipeline)

With `tools` present, tokens buffer for detection (`<tool_call>`, Hermes XML, Gemma `<|tool_call>` incl. double-brace unwrap, hy3 suffixed tags, DSV4 wrappers, raw JSON); thinking buffered separately. Parse chain: strict → tolerant repairs → truncation salvage; then the per-request chokepoint `server.parseToolCallsForRequest` = parse → inferred-name filter → parallel clamp (`parallel_tool_calls:false` / Anthropic `tool_choice.disable_parallel_tool_use` keep ONLY the first parsed call — client-requested, so NOT autocorrect-gated; model re-issues the rest next round) → buried-param hoist → schema coercion (hoist+coercion gated by `--no-tool-autocorrect`; a final safety net guarantees emitted `arguments` are ALWAYS valid JSON). Serialization (`chat.serializeMessagesJson`): role "tool" passed natively (Gemma renders `<|turn>tool` — no `tool_responses` field, causes duplicates), args as JSON STRINGS, every arbitrary-byte string through `appendJsonString`. Streaming: full args in ONE SSE delta; thinking buffered until close, emitted as `reasoning_content`. Fallback (`fallbackFormatChat`): ChatML, Llama ipython, Gemma "Tool result:". Client side: `app/CLAUDE.md`.

## Prompt-based skills / downloads / debugging

- Product skills: `~/.mlx-serve/skills/*.md` (YAML frontmatter; trigger = comma-separated case-insensitive substring match → body injected into system prompt; index always included; `SkillManager` rescans on mtime; no UI — Finder-managed).
- `DownloadManager`: streams to `.partial`, Range resume (206 continue / 200 truncate+restart), 3 retries 2s/4s, cancel preserves partial, size-matching files skipped.
- Server log: `~/.mlx-serve/logs/mlx-serve-<port>.log` (on for all serving paths; 32 MB rotation; per-port; `--log-file off` disables) — THE post-mortem file (app buffer dies with the app). `--log-level debug` for verbose. Grep patterns: `jinja error:`, `[cache] reusing/invalidated`, `<- N+M tokens`, `tool_msgs=`, `[spec-stats] mode=`, `spec-gate: ngram-score=`, `[loop-stop]`, `[lan] proxy`, `[disk-cache] restored`, `[hot-cache]`. Tool-traffic capture: `MLX_SERVE_RAW_DUMP_FILE=<abs path>` + debug level → `tests/harvest_tool_traffic.py`. Reproduce tool bugs `stream:false` first; `pkill -f mlx-serve` between KV-poison tests; render Jinja offline via python jinja2 + the dumped request. Never run mlx-serve and Python `mlx_lm.load` concurrently on big checkpoints (double-load OOM).

## Rules (distilled gotchas — full stories in docs/gotchas/)

### Tool calling & formats (→ docs/gotchas/tool-calling.md)

- **Control bytes**: ONE raw byte <0x20 anywhere in history kills the strict nlohmann render → SILENT downgrade to `fallbackFormatChat` → wrong-family tags, model degenerates (loses its stop token). Every arbitrary-byte string goes through `appendJsonString`; render failure logs WARN. Wrong-family tags in output ⇒ suspect silent fallback before suspecting the model.
- **Model-mangled arg JSON**: after strict parse fails, `looseRepairToolCallJson` re-escapes ctl bytes / inner quotes / invalid backslashes, re-validated by strict re-parse; never drop the whole call (it leaks into content and wastes the turn). Model-agnostic; helps 1B models, leaves valid JSON untouched.
- **Truncated opener** (`close_rel==null`): try JSON shapes, then Hermes, then XML on the remainder; recover NAME + `{}` — NEVER ship partial content values (a half-written file is worse than a re-issued chunked write).
- **Delimiter-drop tolerance (hy3 class)**: a tag parser never bails a whole call on ONE missing/mismatched delimiter — name ends at the earliest structural marker, key-closes match tolerantly, plural-wrapper recovery keys strictly on the SUFFIXED `<tool_calls:` form (bare `<tool_calls>` belongs to DSV4).
- **Loop-stop cuts are truncations**: degenerate-tail cut ⇒ `finish_reason "length"` (`scheduler.loopStopReason`), logged `[loop-stop]`, and the Gemma truncation salvage ships NO fragment values (unterminated pairs dropped via `cut`; completed pairs survive). A tool-executor error must never infer "truncated" — only the loop knows `maxTokensHit`.
- **Types come from the SCHEMA, never the value's spelling**: `coerceToolArgsToSchema` coerces scalars BOTH ways ("False"→bool; literal-spelling strings stay strings); undecidable → untouched so client errors stay honest. ONE chokepoint `server.parseToolCallsForRequest` — never call `chat.parseToolCalls` directly from a handler (silent per-surface regression; output-equality tests can't see it).
- **Buried required params**: `hoistMisplacedRequiredParams` lifts a required top-level scalar buried in a container ONLY on all-schema-read conditions (required+absent at top, scalar, container items don't declare it, unanimous same typed value); ambiguity → untouched. The parse layer is innocent in this class — pristine correctly-escaped args are the tell.
- **Heuristic raw-JSON inference must name a DECLARED tool**: bare-JSON-born calls set `.inferred`; `filterInferredBySchema` drops undeclared names (truncated-data-script → "George Washington" call class; client "tool not found" right after max_tokens truncation is the signature). Explicit tag calls never filtered; new heuristics must set `.inferred`; deliberately NOT gated by `--no-tool-autocorrect`.
- **Hard invariants (replay-pinned)**: emitted args ALWAYS valid JSON (final safety net: loose-repair, else `{}` keeping the name); every tag converter escapes + dedups keys (build via ObjectMap/Stringify or hand escape+dedup); bare `<function=…>` with dropped `<tool_call>` still parses; coercion never worsens conformance; genuinely-broken output stays honest (never fabricate). Harness: `src/tool_traffic_replay_test.zig` + deterministic fuzz. KNOWN GAP: `parseHermesToolCall` trims parameter whitespace (meaningful leading indent lost).
- **Gemma dropped `<|"|>` on big content**: rich bare values (newline or `<`) run to the CONFIRMED closing delimiter or the top-level final `}`, never the first `,`/`}` inside markup. App-side chunking (~200 lines/call, `append`) is the complementary mitigation.
- **Think-tag leaks**: strip pos-0 unclosed openers (a re-opened `<|channel>thought` right after a close is never a content channel); `trimTrailingThinkClosers` loops off trailing `<channel|>` / `</think>` / orphan `<tool_call|>` closes (tool CLOSE with no opener is orphan by construction — parseToolCalls ran first). Universal no-tag-leak corpus invariant auto-covers new entries.
- **Streaming + tools + thinking**: buffer until pattern resolution; `<|channel>thought` held until close; `chat.streamThinkGate` pinned by the corpus streaming replay + `tests/test_messages_stream_thinking_tools.sh`.

### Server, HTTP, lifecycle (→ docs/gotchas/server-http.md)

- **Liveness is a property of the SOCKET, never the generator**: every streaming token loop calls `beatStreamKeepalive` at the BOTTOM of each iteration (or before an early `continue`); emits only when no bytes for 5 s (`Conn.heartbeat` stamped at the write sites). Buffered tool calls otherwise kill clients at their idle timeout (undici `terminated` at ~300 s, chunks=1, server finishes normally later). WS no-ops both senders. `StreamHeartbeat` (client protection, bytes) is the mirror of `StallClock` (server protection, tokens) — don't confuse them. KNOWN GAP: Ollama sink drops SSE comments (fix if reported: empty-content NDJSON line).
- **Teardown with detached workers**: `serve` drains conn threads (atomic `active_conn_threads` + `cancelAllInFlight`; `waitNext` returns `.done` on cancel) BEFORE `scheduler.deinit`. A `defer deinit()` after a spawn loop with dropped handles is the classic use-after-free shape.
- **Non-text model on a text surface must 400 BEFORE prefill** (gen-stub tokenizer → null transformer deref = one-request server kill): `textGenRejectReason` at ALL text-gen surfaces, TWICE (pre-ensureLoaded peek via discovery `arch_hint` — don't cold-load 15 GB to earn a 400 — and post-load authoritative). New surface → extend `isTextGenRoute`; new modality → engine slot + `modalityFromType`; same taxonomy feeds `mlx-serve run` preflight + `list` TYPE column.
- **An arg loop with no else branch is a silent flag eater**: `main.zig`'s `while` matched every flag by EXACT name with a space-separated value and then just ended — so `--model=<path>` (a shape no arm matches; zsh leaves it as one argv token) was DROPPED without a word. The server booted clean, printed an empty `[args] model:`, went headless, auto-picked an unrelated model on the first request and crashed on that instead. Nothing in the output points at the real cause. The loop now rejects anything it did not consume (`cli.classifyUnparsedArg` → `.equals_form` / `.missing_value` / `.unknown`, each with actionable advice); a launcher that ignores what it was asked for is worse than one that refuses to start. Same family as the `runHeadlessServe` entry below — verify with the flag cross-check: every `--flag` any test script or `ServerOptions.toCLIArgs` passes must appear in main.zig's match list.
- **A serve path that hand-rolls its `ServerConfig` silently eats CLI flags**: `runHeadlessServe` literal'd all three PLD fields (`false`/`5`/`3`), so no `--pld*` flag reached a headless request — the mode the app ALWAYS launches (`--serve --model-dir`, no `--model`), passing all three flags every boot. Nothing reports it: the flag parses, `--help` documents it, boot is clean, and the "ENABLED" banner is gated on the same dead field. Related settings travel as ONE value (`server.PldDefaults`, `.off` for non-text paths) so a fix can't honor one field and drop its neighbours; guard = `tests/test_headless_spec_flags.sh` (empty `--model-dir`, banner-observable, no checkpoint needed).
- **A client-supplied PATH must be proven on OUR side of the mlx boundary**: `{"lora_path":"/tmp/gone.safetensors"}` reached `mlx_load_safetensors`, which raises an MLX error — and an MLX error is not a Zig error, it KILLS the process. One request with a stale adapter path (moved file, typo) took the whole server down for every client. `lora.loadFile` now opens+stats first (absolute AND a regular file — a directory opens fine and dies later), returning `error.BadLoraPath` → 400. Any new path that flows from a request into an mlx loader owes the same check.
- **Hand-written error text is not JSON**: media-gen 400s that quote a field value (`mode:"edit"`) shipped a body with RAW quotes — unparseable by every client — and an over-long message made the fixed-buffer `bufPrint` fail so the handler sent NO body at all. Escape at the SINK (`gen_sse.jsonEscapeMessage`, used by BOTH `gen.sendError` and the SSE one), truncating to fit on a UTF-8 boundary rather than dropping the response. Same class as the tool-calling `appendJsonString` rule: a literal is arbitrary bytes too.
- **Endpoint EXISTENCE must not depend on model state**: model resolution runs ahead of dispatch, so on a headless boot (no default model — how the app always launches) an UNKNOWN path never reached the chain's 404 and answered 503 "No default model configured". Any client that maps endpoints by probing them then reads the server as a catch-all that implements everything (llmprobe scored every surface absent: "server answers unknown paths with HTTP 503"). The `NoDefaultModel` arm now 404s when `!routeExists(path)`; `ROUTE_PATHS` is guarded against drift by a test that scans the dispatch chain out of `@embedFile("server.zig")` — so a new route arm that forgets the table fails CI instead of becoming a headless 404. Guard: `tests/test_headless_spec_flags.sh` [4/4] (hermetic, empty `--model-dir`).
- **A page that must render on an EMPTY server can't be rendered FROM a model**: third bite of the resolution-runs-before-dispatch class. `GET /` sat below resolution and `handleStatusPage(…, lm)` rendered 21 slots off a `*LoadedModel`, so a headless boot — how the app launches, and now how bare `mlx-serve serve` starts — answered 503 "No default model configured" at the ROOT. The console IS the model picker, so it renders above resolution with NO `lm` and fetches `/v1/models` + `/props` client-side (which also makes the picker follow loads/unloads without a refresh). Its API reference is hand-written prose and had silently omitted the whole Ollama `/api/*` surface (22 of 31 endpoints documented) — pinned now by a test asserting every `ROUTE_PATHS` entry appears in `@embedFile("html/index.html")`. **`index.html` is a std.fmt FORMAT string** (every literal brace doubled), so CSS/JS live in `app.css`/`app.js`/`metrics.js` and are injected as RUNTIME `{s}` args — std.fmt does not re-parse those. Never inline them back. Guards: `tests/test_index_page.sh` (hermetic, empty `--model-dir`), `tests/html_console_test.mjs` (pure logic + a static id cross-check — a typo'd `$('id')` is a silently dead control that every byte-level assertion still passes).
- **Console layout = sidebar (New chat / Monitor / API + Recents); chat opens SIMPLE and becomes a transcript** — one composer element in two layouts, never two. Recents is localStorage, and `storableTurns` strips image payloads before persisting (one 1024² PNG is ~1.5 MB of base64 against a ~5 MB quota, so one image chat would evict every other) while keeping the agent structure so a reloaded chat can be continued. Replies render markdown built from ESCAPED input — model output is untrusted, including inside a fence, and `[x](javascript:…)` degrades to text. No temperature/max-tokens knobs: model + thinking live in the composer's pill menu.
- **A client cannot time our own stream**: with `tools` present the server buffers tokens for tool-call detection and flushes at the end, so every SSE delta lands at once, the measured decode span is ~0, and the console reported **937 tok/s on a 2B**. The final chunk already carries the server's own `timings` (`prompt_ms`, `predicted_n`, `predicted_ms`), measured around the forward passes — use those and sum them across the turn's rounds (which also keeps a minutes-long media generation out of the denominator). `stream_options.include_usage` is load-bearing: the server gates that whole final chunk on it.
- **Console = Monitor / Chat / API; media is ASKED for, not a form.** The chat carries one tool per modality this server can actually serve (`mediaTools`), so "generate an image", "make it winter" on an attached photo and "write me a lo-fi track" are chat turns; the console executes the call and renders the picture/player inline. Rules the live runs forced, all in the tested pure layer: **ONE media generation per user turn** (a 2B answered one request with four GPU generations — a round cap can't bound that, a budget can, and the refusal must be a SENTENCE or the model just calls again); **the tool's `model` enum and its resolution must be the same list** (the enum offered every image model, the model picked a txt2img one for an edit and ate the 400 — `editableIds` mirrors the server's own name-based `mage_flow.dirIsEdit` gate since edit capability is not API-visible); **rank candidates by usability** — resident first, then sized, then `error` last (a null `bytes_on_disk` is an incomplete download: config+tokenizer, no shards, and it sorted first). The system prompt is OURS, built from `/v1/models` + the API tab's own markup (one list, so the reference can't drift), and must state the base URL, the real request FIELDS, and that questions are answered in text with NO tool call — every gap the prompt leaves, the model fills with invention (measured: `-F "ref1=<base64>"` against `https://your-ollama-ip-address/api/v1/images/edits`, and "give me a curl" answered with a generated picture).
- **A field DISPATCH reads must be readable from every body SHAPE we accept**: model resolution runs before the route normalizes the body, and `parseModelFromBody` is a JSON scanner (`"model":`) — so `/v1/images/edits`, our one multipart endpoint, had its `model` FORM FIELD silently ignored and every edit ran against the DEFAULT model (Open WebUI, live 2026-07-25: 400 "does not support this media modality" against a chat default; headless with no default: 503 "No default model configured"). ONE `parseModelFromRequest(body, content_type)` now feeds both dispatch and `lanShareDenial`, whose contract is that the gate can never disagree with what would actually run. Both edit tests booted `--model <the image model>`, so the default was ALREADY correct and neither could see the class — a guard for it needs a server with NO default.
- **A header PARAMETER lookup keys on the PARAMETER, never a substring**: `paramValue(line, "name=")` also matches inside `file` + `name=`, so a client that orders `Content-Disposition` the other way round (RFC 7578 fixes no order, and only convention puts `name` first) had its field name come back as the FILENAME — the part stopped being recognized as `image` and a well-formed upload 400'd "missing image". Accept a match only at a boundary: start of line, or after a `;` (+ optional whitespace). Any new header-param reader owes the same.
- **A body log that was fine for JSON is not fine once a body can be BINARY**: `/v1/images/edits` is the first multipart endpoint we serve, and `logHttpBody`'s verbatim dump wrote raw PNG bytes into the log — a body near the 64 MB request cap blew straight through the 32 MB rotation, destroying the post-mortem file it exists to be. Text bodies still go out WHOLE (reading a full request body out of the debug log is how tool-calling bugs get reproduced); non-text logs a bounded sanitized preview (`bodyIsText` / `bodyPreview`, `BODY_LOG_LIMIT`).
- **Auto-context is PINNED at load** (`pinAutoContext`) — clients bake `meta.context_length` into config files once; per-request recompute drifts with system load. The 85% margin applies to the MEMORY ceiling ONLY, never the model max. Never gate context behavior on `server_config.max_context_size` (set only by `--ctx-size`) — ask `getEffectiveContextLength`. App budgets (`AgentBudget` → pi/opencode/Claude Code configs) derive from the advertised value verbatim — no hardcodes, no double margin.
- **GPU memory ceiling must see EXTERNAL pressure**: `currentGpuMemoryCeiling = min(getGpuWorkingSetLimit, mlx_active+cache+free)`; reserve the full prefix-cache budget up front. Metal OOM is UNCATCHABLE (async GCD `std::terminate`) — prevention only; its backtrace shows libllama frames even for pure-MLX (terminate handler — red herring). Embedded-engine (ds4/llama) requests are EXEMPT from MLX memory guards (`mlxMemoryGuardApplies` — stub dims bill a transformer that never runs); any new MLX guard skips them or routes through `checkAttentionMemory`.
- **`--timeout` is a STALL timeout** (seconds without a NEW token, `generate.StallClock`) — a producing request never times out. `toolCallFinishReason` preserves "length" through tool parse on all four surfaces (clients' truncation recovery must fire; "tool_calls" on a server-cut fragment burned 15 min of GPU). `outputBudgetGuidance` only when tight (<12288) — a huge honest number overrides the chunking convention and invites mega-calls.
- **Ownership by PROVENANCE, never content** (sentinel-by-content leak class): a `catch "<literal>"` fallback whose defer frees on `!mem.eql(result, literal)` leaks when the literal is also a LEGAL payload (escaping an empty string yields the same `""` as the OOM fallback — every all-reasoning/empty-content response leaked). Use `jsonEscapeOrEmpty`-style `{slice, owned}` returns; the debug-allocator `leaked` lines in the integration server log are the tell.
- **LAN robustness**: dns_sd callbacks fire per-INTERFACE — complete on SUCCESS + MoreComing clear, collect ALL A records, fetch LOOPBACK-FIRST (macOS Local Network privacy silently blackholes unapproved LAN SYNs: connect poll timeout + SO_ERROR=0 is the signature); transient resolve failures retry via the `known` registry (browse never re-announces a live service) and NEVER evict an installed peer directly — removal is `attemptKnown`'s decision only, after `PEER_DROP_FAILS` consecutive failures (one mDNS hiccup — interface churn from a VM/docker bridge, busy daemon — otherwise 404s a live peer "offline" mid-chat); dead dns_sd refs (browse AND advertise) are REVIVED by the browser loop, never left null forever (an mDNSResponder restart otherwise silently ends discovery/advertising for the process lifetime). Any id compared from a raw body scan canonicalizes JSON `\/` first (`unescapeJsonSlashes` — third bite of that class; Swift clients escape every slash). Proxy failure modes stay DISTINCT (discovery-off / model-unlisted / peer-unknown → poked 15 s rediscovery wait); never a silent local-default answer.
- **@peer proxying is bounded by the TUNNEL MARKER, never by loopback-ness**: any DIRECT client may initiate exactly ONE hop (the Agent Sandbox guest is non-loopback by construction — a loopback-only proxy 403'd it, live 2026-07-21); a request carrying `X-MLX-LAN` (stamped by `lan.tunnel`) is never proxied again — `isTunneledRequest` at the keyless gate AND at dispatch.
- **Peer-visible surfaces must not depend on WHERE the peer connects from**: same-Mac peers fetch each other over LOOPBACK, so `/v1/models` filters (shared-only, no remote stubs) key on the discovery fetch's `X-MLX-LAN` marker too, `parsePeerModels` never mirrors an entry that itself carries `lan_peer` (old-peer re-export → `@a@b` chains), and `/v1/models` responses carry `X-MLX-LAN-Token` so a fetch landing on OURSELVES (stale Bonjour record of a former self — TXT self-check can't see it) returns `error.SelfFetch` instead of installing self as a peer.
- **A READY model never advertises LESS capability than its unloaded stub**: embedded-engine GGUFs (ds4/llama) may ship no chat_template yet always serve chat — `readyHasChat` gates "chat" on template-OR-embedded-engine (a loaded DSV4 advertised `capabilities:[]`, LAN clients hid it as "no chat models" while chatting on it); app tolerance: `ModelInfo.lanAdvertises` counts an empty-caps `lan_peer` entry as chat (old peers).

### Engine: KV, spec-decode, kernels, MLX (→ docs/gotchas/engine-mlx.md)

- **KV invalidation**: after tool calls (generated call tokens aren't in `cached_prompt_ids` — reuse corrupts attention) and pad-only gens. Sliding-window layers keep the full buffer (no trimming); decode views slice to last `sw`; mask handles scope.
- **Hot-cache restore ALWAYS clamps**: unconditional `truncate(final_len)` — restored offset = MATCHED length, never the snapshot's stored length (PLD leaves stale KV tails past the committed step; drift ⇒ wrong RoPE everywhere + `broadcast_shapes` mask crash on Gemma sliding layers at long ctx).
- **Slice-born weights into gather_qmm/quantized_matmul must be `mlx_contiguous`-materialized at load** (`splitPackedGateUp` pattern) — lazy views compute SILENTLY WRONG expert outputs at real-checkpoint scale; pointer-read equality tests pass and toy geometries stay green; the guard is the live converged-canvas test (`DIFFUSION_TEST_MODEL`).
- **SSM/hybrid**: init checks `ssm.ssm_state.ctx == null`, NOT `!initialized` (conv sets initialized before recurrence state exists). Param-free RMS norm passes `ones()` (mlx-c crashes on null weight). Nemotron dt clipping: only the `time_step_limit` array, not min/max. PLD-on-hybrid snapshot/restore: per-FIELD null guards (conv without ssm_state aborts mlx-c).
- **Spec verify invariant** (PLD/drafter/MTP shared): `cache.step = prompt_len + emitted`, t1 NOT in cache on entry; verify input `[t1, draft…]`; partial-accept correction sampled from the ORIGINAL `verify_logits[accepted]` (index `accepted`, not `accepted-1` — off-by-one silently corrupts; pinned by equivalence scripts).
- **Spec dispatch discipline**: all four HTTP surfaces × streaming + non-streaming wire `use_pld/use_drafter/enable_mtp`; per-request MTP default = `server.defaultEnableMtp` ONLY (MoE targets default OFF — verify pays expert routing; `--mtp` flips; a MoE head is otherwise unreachable from clients that send nothing). Engagement COUNTS in tests, never just output equality — silent fallback to regular decode is output-identical (two call sites shipped hardcoded `use_drafter=false` for a month). Priority MTP > drafter > PLD; prompt spec-gate `ngramRepeatScore` ≥ 0.01; runtime acceptance gate 0.50 sticky (transition shim seeds pending logits). logprobs>0 + grammar disable spec; tools disable NOTHING (agent traffic is spec's best workload).
- **MTP head**: delta-encoded norms AUTO-FOLD at load (`mtpNormsAreDeltaEncoded` — an unfolded head engages at ~0% acceptance yet passes equivalence AND engagement; acceptance-floor check is the guard); every sidecar/embed weight re-solves quant params PER WEIGHT (`affineParamsFromGeometry`/`computeQuantParams` — OptiQ ships 8-bit embed over a 4-bit base; global-bits dequant CRASHES the server); drafts are GREEDY through a 3-bit draft-only lm_head (verification always uses the trunk head — distribution untouched); ONE bounded sync per stochastic round (batched `probsAllPositions`, lazy gathers, pre-sampled corrections); prefill history FULL by default (`--mtp-history-window` costs 14 acceptance pts on the stock head).
- **No KV snapshots across verify** (copy-on-write class): a live snapshot handle makes every cache `update` COPY the whole buffer (~4.3 GB/round at 64K on the 27B). Rollback = scalar anchors (`moe_seq_offset`, `cache.step`) + per-position SSM capture + offset-only `truncate`; MTP head cache likewise. Symptom: spec round time grows with context far faster than the verify forward; AR outruns speculation at long ctx.
- **A multi-token forward is not a prefill**: `prefillEvalCadenceApplies` (seq ≥ 32) exempts verify/canvas/batched-head forwards from the mid-loop eval cadence — never inherit prefill-only behavior from `seq_len > 1`.
- **INT4 long-greedy divergence is legit**: qmv-vs-qmm reduction order flips near-tie argmax past ~30–80 tokens at temp 0; temp ≥ 0.01 exact (Leviathan preserves the marginal). Byte-stable long-greedy at temp 0 ⇒ no spec + `--kv-quant off/8`. KV-quant divergence stacks on top (per-arch first-N thresholds, env-overridable).
- **kv-quant contract**: attention always reads `KVCache.denseView` — on EVERY forward path: `forwardBatchedDecode` read `entries[].key_view` raw and the first CONCURRENT decode under kv-quant fed packed words to SDPA (uncatchable shape-error server kill; serial tests all green — guard = the force-batched × kv-quant section in `tests/test_batched_equivalence.sh`); extend schemes via enum variant + quantize/dequantize fns + the two switch arms (`update`/`denseView`) — SDPA call sites never change; `HotEntry` records its scheme (no cross-scheme cache hits); TurboQuant requires pow-2 head_dim; snapshots carry 6 handles in quant mode.
- **Hybrid-SSM prefix cache retains ~3.4× what it reports** (refcount-shared checkpoint slices; the byte cap checks the under-count; kv-quant doesn't help — SSM/conv state dominates): the reliable lever is ENTRY COUNT (`ramCappedPrefixCacheEntries` app-side always emits the flag).
- **hd-256 prefill kernel (`msv_attn_p256`)**: sliding-band ALWAYS fused (in-kernel band + block skip; the GB-scale sliding mask is never built; kill `MLX_SERVE_FUSED_256=0`); plain causal DEFAULT-ON via a per-dispatch kv-chunk budget (`MLX_SERVE_FUSED_256_CAUSAL=0` restores composed; `MLX_SERVE_FUSED_256_BUDGET`) — above budget the key axis splits into BK-aligned dispatches carried through fp32 m/l/O buffers, BIT-IDENTICAL to one dispatch (pinned). q_len < 16 ALWAYS declined (decode/verify belong to sdpa_vector; a fused-causal floor must clear depth-8 MTP verify at q_len 9). K/V enter as strided views (`ensure_row_contiguous=false`); guards bill through the ONE predicate `prefillHeadDimFused`. Full story + the IOGPU-preemption root cause: docs/gotchas/engine-mlx.md.
- **Prefill perf kernels — A/B PER ARCH before default-on** (an eligibility predicate adopts every matching shape): GDN blocked-seq (`gdnBlockedEligible`: T≥64, Dk==128, Dv%32==0; kill `MLX_SERVE_GDN_BLOCKED=0`, block-T `MLX_SERVE_GDN_BLOCK_T` 16|32|48) and prefill-width `prefillDqGemm` (affine qmm at M≥2048 → dequant to bf16 [N,K] + steel GEMM; kill `MLX_SERVE_PREFILL_DQ_GEMM=0`) — both same-recurrence / no-worse-than-stock, decode/verify widths never route. Chunk-cap corollary: fused-causal non-sliding hd-256 archs cap the auto chunk at `min(base, 4096)` with NO score-formula shrink (the old 1024-at-64K starved dq-gemm's M≥2048 floor).
- **MTP spec-decode levers (all kill-switched, each bit-identical to its off state)**: drafts GREEDY argmax (beats sharpened-stochastic on low-entropy agent/code; exact-residual machinery opt-in `MLX_SERVE_MTP_DRAFT_GREEDY=0`); draft chain async-dispatched when built (`MLX_SERVE_MTP_EARLY_DISPATCH=0`) + next round's chunk A pre-drafted at the tail (`MtpPreDraft`, `MLX_SERVE_MTP_PREDRAFT=0`) — dispatch TIMING only, PRNG keys bind at graph BUILD. oQ raw-HF head norms get a reference-based `+1` repair vs the backbone anchor (`mtpBackboneAnchorMean`/`ownHeadNormWithRepair`, gap>0.4 on q/k/post_attn/mtp.norm) — the `mtpNormsAreDeltaEncoded` neg-fraction heuristic CAN'T see raw norms with mean≥0.5, so the oQ converter left them +1 too low (draft acceptance 55%→~78%); sidecar/delta heads skip it (no anchor / global fold). EV two-chunk plans pay a mid-pipeline boundary sync → extension dry-spell gate (`MLX_SERVE_MTP_EXT_DRY=0`) + a horizon valve keeping one extension reachable when `best_r>1.10`, both fed by REALIZED rates never priors.
- **verifyQmm lanes** (`vqmmLaneFor`, spec-verify fast path; kill `MLX_SERVE_VERIFY_QMM=0`): split-K M 2–7 / msg wide tile N≥100K / NAX m16 M 8–16 (G17 + macOS≥26.2 only; provenance kept in-source, Apache-2.0). Codegen NAMED SCALARS with literal accumulator indices (array-indexed form stack-spills 10×); M=8 is the plain-SIMD register cliff (NAX is the sanctioned way past it; the NAX kernel object is never BUILT where the probe is false). Auto MTP depth cap 8 needs the FULL calibrated G17/NAX fingerprint (else cap 6); EV adaptive default ON (`MLX_SERVE_MTP_ADAPTIVE=0`), cross-request EV seeding ON (`MLX_SERVE_MTP_EV_SEED=0`); explicit `--mtp-depth` always wins.
- **Kernel testing/measurement rules**: a GPU parity test asserts NO-WORSE-THAN-REFERENCE against fp32 dequant ground truth, never kernel-vs-kernel agreement (both round to bf16 in different orders — green on the dev GPU, red on CI's); a µbench win can lose in the live graph and vice versa — same-boot live A/Bs are the acceptance bar; an eligibility predicate tuned on one arch silently adopts every matching shape — A/B each adopted shape on its own model; never fit spec cost constants from a run whose realized `m_avg` you didn't check.
- **MoE decode `gather_qmm` costs O(EXPERT-BANK SIZE), not O(work)** — measured E-sweep reading the SAME 10 experts out of banks of 8/25/50/201 MB: 30/50/77/300 µs, while pip-Python is FLAT at ~22 µs on the identical dylib (a minimal C program linking only mlx-c reproduces it, so it is process-level, not ours). `take` from the same bank does NOT pay it, so indexed reads are fine and only gather_qmm's addressing is affected. Laguna decode = `gatherQmv`, our own Metal gather-qmv reading the bank IN PLACE (no materialization, no host sync for GPU-resident top-K); `MLX_SERVE_MOE_GATHER_QMV_OFF=1` → batched take, `MLX_SERVE_MOE_GATHER_DECODE=1` → stock gather. Same laguna-only gate as the batched path, and that gate is MEASURED, not assumed: nothing in `gatherQmv` is Laguna-specific (affine 2/4/8-bit, any E/N/K with N%8==0, bf16/fp16/fp32 x) and gemma4-26B-A4B passes every guard it has, but A/B'd there it LOSES — gather 114.9 vs gatherQmv 111.6 tok/s (engagement log confirmed). Its bank is NOT small (~127 MB); it just does far less expert work per token against it, so the O(bank) term is a small share and MLX's better-tuned `gather_qmv_fast` tile wins. The kernel only pays where O(bank) dominates the expert math — A/B any new arch with `MLX_SERVE_MOE_BATCHED_DECODE=1` (enters the branch) and check the engagement log.
- **A kernel's dtype and its threadgroup BLOCK SIZE are ONE decision** (GDN blocked-prefill class): `InT` was hardcoded `.bfloat16` on the strength of a comment saying "our GDN inputs are always bf16" — but an f16 checkpoint (prism-ml/Ternary-Bonsai-27B-mlx-2bit) promotes activations to f32 (f16 ⊕ f32-scalar), so `const device InT*` failed to COMPILE and one request killed the server. Read every dtype off the array (`mlx_array_dtype`), and because the staging arrays are declared in that dtype, the block size must follow it: fp32 stages 2× the bytes and TB=32 needs 40 KiB against Metal's 32 KiB limit, so `gdnBlockTFor` clamps to 16 (null ⇒ decline to the stock kernel, never dispatch over budget). The store type is the OUTPUT's, not the input's — `OutT`, since Metal has NO implicit float→bfloat conversion and `static_cast<InT>` into a bf16 `y` only ever worked by coincidence. The stock/seq kernels survived because they index raw buffer names with `auto`; the blocked port hand-declared pointers. Guards: `gdnBlockTFor` unit test + fp32/f16 cases in the blocked-parity sweep.
- **A custom `fast_metal_kernel`'s signature comes from each input's ACTUAL dtype, and arrays with <8 elements land in `constant` not `device`** (`backend/common/metal_kernel.cpp`): hand-declared `const device T*` pointers mismatch on BOTH counts (Laguna feeds fp32 `x` against bf16 scales) — index the raw buffer names and let the compiler pick. A rejected guard is a SILENT no-op that is output-identical to the fallback, so every new kernel ships a one-shot "engaged" log and its parity test covers the LIVE dtype, not just the convenient one.
- **A helper that materializes a VIEW owns the view**: `mlx_slice` into `o` then `return contig(o, s)` without freeing `o` pins the whole PARENT buffer (a slice is a view). MageFlow shipped it six times — ~47 MB per DiT block = **2.2 GB per megapixel per generation**, compounding and surviving unload. Route every slice-and-materialize through ONE owning helper per file (`mage_flow.sliceContig`; krea/flux were already `defer free(out); return contig(out, s)`). `mlx_clear_cache` is NOT this fix; forcing `mlx_array_eval` and still growing rules out lazy-graph retention. RSS is blind to Metal buffers (flat at 8.5 GB while 10 GB leaked) — measure `/props` `active_bytes` + `vmmap`, FLUX klein as the clean control.
- **mlx-c iterator refs**: `iterator_next` hands a +1 you must transfer into your container or free — copying via `mlx_array_set` and dropping the handle leaks a phantom ref (immortal buffers; 18 GB per video-gen cycle). Diagnosis split: `active_bytes` NOT dropping after unload = leaked HANDLES; active flat + phys climbing = allocator-CACHE growth.
- **Allocator-cache growth**: `mlx_array_free` returns buffers to MLX's size-keyed cache; loops freeing never-repeating sizes grow phys footprint unbounded (invisible to `active_bytes` and `ps`). Every decode/denoise/prefill loop owes periodic `mlx_clear_cache()` — once per CHUNK and once per emitted block (steady-state and intra-request PEAK are SEPARATE bugs; fixing the first hides the second). Repro must VARY the size-driving shape (fixed-prompt replays prove nothing); sample DURING the request (`vmmap -summary` peak vs `/props`).
- **Special-token splitting**: only `Tokenizer.encode` (first-byte buckets, longest-match-first) — a per-special rescan is O(specials×text): 12 s/66 KB on gemma-3's 6415 specials, and this class shipped TWICE (a duplicate splitter hid in chat.zig). Any per-position loop over a vocab-derived collection needs an index. `timings.tokenize_ms` + `/tokenize` isolate the layer.
- **mlx `Copy`/`contiguous` are VIEW ops**: neither breaks buffer aliasing for a row-contiguous slice — a slice OUTLIVING its parent (cache entries, checkpoints) goes through `materializedOwnedCopy` (add same-dtype scalar zero) + eval. `mlx_save_safetensors` silently appends ".safetensors" when missing.
- **mlx-c upgrades**: diff `lib/mlxc-src/mlx/c/*.h` against `src/mlx.zig` extern decls (0.6.0 inserted `global_scale` into `mlx_dequantize`); the submodule pin must stay a version pair brew has PROVEN compatible or mlx-c stops compiling against mlx (v0.6.0 tag vs mlx 0.32.0 fft API class — fba4470 = v0.6.0 + brew's 4 patches). ds4 bumps: re-sync `ds4_ffi.zig` EngineOptions (mid-struct inserts silently hang generation — now caught by the `src/ds4_layout_check.c` sizeof/offsetof test in ds4_ffi.zig) + mirror upstream Makefile CORE_OBJS in build.zig's `addDs4Sources` (efdadd4 added ds4_tp.c + ds4_layer_pack.c).
- **NAX presence is asserted, never assumed** (silent-fallback class): MLX's NAX kernel CMake gate (SDK ≥ 26.2 AND deployment ≥ 26.2) fails SILENTLY → `build-mlx.sh` + `tests/test_mlx_staged_nax.sh` grep the metallib for `*_nax` and check minos. A future brew-bottle rebuild on 26.2+ builders would flip stock-op NAX ON for M5 (formula pins deployment to the builder's point release) — we self-build precisely so that never changes underneath the M5 EV calibration.
- **`openDirAbsolute` on an empty/non-absolute path is ReleaseFast UB that miscompiles the CALLER** (stdlib assert = unreachable; the optimizer deleted a later branch in main()). Guard every openDir/openFileAbsolute call site. When Debug and ReleaseFast disagree on control flow, suspect unreachable-class UB upstream (failed assert, @intCast overflow, null `.?`) and bisect in Debug.

### Model loading, configs, converters, media parity (→ docs/gotchas/models-media.md)

- **A distilled FEW-STEP diffusion model can REQUIRE bf16 arithmetic — f32 is not "more accurate", it washes** (MageFlow Turbo class): the 4-step Turbo DiT run in f32 denoises to a grey blob; bf16 gives crisp (component cosine-1.0 parity in EITHER precision hides it — the divergence only compounds over the multi-step loop). Two bf16 behaviors the checkpoint bakes in: (1) RoPE rotates in f32 then casts to the compute dtype (a bf16 rotation drifts over 12 blocks × N steps); (2) the TIMESTEP VALUE + its sinusoidal freq table are bf16-ROUNDED before the embedding (`roundBf16`) — an un-rounded f32 timestep is the washing bug (e2e cosine 0.55 vs 0.99), because the distilled model memorized the exact bf16 conditioning. mlx promotes bf16⊕f32-scalar → f32, so scalar constants must dtype-match (`scalarLike`); norms compute f32-internal and output the input dtype. Only the sensitive component needs bf16 (MageFlow: DiT+encoder bf16, VAE stays f32 and upcasts its latent). Debug the loop, not the single forward: dump the reference in its NATIVE dtype and compare per-step, and decode a "washed" latent to confirm vs a different-but-valid one.
- **A reference-image editor must not change its input's geometry**: MageFlow edits AT the target grid (every reference is resized to (W,H) and concatenated into the DiT stream), so a 1024² request squashes a 3:2 photo — the reference pipeline instead RESOLVES the target from the primary ref. `gen.fitAspect` reshapes the requested size to the primary reference's aspect at the same pixel budget, /16, logged; any byte-based edit backend inherits it via `editUsesRawBytes`. **The aspect must then survive the CAP**: `normalizeSize` clamps width and height INDEPENDENTLY, so a reference past the backend ceiling got squared off anyway (a 4032x3024 phone photo → 2048x2048 — the exact squash `fitAspect` exists to prevent, reintroduced one step later, on the plain `client.images.edit(image=…)` call). Scale proportionally into `maxDim()` FIRST (`resolveEditTargetSize` = `fitAspect` → `fitWithinCap`), keep the ceiling pinned to the clamp with a drift test, and note that fixtures UNDER the cap cannot see this class — a guard needs a source above it. Related: the placeholder run and the ViT grid are computed by two independent paths, so `encodeEdit` asserts `<|image_pad|>` count == merged vision rows (a mismatch would die inside `put_along_axis` — uncatchable), and the templated edit prompt is capped like txt2img (`EDIT_DROP_TOKENS + TE_MAX_COND`) because the LM's causal mask is built DENSE on the host: an uncapped client prompt is an O(L²) allocation.
- **Quantize only what a MATMUL reads** (converter class): a shape-based "is this a linear" rule (rank 2, in%gs==0, dims ≥512) happily packs `embed_tokens.weight` and `visual.pos_embed.weight` — which are read with `mlx_take_axis`, so the gather returns packed uint32 garbage. Lookup tables are the one case shape cannot decide, so `convert_mageflow_weights.py` carries an explicit `NEVER_QUANTIZE` list. Same rule bounds the win: 0.78 GB of MageFlow TE stays dense until a gather-then-dequantize path exists.
- **A configless repo SHAPE must be taught to every "is this a model?" answer** (MageFlow discovery class): the shape was known to `peekConfig` (`peekMageFlowIndex`) but `tryAddModel` returned false on a missing root config.json BEFORE calling it, the byte scan only summed top-level `*.safetensors` (diffusers keeps weights in component subdirs → size null), and `cli.zig` had a THIRD private copy of the test — so every MageFlow checkpoint was invisible to `list`, `/v1/models` and the app picker while `--model <path>` worked fine. One predicate, exported and shared (`model_discovery.peekMageFlowIndex`), plus `sumComponentWeights` one level down. Guards: `discoverModels finds a MageFlow repo`, `cli: isModelDir accepts a MageFlow repo`.
- **Read `text_config` FIRST, then root, PER FIELD** — every config reader (discovery stub meta AND `parseConfigFromJson`; the class shipped twice in opposite directions). Fields a minimal `text_config` omits need explicit per-arch HF defaults (gated on `get(field)==null`), else 12b-shaped struct defaults crash warmup (`Cannot reshape N into (1,1,H,D)` signature).
- **`*_text` siblings** (gemma3_text/gemma4_text/qwen…): accept the tag in the arm, collapse to the base type, pick weight prefix by `text_config` presence (`language_model.model` vs `model`), force `tie_word_embeddings` for Gemma (never ships lm_head), and add to BOTH visibility allowlists (`model_discovery.supported_model_types` + Swift `supportedModelTypes`).
- **Multi-converter MoE containers**: hy_v3 experts ship as `mlp.experts` (ox-ox) OR `mlp.switch_mlp` (mlx-lm) — resolve by probe (`hy3ExpertContainer`), never hardcode one name for an arch with multiple converters.
- **Gemma terminators merge ADDITIVELY** (`ensureGemmaTerminators`: adds 1+106 if absent, idempotent, all three arms) — never gate a known chat terminator on "config provided no eos" (a scalar `eos_token_id: 1` defeats it → `<end_of_turn>` leaks forever). Same class as the Qwen `<|im_end|>` load-path merge.
- **Quant modes resolve PER WEIGHT** (`computeQuantParams`; scales dtype decides: uint8 → config's fp8 mode, float → affine with (bits,gs) solved from the activation inner dim): mixed QAT checkpoints override individual layers; `.biases` mandatory under affine, OPTIONAL under non-affine (`getLayerBias`) — never skipped, and never infer fp8-vs-affine from `biases==null` alone.
- **Affine bits outside MLX's kernel set {2,3,4,5,6,8} must be rejected at config PARSE** (`parseConfigFromJson` → `UnsupportedQuantBits`): mlx only validates bits inside `quantize()`, so an already-quantized checkpoint (a "1-bit" conversion) loads fully and dies at warmup with an UNCATCHABLE `Unable to load kernel affine_dequantize_..._b_1` — one bad model killed the whole server. On an mlx bump that adds a width, extend this switch AND `affineParamsFromGeometry` together.
- **A GGUF folder is a SHELF of models, not a model**: one `LocalModel` per quant (path = the FILE; `id#<file>` suffix; display `repo · QUANT`), per-quant delete/cancel scoping, `existingModelDir` accepts config.json OR a servable .gguf, terminal-state-free quant menu, and the sidecar classifiers (Swift `isGgufSidecar` / Zig `isGgufSidecarBasename`: mmproj + tokenizer) MUST stay in sync — a new `.gguf` companion convention updates BOTH.
- **DiffusionGemma parity = converged-canvas self-consistency**, never random-canvas logit compare (garbage canvases put the sigma-MoE router on knife-edge ties; one bf16 kernel-order difference flips expert sets while both outputs are "valid"). Sliding prefill takes the `"causal"` fast path when `total_kv ≤ sw` (reference kernel/reduction parity affects convergence). Trace: `MLX_SERVE_DIFFUSION_TRACE=1`.
- **Optional per-token modulation over a scalar path (LTX I2V AdaLN class)**: gate entirely on the optional mask (`nv_pt==0` dispatches to the EXACT unchanged scalar code — zero t2v overhead) and pin with a uniform-mask self-equivalence test (per-token with all-ones mask MUST reproduce scalar; reference-equality tests cannot see a scalar-path regression). Audio/prompt/AV gates stay scalar for image-only conditioning.
- **Parity fixtures for deep ViTs/DiTs: dump fp32 on CPU** — torch fp16-on-MPS quietly decorrelates deep networks (cos ~0.3, no NaN — nothing "fails" at dump time; SD-class UNets/VAEs are fp16-safe). An oracle missing badly ⇒ suspect the FIXTURE before rewriting the port (numpy-spec repro from converted weights localizes in minutes). transformers ≥5.x materializes custom-model rotary `inv_freq` buffers as ZEROS (identity-RoPE fixtures): dump scripts assert rotary buffers non-zero + rebuild from fresh instances; an oracle that IMPROVES when you remove a transform = the fixture's transform was silently disabled.
- **TTS**: ECAPA/SpeechBrain `TimeDelayNetBlock` = conv + IMPLICIT ReLU — never drop it when fusing (0.9989 vs bit-exact). Embedding lookups reshape to the TABLE's native width via `getShape`, never a config dim (a projection between lookup and residual makes them diverge; wrong width = uncatchable reshape crash). Voice clone = ECAPA speaker embedding spliced as one codec-prefix position; `ref_text` ignored; no predefined voices on Base checkpoints.
