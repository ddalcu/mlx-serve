# Swift macOS app (MLX Core) — AI context

Compressed rules. Full war stories: `../docs/gotchas/app.md`. Full service contracts: `../docs/reference.md`. Repo-wide policy (TDD, release, conventions): root `../CLAUDE.md`.

## Build

- ALWAYS ship via `bash app/build.sh` (signs, entitlements, links Zig artifacts, keeps MLXCore + mlx-serve in lockstep); dev: `SKIP_NOTARIZE=1`. **No signing identity on the machine?** `APPLE_DEVELOPER_ID='-' APPLE_TEAM_ID='-' SKIP_NOTARIZE=1 bash app/build.sh` takes the ad-hoc branch (line 282: hardened runtime and productbuild are skipped for `-`), which is how a dev bundle is already signed — `codesign -dv` on it reports `Signature=adhoc`, `TeamIdentifier=not set`. A release still needs the real identity, so cut it where that lives or via `.github/workflows/release.yml`. Swift-only fast iteration escape hatch: `cd app && swift build -c release`. Never force a global Swift language mode through SwiftPM: MLXCore's manifest keeps the app in Swift 5 mode while modern dependencies compile in the mode declared by their own manifests (swift-sdk must stay >= 0.12.1; 0.10.x cannot compile in the MAS Xcode project).
- **`FAST_DEV=1 bash app/build.sh` is the iteration build, and an UNSET var is the release path byte for byte** — one variable gates every shortcut, so a shipping build can never take one by accident. What it changes: Swift compiles `-c debug` (the single biggest lever — `-c release` turns on WMO, so touching one file recompiles the module, and SwiftUI's type-checker is what makes that minutes; the two configurations keep SEPARATE build dirs, so alternating costs a full rebuild of whichever you left); CalVer skips the `gh` round-trip and does NOT stamp the tracked Info.plist (a fast build cuts no release, and a dirty tree is what breaks release.yml's Homebrew rebase); the bundle is updated IN PLACE (no `rm -rf`) and the icon is regenerated only when the bundle has none; the frameworks are re-staged, re-fixed-up and re-signed as ONE decision, skipped while `lib/mlx/lib/libmlxc.dylib` is no newer than the bundled copy — `install_name_tool` rewrites a file and invalidates its signature, so skipping the re-sign while still running the fixups would leave broken signatures in the bundle; and it stops at a signed .app, before notarization, `productbuild` and the DMG. What it deliberately does NOT change: **mlx-serve stays `-Doptimize=ReleaseFast` even under FAST_DEV** — Zig's cache already makes an unchanged rebuild a few seconds, so the Swift phase is the whole cost of an iteration and the Debug arm buys nothing for Swift-side work. **`ZIG_DEBUG=1` is that arm, a SECOND lever rather than something FAST_DEV implies**, because it costs more than it looks like: a Debug engine decodes 2–4× slower (root `../CLAUDE.md` "Building"), so every latency read off that app is fiction — and it is invisible from the running app, which is why the fast-build banner names both configurations — and Zig keys its cache on the optimize mode, so alternating with a release build is a full rebuild each way. Reach for it when the thing you are debugging is Zig-side (safety checks, real panic traces), not while iterating on Swift. It is FAST_DEV-only and refused BY NAME otherwise (`ZIG_DEBUG=1 bash app/build.sh` exits before any build work rather than quietly shipping a Debug engine): FAST_DEV is what stops before notarization and the DMG, so that gate is the entire reason a Debug binary cannot reach an artifact anyone else runs. The trade to know: a resource deleted from `Sources/` lingers in the bundle, so when a fast build behaves strangely, delete `app/MLX Core.app` (or run once without `FAST_DEV`) before believing it. Guard: `tests/test_release_workflow_gates.sh` (the release path still compiles `-c release`, still starts from an empty bundle, the optimize mode defaults to ReleaseFast with the one `-Doptimize=Debug` sitting directly under the ZIG_DEBUG gate behind a refusal that exits before any build work, and the FAST_DEV `exit 0` precedes notarytool/productbuild/create-dmg — the first draft of this change had reindented the script and left `# ... (rest of the block is identical)` where notarization and the App Store .pkg used to be).
- The .app bundles TWO binaries (MLXCore UI + mlx-serve server) — always update together; a stale sibling is the classic "still doesn't work".
- **The bundle's version is STAMPED from the version being released, never copied from the committed plist**: release.yml PlistBuddy's `$CONTENTS/Info.plist` after the `cp` and before `codesign` (stamping the repo file instead breaks the Homebrew step's `git rebase` on a dirty tree). It shipped unstamped once — v26.8.1's DMG contained an app reporting 26.7.12, so `UpdateChecker` offered an update that installing could never satisfy, forever. CalVer's `YY.M` is TZ-pinned in release.yml and app/build.sh together (runners are UTC; an evening release otherwise lands in next month). Guard: `tests/test_release_workflow_gates.sh`; story: `../docs/gotchas/app.md`.
- **An asset dragged out of Finder carries `com.apple.FinderInfo`, and codesign refuses the WHOLE bundle for it** (live 2026-08-09, a screen recording copied off the Desktop): `resource fork, Finder information, or similar detritus not allowed` — reported three minutes into a build, against the BINARY rather than the file that brought the metadata in. build.sh now `xattr -cr`s the staged bundle before signing (fixes the class); `tests/test_resource_xattrs.sh` keeps the checked-in copies clean so it's caught in a second with the file named. It checks ONLY the attributes that actually block signing — `com.apple.macl`/`com.apple.provenance` are added by macOS whenever a sandboxed app touches a file, every existing resource has always carried them, and failing on those would make the guard cry wolf until someone deleted it.
- Agent Sandbox needs `com.apple.security.virtualization` in BOTH signing branches of build.sh (ad-hoc included) or VZ refuses to boot. `swift build` binaries / xctest can't boot VMs; live guard = `SANDBOX_SMOKE=1 <MLXCore binary>`.

## Rules

- **A GUI bundle has NO shell environment, so an env var the user set is INVISIBLE — reading it is not the same as honoring it** (HF cache, 2026-08-14): `huggingFaceRoot` already read `HF_HUB_CACHE` then `$HF_HOME/hub`, but from `ProcessInfo.processInfo.environment`, which a Finder-launched app never carries — so those branches were dead in the shipped app and every install fell through to `~/.cache/huggingface/hub`, listing nothing for anyone who moved the cache off the boot drive (the same reason `hfToken` prefers the token FILE over `HF_TOKEN`, and `CLIInstaller` asks the login shell for PATH). `LoginShellEnv` is the ONE probe now: marker-delimited `printf` through `$SHELL -l -i -c`, 5 s watchdog, cached, primed OFF-main at launch (`refreshHuggingFaceRootFromLoginShell`, rescan only when the root MOVED) so nothing blocks on an rc file; process env WINS over the shell's, and an unset var must not come back as `""` and shadow one the process has. `XDG_CACHE_HOME` was missing outright and is now in both the root and token precedence, matching `huggingface_hub`'s own order (`HF_HUB_CACHE` > `$HF_HOME/hub` > `$XDG_CACHE_HOME/huggingface/hub` > `~/.cache/huggingface/hub`). A CONFIGURED root that is not on disk is nil, never a fall-through to the default cache — the point of the variable is that the models are elsewhere. Gated on `BuildFeatures.customModelFolders`: under MAS an out-of-container cache is unreadable whatever the shell says (audit entry in `HostEscapeAuditTests`). Guards: `HuggingFaceRootTests` + the class scan `testHuggingFaceEnvIsNeverReadStraightFromTheProcessEnvironment`, verified red by injecting one direct read.
- **The app is ONE window: Models / Tasks / Settings / the four media generators are MODES of the chat window** (`Models/ChatWorkspace.swift`), not `Window` scenes. Each has exactly one door on `AppState` (`showModels` / `showTasks` / `showSettings` / `showCreate`) that sets the mode AND bumps `pendingChatOpenTick` — setting the mode alone switches a window nobody is looking at, opening the window alone lands on a transcript. Retired scene ids (`modelBrowser`, `tasks`, `settings`, `imageGen`/`videoGen`/`audioGen`/`model3dGen`) are gone from every surface: `openWindow(id:)` on an unknown id is a silent no-op, so a leftover id is a control that opens nothing (guards: `ChatWorkspaceTests`). The sidebar is a list of DESTINATIONS above the conversations and never rearranges — the row that takes you in is the row that brings you back, which is what the tray/welcome/Tools-menu entries (which arrive already in a pane) depend on.
- **Moving a view into another window means moving its ENVIRONMENT with it** (live crash 2026-08-08): the browser's window injected four objects, the chat window three, and opening the models pane trapped in `ModelBrowserPane.downloads.getter` — SwiftUI reports a missing `@EnvironmentObject` at first RENDER, with no compile error. `testTheChatWindowInjectsEveryObjectItsHostedPanesRead` regex-scans every hosted pane's declarations against an explicit injection map, so a new one fails a test naming the type. Corollary: a pane with its own `NavigationSplitView` (Tasks, Settings, Agents) can't just be dropped in — it needs an `embedded` shell (plain HStack, or promoted to real columns as Tasks was), or it fights the outer sidebar.
- **An environment reader has to BE the column, never produce it** (second crash the same day, and the injection audit was green throughout): the Tasks columns were `TasksView().taskList` / `.taskDetail` — a view VALUE whose computed property is evaluated on the spot. SwiftUI populates `@EnvironmentObject` storage when it INSTALLS a view in the hierarchy, and that instance never was one, so the first click on Tasks trapped in `TasksView.$appState.getter`; the `.environmentObject(…)` chained at the call site cannot save it, because it decorates the view the property already returned, long after the property read the empty box. Columns are `TaskListPane` / `TaskDetailPane`, real types declaring their own environment. The guard is a source scan for `SomeView(…).bareProperty` — a MODIFIER is always a call, so "property access not followed by `(`" separates the two shapes with no allowlist to maintain (comments are stripped first, or it matches the prose warning about it). The window-injection audit is blind to this class by construction: it asks what the window injects, and the bug is WHERE the reading happened.
- **`listRowBackground` is the ROW's backdrop, and `listRowInsets` moves only the CONTENT**: putting the conversation highlight in the former made a selected chat run edge to edge under a column of destinations inset 8pt, while both read the same `SidebarRowStyle` colour — one meaning for gray, two shapes. The fill rides the row content as a plain `.background`, inside the same insets, with `.listRowBackground(Color.clear)` so the list cannot draw a second surface beneath it. Guard: `testTheConversationHighlightIsInsetLikeADestinationRow` (walks back from the fill to the nearest enclosing modifier and demands it be `.background(`).
- **Hiding a window toolbar hides its RESIDENTS** (live 2026-08-09): `.toolbar(.hidden, for: .windowToolbar)` removes the BAR, and the traffic lights and the sidebar-collapse button live in it — a window that cannot be closed, zoomed or collapsed. To retire an empty band, hide its MATERIAL (`.toolbarBackground(.hidden)`), which keeps the bar, its chrome and the safe area it reserves. The older trap pointing the other way (`toolbarBackground(.hidden)` leaves `scrollEdgeEffectStyle` attached to an invisible bar, transcript text clipping mid-line, 2026-07-30) was about the floating CLUSTER; with no cluster nothing floats over the transcript. Guard bans `.toolbar(.hidden)` and requires the material form in both splits.
- **A `ToolbarItem` on macOS 26 draws a capsule around EVERYTHING it holds**: a title beside a button becomes one "Tasks +" lozenge with the title's baseline padding fighting the button's hit area. Ask for `.sharedBackgroundVisibility(.hidden)` (the answer the chat's old cluster used) and let the button carry its own hover-lit target. Static content only — the `»`-eviction rule is about members that appear or change WIDTH at runtime, which a fixed word and one button are not. Shared as `PaneTitleBar` so Tasks and Agents cannot drift.
- **`.listStyle(.sidebar)` adds a horizontal margin that `listRowInsets` does not control** (live 2026-08-09): the same "8" therefore drew two different widths — destinations at the panel edge, conversations pushed ~18pt further in — and zeroing the row insets changed nothing on screen because that was never the number doing the work. No API removes it. Rows that draw their own background, hover, selection and separators get nothing else from a List, so the conversation column is a `ScrollView` + `LazyVStack` taking the SAME `.padding(.horizontal, ChatMetrics.sidebarGutter)` the destination stack takes. One gutter + one row inset constant, read by both halves and the section headers.
- **A row's hit target is whatever its BUTTON covers, not what its fill covers**: sizing the row from an outer frame centres the label in it, leaving a dead strip along the top and bottom of the highlight. The button carries the padding, the height floor and the `contentShape`; a trailing control becomes an overlay (a real Button, hit-tested first) with its space reserved at ALL times, since reserving it on hover reflows the title under the pointer.
- **Exactly one row of the sidebar is lit** (`SidebarSelection`): destinations read `chatWorkspace` and conversations read `activeChatId`, so nothing reconciled them and opening Tasks left the last chat lit beside it — each half correct alone. The active chat is where you ARE only while the window is showing conversations.
- **A placeholder title is a CONCEPT, not a literal** (`ChatSessionTitle`): the auto-titler gated on `title == "New Chat"`, so an agent thread starting as "New agent" would have kept that name forever. Placeholders + the derived title live together; `display(title:hasAgent:)` normalizes at DRAW time so threads stored before agents had a section read correctly without rewriting anything on disk.
- **A view expression can stop the compiler finishing** (live 2026-08-09): the agent editor's identity header as one nested expression took the release build from ~48s to over TEN MINUTES, with no warning — SwiftUI's type-checker just grinds. Split into typed sub-views it was 47.9s. Suspect the last view you wrote when a build time jumps an order of magnitude.
- **A redesign is where affordances disappear quietly** — nothing fails when a control simply stops being drawn. Removing the Agents row's menu once left `startChat(withAgent:)` with NO caller anywhere in the UI while its test stayed green, because the test named the control's location instead of the capability. Pin that it is reachable AT ALL; `AgentsPanelTests` lists every affordance the agent editor had, each named so a failure says WHICH one went.
- **One meaning for gray in the sidebar** (`SidebarRowStyle`): destinations and conversations read the SAME fill for hover/selection. A `List(selection:)` also draws its own tint UNDER `listRowBackground` — that double highlight is why the conversation rows are plain Buttons with no selection binding. Row + delete button are real siblings, never a tap gesture around a button (the swallowed-click class).
- **The chat column has a reading measure** (`ChatMetrics.contentMaxWidth`, 740): transcript, composer and the empty-state greeting all cap at it and centre. One number for all three — a composer even slightly off the answers above it is a seam you can't unsee.
- **The composer never becomes a generator** (create mode REMOVED 2026-08-09): a media chip navigates to the Create pane through `appState.showCreate`, exactly like the Tools menu. Two ways to make an asset, not three: chat with tools on (the model drives at preview settings) or the Create pane (you decide everything). Old sessions may still carry a `createMode` key on disk — the decoder no longer asks for it.
- **Per-chat tool switches SUBTRACT at the resolution chokepoint, never at a turn site** (Tools pill → chevron menu): `AppDefaultsSnapshot.disabledTools` is removed from whatever the agent (or the app defaults) already allowed, so a chat tab can never grant a capability an agent forbids — forbidden rows render disabled rather than offering a switch the resolver would ignore. Turning everything off makes the turn plain chat (`loopRuns`: advertising nothing while still looping is a dead offer). `searchDocuments` is exempt from BOTH the menu and the subtraction — its gate is the attached folder, which is stronger — and `AgentToolKind.chatToggleable` × `AgentToolGroup` are pinned against each other (a tool in no group is unreachable from the UI; one in two renders twice). Stored on the session as RAW STRINGS so a retired tool leaves an unknown name instead of failing the whole session's decode. Guards: `SessionToolDisableTests`.
- **A control the AGENT decides shows the agent's value and says who decided it** (composer Think/Tools/MCP): `AgentResolution` takes `toolsEnabled` from the agent's capabilities and `mcpEnabled` from `capabilities.mcp` and ignores the chat's own toggles — and `AgentCapabilities.web` defaults TRUE, so selecting ANY agent (even one with `tools: false`) forced the tool loop on while the wrench rendered OFF and a click on it wrote a field the resolver discards. `ChatModeToggles.resolve(…, agentLock:)` overlays the agent's values and names the owner PER CONTROL; the disc gets a dashed inset ring (never a dimming — ON/OFF is what its colour has always said) and its menu becomes "Set by \<name\>" + "Edit Agent…", because a locked control that does nothing on click is the dead-control class. Thinking locks ONLY when `agent.enableThinking != nil` — resolution falls back to the surface there, so locking it takes away a control nobody is deciding. The lock is built from `resolvedAgentSettings`, NEVER from `capabilities` directly (a second copy of that rule is how they drifted), and the pre-send intent nudge plus both setters refuse while locked. Guards: `ChatModeTogglesTests`, `ComposerModeControlTests`.
- **The pre-send nudge is ONE pure decision, and tools can be made strictly opt-in** (`ComposerIntent.nudge`): every gate — the opt-in setting, mode already on, agent lock, per-chat "Send Anyway", MCP-before-Agent priority — lives in that one function, and `ChatView.detectIntentPrompt` only gathers its inputs. Settings ▸ Agent Sandbox ▸ "Only use tools when I ask" (`ServerOptions.toolsOnlyWhenAsked`, default OFF = shipped behavior, app-level so it never trips the restart banner) short-circuits it: tools reach the model only where the wrench/MCP disc or the tab's agent turned them on. A second copy of the rule in the view is how one branch would keep nudging — source-scan-pinned in `ComposerModeControlTests`, branch-pinned in `ComposerInputTests`.
- **The chat generates media itself, at PREVIEW settings, one per message** (`generate_image` / `generate_speech` / `generate_music` / `generate_video`): speech and music are separate tools because music IS audio and one overloaded tool makes a 2B guess (`generate_audio` was split — `Agent.renamedTools` maps the old name, since the capability decoder DROPS names it doesn't know and a plain rename would silently strip the capability from every agent that had it). The model picks nothing but the prompt: which model comes from the user's saved settings for that modality, the step/duration knobs from `MediaChatDefaults` (a chat generation blocks chat decode on the one GPU, so it is a preview and the tray window stays the place for full-quality work), and every number it CAN send is clamped in `MediaToolArgs` — a 4B asking for 30 seconds of video is not hypothetical (measured: clamped to 4.0s). Read the spellings models actually emit: asked for "widescreen" a model sends `{"size":"16:9"}`, and an aspect resolves against the user's OWN size (an exact-ratio match escalated a preview to the model's largest 16:9, 8× the pixels). **One generation per USER TURN**, keyed by a turn TOKEN the driver passes rather than a `reset()` it must remember — as a reset call, the headless harness (a second driver on the same engine) inherited a spent budget and silently refused every generation forever. The refusal leads with **"NOT GENERATED"** and the words to relay: with the rule first and the fact second, a refused 4B told the user both items had been made. Music takes the WHOLE knob set the engine reads (`bpm` 30–300 — outside it the server 400s, so it clamps; `keyscale`, `time_signature`, `vocal_language`), each validated against `MusicOptions` — the catalogue IS the accepted grammar — and OMITTED when unrecognised, because only `bpm` is checked server-side and an unknown `keyscale` goes into the conditioning as junk (an absent field is the engine's own "model decides"). Results ride `ChatMessage.media` as a PATH (`ChatMediaRef`) — a 30 s track is tens of MB and `chat-history.json` would carry it forever. An IMAGE carries both: the JPEG bytes the transcript draws AND a `.image` ref for the same Reveal-in-Finder row a track gets, which is why the ref line sits BETWEEN the caption and the data URI (after it, the caption swallows the whole base64) and why both land on ONE message. A missing file is its own row — except for an image, whose picture is still on screen, so the row just disappears. Guards: `MediaToolArgsTests`, `MediaGenProgressTests`, `AgentMediaInlineTests`.
- **A live ETA from observed laps is floored by the MODEL and carries the after-sampling tail** (`H3TimeEstimate.liveEta(floorPerStep:tail:)` from `livePricing` — the pre-run estimate decomposed): under the fast recipe the lap history is dominated by cheap cached steps while the closing steps always refresh at full cost, and the VAE decode never appears in step events — mean × remaining said "77 sec left" with minutes to go. H3 only; LTX keeps the plain mean (uniform laps, no pre-run model). Guards: `H3PlanningTests` floor/tail + decomposition cases.
- **A media generation shows a meter or it reads as a hang**: `ChatTurnEngine.mediaProgress` (ONE value — the inference thread serializes media gen) drives `MediaProgressCard`, determinate when the engine reports a total and indeterminate when it doesn't (TTS length is model-determined, so it sends a growing frame count against total 0 and a bar at 0/0 looks stuck). Elapsed time is a `TimelineView(.periodic)`, never a `repeatForever` animation or a `Timer` — that is the `VoicePulse` tray-wedge class. The four services' identical SSE parsing collapsed into `MediaSSE.classify`; each gained a `generateForAgent(_:server:onProgress:)` that runs the same load → stream → write → unload pipeline WITHOUT touching its pane's `phase`/`task`/`recent`, so a chat generation never hijacks the tray window.
- **"length" is two different endings, and only one of them may CONTINUE the turn** (`TruncationNotice.Cause`, live 2026-08-05): the server reports both a `max_tokens` cap and its own degenerate-tail loop cut as `finish_reason: "length"` — the only OpenAI value for either — so the app told a user with two thirds of their context free that they had hit an output limit neither side set (pi sends no `max_tokens` at all). The cause comes from the server's sibling `finish_details` (`APIClient.truncationCause(fromChoice:)`, static + dictionary-shaped so it is testable without a live stream; ABSENT reads as `.maxTokens`, which is exactly the old behaviour, so an older server or another OpenAI backend is unchanged), and it rides `SSEEvent.truncated(cause)` — renamed from `.maxTokensReached`, which had stopped being true. A repetition loop **ends the turn** (`TruncationNotice.endsTurn`, checked ahead of every recovery branch): the loop's text is already in the transcript, because a streamed delta cannot be retracted and the server's own trim only reaches non-streaming clients, so the next round sends it back as history and the model reads its own loop and resumes — the error-echo class with our transcript as the error, and from the server it looks like five cuts in a row, each firing sooner. A max_tokens cut keeps every existing recovery (chunk-and-retry, truncated-tool-call nudge) — the reply was fine and ran out of room. The loop notice names NO cap: naming one sends people to raise a setting that was never the problem (same rule as `ChatErrorNotice` refusing a diagnosis it cannot support). Guards: `TruncationNoticeTests`. Server side + the measurements: root `## Rules`.
- **The truncation notice is DATA on the message, never content** (`ChatMessage.truncationNotice`, 2026-08-11): the banner used to be APPENDED into `message.content` (`updateLastMessage(content:)`), so both history builders sent "⚠️ Stopped — the model started repeating itself…" back as assistant prose every turn — the error-echo class with our own warning as the error (live capture: the banner rode the muse chat forever). The notice rides `TruncationNotice.Notice` (cause + cap), renders as a footnote under the bubble (`MessageBubble`), and content stays clean by construction; sessions saved by older builds get the in-content banner scrubbed at history build (`TruncationNotice.stripped(from:)`, both builders — markers DERIVE from the legacy `text(...)` so they cannot drift). Decode is tolerant (unknown cause → nil, absent forever on old messages). Guards: `TruncationNoticeTests` data-not-content cases.
- **A failure is its own transcript row, not text appended to the model's answer**: `[Error: …]` glued onto the assistant's own content read as something the model said and gave the user nothing to do. `ChatErrorNotice` classifies it — `.contextOverflow` (the one failure fixable from here) carries the server's real counts and offers "Increase Context Size"; everything else stays `.generic` and shows the server's wording verbatim, because guessing a diagnosis sends people to change settings that were never the problem. The notice message is `failedRetry`, so it renders but is excluded from the history sent back (an error card fed in as assistant output is how a model starts apologising for a server failure). ## Testing — TDD is mandatory for every change

Order is fixed: (1) failing test FIRST, failing for the right reason; (2) minimum code to green; (3) full suite (`zig build test` 6/6 steps 0 fail + `cd app && swift test`/`build` + relevant `tests/*.sh`); (4) refactor under the tripwire. A live curl is a sanity check, NOT a test.

Per change class: feature = unit test that fails without it (+ integration script if HTTP-observable). Bug fix = regression test red→fix→green, verified red-on-revert. Cross-arch work = cover every touched arch. Refactor = characterization test first if coverage is missing. UI/build scripts = factor a pure helper and test that.

**Class bugs get class guards — no whack-a-mole.** A live failure revealing a CLASS ships THREE things: the instance regression test; a corpus entry or universal invariant in `src/format_corpus_test.zig`; and a 1–3-line rule here + full story in `docs/gotchas/`.

## Conventions

- Minimal DRY Zig; tests at the bottom of each source file; shell integration tests in `tests/`.
- Inference thread is the SOLE mlx caller (even array frees) — media gen posts to `gen_queue`, never a gpu mutex. A long gen blocks chat decode (accepted; single GPU).
- Concurrent requests batch-decode on pure-attention archs; `--max-concurrent` sizes the submit queue, not a decode gate. Slots entering a batch mid-generation drain lazy pipeline state first.
- A cold prefill YIELDS to decode ticks at chunk boundaries and between admitted slots (`scheduler.interleaveDecodeTick`), so concurrent streams stall at most one chunk-forward instead of the whole prefill; greedy output is byte-identical, idle/single-stream cost is zero, `MLX_SERVE_PREFILL_INTERLEAVE=0` restores whole-prefill scheduling. Guard: `tests/test_prefill_interleave.sh`.
- KV reuse via prompt-prefix matching; invalidated after tool calls + pad-only gens; hot cache spills to SSD tier; RAM invalidation propagates to disk.
- Chat templates live in model dirs; Jinja renders with fallback formatting.

## HTTP APIs

- **OpenAI chat/completions + Responses**: usage ALWAYS carries `prompt_tokens_details.cached_tokens` (ONE `formatChatUsage` helper — black-box tooling reads only this); thinking opt-ins = `reasoning_effort` OR `enable_thinking` (explicit `reasoning_budget_tokens` outranks); `n>1` honestly 400s. `/v1/responses`: envelope echoes request fields, every SSE event gets `sequence_number`, `background:true` → 400, stateful chains via `ResponseStore`, WS = same endpoint via Upgrade, NO `[DONE]` on WS success.
- **Continuing a partial reply is per-surface by design, and the RENDER is what changes** (`chat.continuationRequested`/`continuationPrefill`): the trailing assistant message becomes a PREFILL — the prompt ends mid-turn on its text, trailing whitespace trimmed (a tokenizer merges it into the next word) — instead of history followed by a second `add_generation_prompt` turn, which the model answers by starting over. `/v1/chat/completions` takes `continue_final_message` (vLLM's spelling) EXPLICITLY, because agent frameworks POST assistant-last history there expecting a fresh turn; `/v1/messages` INFERS it, because that is Anthropic's own contract; `/v1/responses` does neither. The flag is ignored (never 400'd) on a conversation that isn't continuable, and a tool-call reply is never continuable. The prompt commits the CONTENT channel first — `contentChannelTail`, shared with thinking-off, so muse's `to=user` and LFM2.5's `</think>` cannot drift — or the resumed prose comes back as reasoning. `continue_final` is part of the tokenize-cache key (same messages, different prompt). Embedded ds4 renders inside the engine and cannot serve one: BOTH surfaces consult `server.continuationRejectReason` first (explicit → named 400, inferred → ordinary turn), since `cachedFormatChat`'s backstop error reaches no handler and closes the socket bare.
- **Context-overflow 400s name BOTH counts** (`contextOverflowMessage`; legacy sentence stays the prefix). The app renders it as a card.
- **Anthropic `/v1/messages`** (Claude Code): typed blocks, `input_schema`→`parameters`, stop-reason map incl. `stop_sequence` echo (`anthropicStopReason`), full SSE content-block lifecycle. Launcher env: `ANTHROPIC_BASE_URL` + dummy keys + `ANTHROPIC_DEFAULT_*_MODEL=mlx-serve`.
- **Ollama `/api/*`**: pure translation (ollama.zig), NO duplicated inference; no-model endpoints answered pre-scheduler; `resolveName` handles `name:tag`. Discovery is two-level; one path must never register under TWO ids (`registry.peekByPath` — double-residency OOM class).
- **`/v1/models` rows carry `context_length`+`max_model_len` at the TOP level, twinning `meta.context_length`** (issue #188): openai-models-list discovery clients (oh-my-pi, vLLM-shaped readers) never read `meta.*` and substitute their own defaults (omp: 128k) when the twins are absent. Both emitters (loaded + stub). Guard: `tests/test_models_capabilities.sh` [4b].
- **LAN sharing**: proxy is a TRANSPORT; keyless gate = `routeClass` × `SharedSet`; `<id>@<peer>` mirroring; loops impossible by construction (self-token + tunnel marker, one-hop bound). Full design: `docs/reference.md`.
- **Observability** (`--metrics`): zero cost when off; TTFT at prefill completion; live tok/s via ONE atomic per decode tick. `--api-key`: loopback exempt; `/health`+OPTIONS open; `constTimeEql`. No admin surface (deliberate).

## Tool calling (server pipeline)

With `tools` present, tokens buffer for detection (all tag families + raw JSON); thinking buffered separately. Parse chain: strict → tolerant repairs → truncation salvage; then the per-request chokepoint `server.parseToolCallsForRequest` = parse → inferred-name filter → parallel clamp → buried-param hoist → schema coercion (hoist+coercion gated by `--no-tool-autocorrect`; final safety net guarantees emitted `arguments` are ALWAYS valid JSON). Serialization (`chat.serializeMessagesJson`): role "tool" native, args as JSON STRINGS, every arbitrary-byte string through `appendJsonString`. Streaming: full args in ONE SSE delta; thinking buffered until close → `reasoning_content`. Fallback (`fallbackFormatChat`): ChatML, Llama ipython, Gemma "Tool result:". Client side: `app/CLAUDE.md`.

## Rules (distilled gotchas — full stories in docs/gotchas/)

### Tool calling & formats (→ docs/gotchas/tool-calling.md)

- **Control bytes**: ONE raw byte <0x20 in history kills the strict render → SILENT downgrade to `fallbackFormatChat` (model loses its stop token). Everything through `appendJsonString`; wrong-family tags in output ⇒ suspect silent fallback before the model.
- **A `chat_template` value can be a POINTER, not a template**: transformers >= 5 writes `{% include 'chat_template.jinja' %}` into tokenizer_config.json beside the real sidecar file; jinja.cpp has no `include`, so taking it literally = silent `fallbackFormatChat` in another family's markers (issue #169). `chat.isIncludeStub` reads an include-ONLY value as "no inline template" so the sidecar loads. Wrong-family tags out ⇒ grep the log for `jinja` first.
- **Model-mangled arg JSON**: strict parse fails → `looseRepairToolCallJson` (re-escape, strict re-parse); never drop the whole call.
- **Truncated opener**: recover NAME + `{}` — NEVER ship partial content values.
- **Delimiter-drop tolerance (hy3 class)**: a tag parser never bails a call on ONE missing delimiter; plural-wrapper recovery keys strictly on the SUFFIXED `<tool_calls:` form (bare form is DSV4's).
- **A `<tool_call>` body carrying a `<function=` opener is the XML dialect and is read FIRST**: qwen 3.5/3.6's own template MANDATES `<function=NAME>`/`<parameter=KEY>` inside the SAME wrapper the JSON form uses, so the JSON branch ran first, `balancedJsonObject` snapped the package.json being WRITTEN out of the `content` parameter, and its `"name"` key shipped as the tool name (live 2026-08-12: pi answered "Tool voxel-pagoda-garden not found" and the model looped on its own error). A parameter VALUE never decides the call — a value is arbitrary bytes.
- **A `</think>` inside a tool ARGUMENT is payload, not a block close** (`chat.thinkCloseIsToolCallPayload`): decline a close whose nearest preceding tool opener is still OPEN there AND whose block closes afterwards — BOTH halves load-bearing.
- **Near-repeat loop tier** (`generate.isNearRepeatTailLoop`): a rephrasing loop has no exact cycle — judge a 1024-token window on THREE ratios that must ALL be low (distinct ≤ 0.12, 4-grams ≤ 0.35, novelty ≤ 0.10); any two alone convict honest output.
- **The third ratio is PROGRESS** (`near_repeat_max_novelty`): vocabulary ratios can't tell a loop from procedural code; novelty = fraction of second-half 4-grams the first half never had. Bar errs toward acquittal — a false cut destroys good work; a missed loop just hits max_tokens.
- **Loop-stop cuts are truncations**: `finish_reason "length"` (`scheduler.loopStopReason`), `[loop-stop]` logged, salvage ships NO fragment values; only the loop knows `maxTokensHit`.
- **A loop cut says WHY and does not hand the loop back**: `finish_details:{"type":"repetition_loop"}` on chat+completions (never invented inside Anthropic's schema); non-streaming responses trimmed to the degenerate span start (`loopTrimmedIds`, `MLX_SERVE_LOOP_TRIM=0`); streaming keeps the tail — a delta cannot be retracted. Guard: `tests/test_loop_stop_signal.sh`.
- **Types come from the SCHEMA, never the value's spelling** (`coerceToolArgsToSchema`, both directions; undecidable → untouched). ONE chokepoint `server.parseToolCallsForRequest` — never call `chat.parseToolCalls` from a handler.
- **Buried required params**: `hoistMisplacedRequiredParams` lifts only on all-schema-read unanimity; ambiguity → untouched. Pristine args are the tell that the parse layer is innocent.
- **Heuristic raw-JSON inference must name a DECLARED tool** (`filterInferredBySchema`); explicit tag calls never filtered; new heuristics set `.inferred`; deliberately not autocorrect-gated.
- **Hard invariants (replay-pinned)**: emitted args ALWAYS valid JSON; every converter escapes + dedups; coercion never worsens conformance; genuinely-broken output stays honest. Harness: `src/tool_traffic_replay_test.zig`. KNOWN GAP: `parseHermesToolCall` trims param whitespace.
- **Gemma dropped `<|"|>`**: rich bare values run to the CONFIRMED closing delimiter or top-level final `}`, never the first `,`/`}` inside markup.
- **Think-tag leaks**: strip pos-0 unclosed openers; `trimTrailingThinkClosers`; universal no-tag-leak corpus invariant auto-covers new entries.
- **Unparsed tool markup never rides out as reasoning OR content** (`chat.trimLeakedToolMarkup`): one cut at the first wrapper opener, applied ONCE in the split/strip wrapper; `/v1/messages` cuts at emission; streaming end-flush concatenates BEFORE cutting (markers split across tokens).
- **Streaming + tools + thinking**: buffer until pattern resolution; reasoning streams INCREMENTALLY on the tools path (`.hold_thinking` + `chat.unstreamedReasoning` — never a resend; a reasoning BUDGET keeps buffering). Pinned by corpus streaming replay + `tests/test_messages_stream_thinking_tools.sh`.
- **The streaming think gate scans with a CURSOR** (`chat.ThinkScan`, O(total bytes) not O(n²)); the close tag cannot be latched once a `tool_call` substring is seen (payload lookahead) — that case falls back to the exact full scan.
- **Pythonic tool calls (lfm2/LFM2.5)**: call-expression grammar; value TYPES live in the SPELLING (`True`, single-quoted lists) and are parsed at parse time; marker-gated ⇒ additive; truncation ships NAME + `{}`.
- **A template can open `<think>` unconditionally** (LFM2.5): whether a prompt ends inside a think block is a property of the RENDERED BYTES (`server.promptOpensThink`), never ANDed with `enable_thinking`; thinking-off + prompt-opened ⇒ a stream arm DROPS the block. New template ⇒ check if its opener is conditional.
- **`in_think_block` starts from the PROMPT, not the request flag**: the end-of-stream flush demands POSITIVE evidence a block was open (`saw_think_open` or prompt opener) — Gemma decides per turn. That rule covered the FLUSH but not the SEED: all three streaming surfaces still initialized `in_think_block` by OR-ing `enable_thinking` in, which is only harmless where the template renders the opener (Qwen/Gemma — where `promptOpensThink` sees it in the rendered bytes anyway). LFM2-VL's generation prompt is a bare `<|im_start|>assistant` and its model answers directly, so a thinking-enabled STREAM routed the entire answer into `reasoning_content` and shipped `content` EMPTY — the app drew a Thinking block with the whole reply inside it and nothing underneath (live 2026-08-13), while the same request non-streaming was correct because the non-streaming split always keyed on the prompt. The seed is now `prompt_opened_think` alone at every site; class guard = the source scan `a stream never starts inside a think block because the REQUEST asked for thinking` (needle ++-split so its own comment can't satisfy it), and the bar is the stream-vs-non-stream byte invariant, not phrasing (`tests/test_lfm2_vision.sh` [6/7]).
- **An integration assertion that a MODEL must think/answer/call is a checkpoint expectation**: assert the INVARIANT, branch on the model's choice; a skipped arm reads as a pass.
- **A contract COMMENT is read as a spec** — pin it with a test or it gets filed as a bug (issue #94).
- **Assistant-history reasoning round-trips** (`Message.reasoning_content`, key OMITTED when absent): reasoning-persisting templates (laguna, inkling) otherwise render nothink signatures from turn 2.
- **A template can raise_exception on OUR extra-context values** (Inkling, Qwen3.8): `serializeExtraContext` sniffs the family; tool-call `arguments` stay OBJECTS; history tool_calls carry `"id"`; hermetic render test pins it. Qwen3.8 is a THIRD effort vocabulary (`xhigh|medium|low`, default xhigh, sniffed on the literal `'xhigh'`, which EVERY 3.8 template raises OpenAI's "high" against); its fallback is ChatML too, so the downgrade shows only as a missing tools preamble. Whether the template REFUSES thinking-off is a SEPARATE question that splits INSIDE the family — 2.4T-A95B raises, the 27B answers that arm the 3.6 way (closed `<think>`, no reasoning preamble) — so the `enable_thinking:false` withholding is sniffed on the refusal string, never on the effort literal, and only a refusing template gets the block closed by `noThinkTailSuffix`.
- **A transcribed chat template is worth what it is PINNED against, and whitespace is a token-level contract** (`tests/dsv4_template_ab.py`, byte equality over the shapes the server emits; convert INPUT shapes to each side's contract).
- **Inkling channel markers are single special tokens, but marker filtering alone does not cover tool turns**: `streamShouldBufferForTools` buffers on the invoke marker and HOLDS bare-identifier segments after boundary markers.
- **A muse channel HEADER is ordinary text between single-token markers** (`<|start|>assistant to=<r><|message|>`): every streaming surface HOLDS an unresolved header — including sub-`to=` prefixes (a bare " to" delta leaked live 2026-08-10) — and drops header tokens between `<|start|>` and `<|message|>` (`museHeaderSkipNext`); routing is `to=self`→reasoning, `to=user`/bare→content, anything else→ATEM tool payload (`splitMuseChannels`/`museStreamVerdict`/`museThinkOpenerAt`). ATEM values: strings RAW (never trimmed), spelled JSON keeps its type, truncation ships NAME + completed params only.
- **An error echo teaches the model the error** (Inkling name salvage): NAME = trailing identifier run; body = BALANCED JSON, never scan-to-end-tag; a parsed NAME must never contain `<|` (corpus invariant); bare-JSON inference never runs on invoke-marker text; `applyFamilySamplingDefaults` fills top_p 0.95 when a checkpoint ships no generation_config.
- **Thinking-off is enforced in the PROMPT; generated reasoning is ALWAYS delivered, never discarded** (`chat.noThinkTailSuffix`: muse commits `to=user<|message|>` when tools are absent, an unconditional `<think>` opener — LFM2.5 — gets `</think>` appended; muse's silent default = thinking ON with tools / OFF without, `defaultEnableThinking(has_tools)`, and `/v1/messages` consults it when `thinking` is absent). Every delivery site splits via `splitThinkBlock(text, true, …)` — there is no strip-and-discard path (discarded tokens still cost the full reasoning latency; the old path generated a whole hidden `to=self` pass and threw it away).
- **Muse renders round-tripped reasoning as `to=self` HISTORY, so PRIOR-turn reasoning is dropped from the prompt** (`chat.dropPriorTurnReasoning`, harmony convention, same `reasoning_strength` sniff): only assistant messages AFTER the last user message keep `reasoning_content` (current-turn tool rounds) — one loop-cut chain otherwise replays in the prompt on every later turn (live 2026-08-10 capture; the echo, not the loop, is what made it permanent). laguna/inkling untouched — the round-trip rule stays per-family.

### Server, HTTP, lifecycle (→ docs/gotchas/server-http.md)

- **Logprobs are the MODEL's distribution, ids travel WITH values, and the entry belongs to the RETURNED token**: pre-temperature logits; ids via argpartition+gather (`mlx_topk` is NOT descending); one-token delay (`Generator.pending_logprob`). Bar: temp-0 rank 1 == chosen token. Scan: `last_logprob` only assigned from `pending_logprob`. A broken instrument is worse than none.
- **Streaming logprobs ship on BOTH surfaces**: `logprobs` is a SIBLING of `delta`/`text` (`ChunkExtras`, null never absent); ONE collector `StreamLogprobs`; entries drain against a HIGH-WATER MARK, ship EXACTLY once; `text_offset` runs whole-completion; token+entry publish in ONE critical section (`Slot.pushTokenWithLogprob`). Guards: `tests/test_logprobs.sh` [4][5] + emitter scan. Honest gaps: `logit_bias` unparsed, `/v1/responses` no logprobs.
- **`logprobs.content` describes `message.content`** — slice by `contentTokenRange` (unlocatable content keeps FULL range); streaming is structural (reasoning emitters never drain; content chunks `skipToContent` first; the empty-content arm is `dropPending` at all four sites). Guard: [6] + two-sided emitter scan.
- **A logprobs token string is a BPE FRAGMENT, not necessarily valid UTF-8**: `jsonEscapeLossy` (U+FFFD, maximal subpart) at the four token-string sites, `bytes` keeps exact bytes; do NOT widen to `jsonEscape`/`appendJsonString`. Guard: [7].
- **`/v1/completions` logprobs is an INTEGER and a different shape** (four parallel arrays, text-keyed map that can collide — OpenAI's own shape); measure over the CHAT surface.
- **Liveness is a property of the SOCKET**: `beatStreamKeepalive` at the bottom of every streaming loop; emit on 5 s byte-silence. `StreamHeartbeat` (client, bytes) mirrors `StallClock` (server, tokens). GAP: Ollama sink drops SSE comments.
- **A load failure crosses the inference-thread boundary by NAME** (`req.error_name` → `ModelRegistry.loadErrorFromName`, also on both `.error_state` arms): memory-preflight refusals surface as `error.InsufficientMemory` → their own named 503 + entry reset to `.unloaded` (the 503 says "retry" — sticky error_state made that a lie); everything else ships `Model load failed: <stored name>` (#144).
- **Thread lifecycle**: detach every spawned per-connection `std.Thread` immediately (dropping a joinable handle retains stack mappings per request); on teardown drain conn threads (`active_conn_threads` + `cancelAllInFlight`) BEFORE `scheduler.deinit`.
- **Serial ≠ exclusive**: module-owned decode state needs admission-level single-flight — `scheduler.admitPendingTick` keyed on `modelExclusiveDecode` (NEVER `!modelBatchable`); held slots stay in `pending` so keepalives flow.
- **`--model-dir` is REPEATABLE**: `discoverModelsMany` merges N roots FIRST-WINS (un-deduped merge fails registry init); app `ModelRoots` is the ONE answer to downloads + scan; DevID-gated (MAS helper can't inherit scoped grants). Second bite (2026-08-08): `modelsDir` alone hid the pre-move library from the app while the server kept serving it. Third bite (2026-08-09): `ownedRoots` (destination + built-in) skipped the LM Studio + custom scan folders, so a pack there got a Download bar over a copy already being served — app-side READS (picker, `existingModelDir`, `resolveModelDir`, `componentReady`, drafters) now go through `readRoots` = EVERY served folder (`ModelRoots.readRoots` ≡ scanRoots, first-wins); writes + cancel cleanup + DELETE scoping stay on `ownedRoots`/destination (other tools' trees), test-pinned roots stay alone. Guards: `tests/test_multi_model_dir.sh`, `ModelRootsTests`, `OwnedRootDiscoveryTests`.
- **A KV bill is per CACHING LAYER at the arch's OWN K and V widths** (`ModelConfig.kvBytesPerToken`, fed by `attnCacheLayerCount`): a hybrid's linear layers hold a fixed-size recurrent state, not a per-token cache, and MLA's key is wider than its value — the uniform `layers × 2 × kv_heads × head_dim` over-billed bailing_hybrid 3.2x and pinned auto-context to a third of what fits. The auto-context sizer and `prefillMemoryNeeded` read the ONE helper, source-scan-pinned at the call site (they must move together or a raised context gets its own prompts refused).
- **The STORED width and the SCORED width are two parameters** (`prefillMemoryNeeded(… hdim, score_hdim …)`): the score term's fused-or-materialized decision reads `prefillScoreHeadDim()`, the quantized-KV dequant transient the stored `head_dim`. Passing one value for both declared MLA's 192-wide composed scores "fused" and billed them at ZERO — under-billing ends in an uncatchable Metal OOM, not a 400. Both are pinned at the call site by the same source scan.
- **An MLP envelope is not a prefill working set — the arch's OWN streams are the missing term** (`prefillStreamBytesPerToken`, 5 checkpoints measured 2026-08-14): the per-chunk-token peak spans 9x per unit of ffn, so one stretched envelope was still 33% short on a GatedDeltaNet hybrid (7 of 16 measured cells under-billed, worst 0.58x). A linear-attention hybrid holds a chunk-wide q/k/v stream in EVERY linear layer (not the ~3 the eval cadence bounds); a MoE prefill replicates the hidden stream `top_k` times for the 4 layers its cadence coexists; plain attention has neither. `max(3 x mlp, mlp + fwd x stream)` — the max is a FLOOR so no arch's admission LOOSENS.
- **The chunk-independent part is a RUNTIME floor, not a weight set** (`PREFILL_RUNTIME_FLOOR_BYTES`, both consumers + the dsv4 sibling): a dense bf16 checkpoint pays it too, killing the dequantized-weights theory — `prefillDqGemm`'s copies are a kill-switch-MEASURED few hundred MB, chunk-independent, only at forwards ≥ its own min M. Retuning the guard costs the SIZER: 27B @ chunk 512 on a 16 GB profile reports ~18k tokens, not ~51k, because that is what it peaks at; `--prefill-chunk` buys it back.
- **The prefill CHUNK is a machine decision, and the pin cannot reach the forward through `xfm.config`** (`resolvePrefillChunk` + `ModelConfig.pinned_prefill_chunk`): the bill is dominated by `3 x 8 x chunk x max(hidden,ffn) x 2` and the chunk defaulted to 8192 everywhere, so a 16 GB Mac reserved the same 5-7 GB envelope a 128 GB one does — measured, Mistral-7B-4bit at chunk 8192 bills 9.18 GB for a 10,348-token prompt whose real peak is 2.39 (3.84x; the `3 x mlp` floor alone is 1.7x-10x over on plain attention). The ladder 8192->512 takes the widest rung whose `prefillTransientReserve` is <= a QUARTER of what is left after weights + hot-cache budget, frozen by `pinPrefillChunk` ABOVE the `--ctx-size` early-out; `--prefill-chunk` still wins. `Transformer` holds a COPY of the config made at build time, so the pin rides `InitOptions.pinned_prefill_chunk` from `slot.model.config` — the same object the guard bills (live: pinned 4096, prefilled 8192). A VISION prefill chunks like text since #197 (`ForwardCtx.vision_splice_offset` resumes the row scatter across chunks; `MLX_SERVE_VISION_CHUNKED=0` restores whole-prompt), so `checkAttentionMemory` bills the chunk — `unchunked_prefill` bills `seq` only on the kill-switch arm, and both sides read `generate.visionPrefillUnchunked` so they cannot disagree.
- **A `layer_block_types` hybrid was billed a KV cache for every layer** (`attnCacheLayerCount`): `isLinearLayer` keys only on `full_attention_interval`, which lfm2/lfm2_vl (`layer_types`) and nemotron_h (`hybrid_override_pattern`) never set — lfm2 caches 8 of 30 and paid 3.75x, Nemotron-H worse. Only `.attention` blocks reach `ctx.cache`; conv/mamba2 hold a fixed-size state in `ssm_entries`. Layers past the 128-entry table keep the `.attention` default (the over-bill direction).
- **A gate that runs BEFORE the estimator that knows better is the estimator** (#126): eviction gate + preflight + COMMIT all read ONE estimator (`gen.estimatePeakResidentBytes` → `gateEstimateBytes`); refusals log estimate/cap/resident and name `--max-resident-mem`.
- **A refusal quotes the number it COMPARED, and keeps its own error out to the client** (live 2026-08-08): "peaks at ~4.3 GB but only 5.4 GB is free" reads as "this should have worked" — it was refused for the ~1.5 GB warmup headroom the sentence never named, so `scheduler.loadRequirementBytes` is the ONE number the comparison uses AND the message states (context-overflow-400 class). `ensureLoaded` FREED `req.error_name` and collapsed everything to `LoadFailed`, so `ModelRegistry.loadErrorFromName` keeps BOTH spellings (InsufficientMemory/OutOfMemory) as a memory error — 503 with a message that must fit BOTH gates, cap and preflight, since the client can't tell them apart; everything else stays honestly generic. (It was `scheduler.loadErrorFor`; the refactor that replaced it kept the first name and dropped the second, so an allocator OOM went back to a generic 500 — a merge is where a two-case function quietly becomes a one-case one.) App twin: a gen pane's "Show log" showed the SERVICE log, empty for a model that failed to LOAD — all four panes fall back to the server log tail. - **A staged bill is per-STAGE**: transient allowance belongs to the stage that allocates it; a stage's weights are what it KEEPS (`h3DitResidentBytes` reads the SAME predicate generate branches on); `gateEstimateBytes` adds no 10% to media peaks (reserve == commit).

- **A long job's abort must not depend on the RESPONSE SHAPE** (`gen_sse.StreamCtx.stream`): the probe is `Conn.peerClosed` (write failure is seconds late); `stream:false` no-ops the event cb; cancel arms report `error.Cancelled`, never "generation failed".
- **Non-text model on a text surface must 400 BEFORE prefill** (`textGenRejectReason`, TWICE: arch_hint peek + post-load). New surface → `isTextGenRoute`; new modality → `modalityFromType`.
- **An arg loop with no else branch is a silent flag eater** (`cli.classifyUnparsedArg` rejects unconsumed args). Flag cross-check: every `--flag` any script or `ServerOptions.toCLIArgs` passes must appear in main.zig's match list.
- **A serve path that hand-rolls its ServerConfig eats CLI flags**: related settings travel as ONE value (`server.PldDefaults`). Guard: `tests/test_headless_spec_flags.sh`.
- **A client-supplied PATH is proven on OUR side of the mlx boundary** (`lora.loadFile` stat → 400; an MLX error KILLS the process).
- **Hand-written error text is not JSON**: escape at the SINK (`gen_sse.jsonEscapeMessage`), truncate on a UTF-8 boundary rather than send no body.
- **Endpoint EXISTENCE must not depend on model state**: `!routeExists(path)` → 404 even with no default model; `ROUTE_PATHS` pinned against the dispatch chain by source scan.
- **A 404 must cost NOTHING, and "endpoint existence does not depend on model state" is an ORDERING claim** (live 2026-08-11): the existence check sat inside `ensureLoaded`'s `NoDefaultModel` arm, so it only answered when there was no model to load — with a resolvable `model` in the body, resolution SUCCEEDED first and the unknown path 404'd afterwards. `POST /v1/load` (the route is `/v1/load-model`) cost 2m42s and 121 GB resident for a typo, and the same one-liner pins the box from any client. Measured M4 Max, Qwen3.8-27B 6-bit, MTP on: **1.10x-1.22x** — but forcing EVERY shape on measures 1.03-1.05x, because the 1024-wide K/V projections lose, exactly as `mixedNaxShapeEnabled` encodes. 8-bit (1.01-1.04x) and unmeasured 5-bit stay default OFF. Hoisting the POINTER is not hoisting the LOAD — the widened arms hoist the WORDS at the widest load each alignment allows (8-bit two uints, 6-bit three ushorts, 5-bit bytes). MLX names its JIT `custom_kernel_<name>_<template_hash>_<dtypes>`, so `BITS` needs NO kernel-cache-key change (same reason GS 32/64/128 already share one handle).

The bars are fp32-dequant-reference parity per width, and bit-identity of 4-bit ACROSS a refactor. In a paired sweep, reverse the CELL order per pass too: the first cell reads ~2% fast, which read as the whole win before it was controlled.

Codegen NAMED SCALARS with literal indices (array-indexed stack-spills 10×); M=8 is the plain-SIMD register cliff; auto MTP depth 8 needs the full fingerprint.
- **The EV cost tables are refit whenever the verify forward changes** (`MTP_EV_DEFAULT_COSTS` doc comment carries the method + numbers; refit #4 post-sdpa-split: flat_max 4, hi 0.26, k≥7 cliff 0.62 via the generic third region, +2.9% echo): saturated forced-depth traces with `MLX_SERVE_MTP_ADAPTIVE=0` + `--prefix-cache-entries 0`, m_avg==N windows only. - **When an A/B's arms fork CONTENT, per-prompt spec cells are variance**: sample across prompts before believing a regression, and at temperature take 3+ REPS (one boot read a 13% dflash temperature penalty that a second boot of the same build showed does not exist; sampled drafts with the full Leviathan ratio are exact and measured a LOSS — `p(argmax q)` beats `1 − TV(p,q)` when the sidecar's argmax tracks the trunk but its distribution shape does not). A per-arm PROMPT NONCE forks it by construction — the nonce defeats the prefix cache but must be identical across arms (a chatty model echoes it, so one differing byte re-rolls the whole generation and the acceptance columns stop being comparable too). Vary it by REP, never by arm; boots start with an empty prefix cache anyway.
- **dsv4 comp_in int8 requant is EXPLICIT-opt-in** (`decodeAttnQuantExplicit`) — its characterization moved an answer; a shared lossy flag's default is not transferable between archs.
- **MoE decode `gather_qmm` costs O(EXPERT-BANK SIZE), not O(work)** — superseded: stock gather is the default on EVERY arch since the mscale fix; env levers remain for A/Bs.
- **A kernel's dtype and its threadgroup BLOCK SIZE are ONE decision** (`gdnBlockTFor`; read dtypes off the ARRAY; store type is the OUTPUT's — Metal has no implicit float→bfloat).
- **Every KV buffer is sized from the OPERAND it stores, and a scheme with a shape constraint refuses at LOAD**: K and V widths differ on MLA (192/128), so dense AND affine grow/write/view/truncate each read their own array (a K-derived packed width wrote a 16-u32 chunk into a 24-u32 window — an uncatchable mlx slice_update mismatch, and nothing gated the SCHEME because the "MLA never opts in" note covered only the fused READ kernels). TurboQuant's Hadamard needs a power of two, so `initWithConfigAndHeadDim` checks `ModelConfig.kvCacheKeyHeadDim()` (the CACHED key width, not `head_dim`) instead of failing at the first MLA layer mid-request.
- **A fallible re-init BEHIND a `deinit` leaves a freed object installed on the error path** — build first, then swap (`KVCache.reinit`). Four sites read `cache.deinit(); cache = try init(…)`, so the moment `initWithConfigAndHeadDim` became fallible, `--kv-quant turbo2|turbo4` on an MLA arch printed its own named refusal and then died double-freeing every handle in `Transformer.deinit` — an EXC_BAD_ACCESS frames away from the refusal that caused it. Scan-pinned: no `.cache = try` in transformer/scheduler/main, and the helper's build must precede its free.
- **An MLA cache is billed per ATTENTION head** (`kvBytesPerToken`): the latent is decompressed to all of them before the write, so `num_key_value_heads` is a GQA question this arch never asks — equal on Ling 3.0 (16/16), so only an asymmetric config tells the spellings apart, and the wrong one UNDER-bills.
- **A gate's LOWER BOUND may REPLACE the formula, not clamp it** (KDA: `g = exp(bound·σ(exp(A_log)·(a+dt_bias)))`, bounded in (exp(bound),1) — reading `kda_lower_bound` as a clamp on `-exp(A_log)·softplus(·)` is a plausible, silently wrong recurrence). Read the reference KERNEL's arms, not the config key's name. Two arms means the arm is SELECTED (`ModelConfig.kdaUsesBoundedGate`): an absent bound is the softplus arm (elementwise, so it serves a per-channel gate unchanged), never bound 0 fed to the bounded chain — that is `exp(0)` = a gate that never forgets, on a checkpoint whose only sin was omitting a key.
- **Per-head vs per-channel gating is an INDEXING contract**: one recurrence, generated for both (`gdnKernelSource(vectorized, capture_seq)`); kernels that read the other shape DECLINE (the blocked prefill kernel); the equivalence test is a per-channel gate held UNIFORM across a head, which must match the scalar kernel EXACTLY (a wrong stride survives every "finite and decaying" check).
- **A struct declared inside a generic fn that captures NO comptime param is memoized to ONE type** — a per-variant kernel cache then hands the first compiled kernel to every variant. Capture the params (`const is_vectorized = vectorized;`).
- **A custom kernel's signature comes from each input's ACTUAL dtype; <8-element arrays land in `constant`**: index raw buffer names; every new kernel ships a one-shot "engaged" log + parity on the LIVE dtype.
- **A helper that materializes a VIEW owns the view** (slice-and-contig leaks pin the PARENT): route through ONE owning helper per file (`sliceContig`). RSS is blind to Metal — measure `/props` `active_bytes` + vmmap.
- **A weights MAP outliving the model pins every buffer the model frees**: scope it inside a block ending at `Model.load`; staged loaders log residency.
- **mlx-c iterator refs**: `iterator_next` hands a +1 you transfer or free — dropping it makes immortal buffers.
- **Allocator-cache growth**: loops freeing never-repeating sizes grow phys unbounded — `mlx_clear_cache()` once per CHUNK and per emitted block; repro must VARY the size-driving shape.
- **The pool is unbounded, so the clear must be un-skippable** (#110): `server.applyMlxCacheLimit` ONCE at top of `main()`; cadence is INTERVAL-based (`step -| last_clear >= 256`, never `%` — spec strides walk over multiples); `Generator.advanceStep` is the one place step moves (scan-pinned); `finishSlot` clears the tail.
- **KV growth is PROPORTIONAL** (`nextCapacity` +25%, floored one chunk, capped 8192) — fixed +256 stranded ~5.6 GB per 256 tokens at long ctx; truncate/snapshot/restore stay capacity-agnostic.
- **`active` flat while phys climbs = the POOL, and it must be nameable from outside**: `/props` `memory.cache_bytes`, `mlx_serve:mlx_cache_bytes`, the tray's `(+N GB cache)`.
- **Special-token splitting**: only `Tokenizer.encode` (first-byte buckets) — a per-special rescan is O(specials×text) and this class shipped TWICE. Any per-position loop over a vocab-derived collection needs an index.
- **mlx `Copy`/`contiguous` are VIEW ops**: a slice OUTLIVING its parent goes through `materializedOwnedCopy` + eval. `mlx_save_safetensors` silently appends ".safetensors".
- **A raw data-pointer read must PROVE row-major contiguity** (post-eval strides; materialize via FLAT RESHAPE — add-scalar-zero propagates broadcast strides).
- **mlx-c upgrades**: diff `lib/mlxc-src/mlx/c/*.h` vs `src/mlx.zig` externs; the pin must be a brew-proven pair. ds4 bumps: re-sync `ds4_ffi.zig` EngineOptions (layout test) + mirror upstream CORE_OBJS in build.zig.
- **NAX presence is asserted, never assumed**: `build-mlx.sh` + `tests/test_mlx_staged_nax.sh` grep the metallib for `*_nax` (the CMake gate fails silently).
- **`mlx_array_new_data` COPIES shape-worth of bytes**: a smaller buffer is latent UB that passes until stack layout shifts.
- **A model whose per-request state lives OUTSIDE the KVCache is excluded from prefix-cache/snapshot reuse AND owed a `Transformer.deinit` arm** (dsv4 leaked 108 GB on unload until it got one).
- **`openDirAbsolute` on an empty/non-absolute path is ReleaseFast UB that miscompiles the CALLER**: guard every call site; when Debug and ReleaseFast disagree on control flow, suspect unreachable-class UB and bisect in Debug.

The symptom is ONE `[dtype-trace] residual widened` line, never a wrong number.
- **Calibrated quantization**: channel weights are PER-INPUT-CHANNEL and PER-EXPERT (imatrix value IS the weight, no sqrt); bit width beats group granularity at ≤3 bits; round (s,b) to the STORED dtype before deriving q; self-test against a weight-BLIND arm; the corpus shapes what survives — quality gates must not hang on knife-edge cells.

- **A hand-rolled pretokenizer is calibrated to ONE tokenizer.json — digit GROUPING is per-model** (`Tokenizer.digit_group` from the Split rule): mis-grouping presents as a MODEL-QUALITY bug; config-invariant quality ⇒ suspect the PROMPT; cross-check `/tokenize` vs HF tokenizers at bring-up.

Mirror `ddalcu/LTX-2.5-MLX-Serve-8bit` (~59 GB); recipe = `scripts/quantize_ltx25.py --bits 8` (passthrough components are byte-identical to the 4-bit pack's, so they are copied, never re-downloaded).
- **A module's constructor arguments are not its config, and a pack that ships no config makes the class DEFAULTS a guess** (LTX-2.5 DiffVAE, 2026-08-13): the reference decoder reads `model_output_type` / `default_num_inference_steps` / `timestep_scale_multiplier` from a `vae` section, no LTX pack ships one, and its defaults (v-prediction, 2 steps, x1) run the shipped weights into pure STATIC — the prediction is small against the noise it is subtracted from. Measured, the file is what Lightricks call it: a 1-step x0 decoder at timesteps x1000. Every wrong arm is a decode you cannot mistake for a bad model (adjacent-pixel gradient 17.7 / 29.5 / 44.8 against 2.2-2.8 for a real render, `tests/lora_noise.py`'s metric), so `ltx_diffvae_forward.Sampler` pins all three behind kill switches and both the unit test and `tests/test_video_gen.sh` assert them. Faithful-port parity CANNOT see this: our decode matched the transcribed reference at cos 0.99998 while producing static, because the transcription inherited the same guess.
- **The DiffVAE's tile budget is a per-REQUEST memory decision, not a load-gate term**: the diffusion stage carries context + x + q/k/v at 256 wide over the whole tile (measured 10 KiB per stage-5 token; 20.7 GiB peak / 21.2 s decode for an untiled 768x512x97, inside end-to-end variance against the conv decoder), so `tileTokensForMemory` sizes it from free RAM at decode time. Billing it into the per-model gate would refuse packs that only ever use the conv decoder. Stages 1-3 run on the FULL volume; only stage 4 and the diffusion stage tile, seams blended by trapezoid ramps that sum to exactly 1.

The frame ladder is per-canvas (`frameOptions(width:height:)`): the whole clip rides back as ONE base64 blob, so 193 frames at 1920×1088 is 1.2 GB raw and 1.6 GB encoded, held on both sides — lifting `maxFramePayloadBytes` is a TRANSPORT change, not a number to raise.
- **A media pack's RELEASE is a config field, and the text encoder is what it decides** (LTX 2.5, 2026-08-12): 2.5's DiT is 2.3's key template minus the 96 video-FF biases plus one `keyframes_abs_pos_embedding`, its connector/VAEs/vocoder/upscalers re-ship byte-identical, and its config.json differs in FOUR fields — so `ltx_video.LtxVersion` (from `model_version`, absent ⇒ 2.3) is the whole discriminator. - **The 2.5 text encoder is the `gemma4_unified` decoder we already serve, so it runs the REAL transformer** (`ltx_video.gemmaCapture4` via `ForwardCtx.capture_layers` + `skip_lm_head`): dual head dims on full-attention layers (512 vs 256), one global KV head, K aliased to V there, partial proportional RoPE, per-layer `layer_scalar` — re-deriving that in the media file would be a second copy of an arch with no oracle to check it against. Its prompts are LEFT-PADDED, which the standard forward has no notion of, so the mask rides in on `ForwardCtx.prefill_mask_add`: an additive term that must ALREADY be causal (a "causal"-mode layer swaps to an array mask carrying it verbatim) and must be FINITE -1e9, never -inf — a pad query row sees nothing but pads, and an all -inf row softmaxes to NaN. Non-null also DECLINES both fused prefill kernels, which mask from geometry and cannot carry an extra term. Null on every serving path.
- **`keyframes_abs_pos_embedding` marks "tokens whose latent encodes a single standalone pixel frame"**, added to the projected hidden immediately after `patchify_proj` as `h + mask * embedding`. Our `cond_mask == 0` set IS that mask today (one first frame, VAE-encoded alone); a conditioning shape whose clean tokens come from a multi-frame CLIP would need its own — those are not standalone frames. Zero-initialized upstream, so an untrained checkpoint is an exact no-op, and t2v never applies it.
- **A bytes-read table prices a lever only for a path already AT its read floor** (music3 depth KV cache: estimated 1–3 ms from weight reads, measured −11.6 — the naive re-forward sat 2× its floor on recompute + per-forward graph-build; the lm stage, genuinely at floor, moved 0). Per-stage probe laps (`MUSIC3_COST_PROBE` pattern) before bandwidth arithmetic.
- **Music3 is NOT an ACE-Step variant — pattern-matching acestep.zig ships silent wrongness**: the DiT's timestep is a prepended TOKEN (plain LayerNorms, no AdaLN), SwiGLU is REVERSED (`first * silu(second)`), Snake is alpha-only with NO exp, DiT RoPE is dims-32 theta-10000 (hardcoded upstream, not in config), and the AR loop's frame 0 is never emitted while its codes still feed back. Full trap list: the music3 story below.
- **When an arch's reference deliberately IGNORES a config field, that field is not the source of truth** (laguna YaRN mscale is COMPUTED; XS ships `attention_factor: 1.0`).
- **A config field HF allows in two SHAPES must be read as both** (`chat_template` string OR list of `{name,template}` — pick `"default"` > first > null-to-fallback); `.string` on an unchecked `std.json.Value` is a process-killing panic.
- **Read `text_config` FIRST, then root, PER FIELD** (both readers); fields a minimal `text_config` omits need explicit per-arch defaults.
- **`x-mlx-pixels` is a GEMMA format, and the client gate for it is an allowlist of ONE** (live crash 2026-08-11): the app preprocesses images into Gemma's square CHW buffer unless it recognises the arch, and that gate was `hasPrefix("qwen")` — so muse vision shipped and the next image killed the server, because a gridless buffer routes to the SigLIP `forward` whose weights are null sentinels on a patch-grid encoder. `MultimodalContent.wantsServerPreprocess` now names the one family the format belongs to (`!hasPrefix("gemma")`), so a NEW vision arch defaults to server-side preprocessing instead of to the crash. Server side is the load-bearing half: `parseImageUrlContent` refuses the payload when `vp.mode != .gemma` (the source image is unrecoverable from it), and `VisionEncoder.forward`/`forwardPatches` return named errors instead of dereferencing sentinels — a client can send anything.
- **A chunked vision splice resumes its ROW INDEX, and byte-equality across chunk widths is not its bar** (issue #197): the splice's row lookup is a cumsum over the CURRENT forward's placeholder mask, so each chunk passes the rows earlier chunks consumed (`vision_splice_offset`) or every chunk re-splices from row 0 — coherent output, wrong image content (bottom quadrants vanish). `nextChunkEnd`'s TAIL_MERGE_MAX (512) means a "boundary inside the image" repro needs prompt > chunk+512 or it silently runs one chunk. The A/B bar is the PERCEIVED-content invariant (both arms name the same color set), never byte equality — chunk width changes GEMM shapes and 4-bit near-ties flip across widths (same class as MTP verify). Guard: `tests/test_vision_chunked_prefill.sh` + the `spliceVisionRows` chunk-equivalence test.
- **A forward ARM that never splices vision is invisible from the outside** (LFM2-VL, live 2026-08-13): `forwardWith` fans out per arch family and the splice lives in each arm — the HYBRID arm (lfm2, nemotron_h, qwen3_next) never had one, so the tower loaded, the image encoded, the token accounting logged correctly and the model answered "a completely black rectangle" from 247 identical `<image>` placeholder embeddings. Nothing errors, so it reads as a bad IMAGE. Class guard: the source scan `every generative forward arm splices vision embeddings` — encoder-only arms are exempt BY NAME so a new arch defaults to being required.
- **A resampled position table is `bilinear` WITH antialias, and the widened footprint is the whole point** (SigLIP2-NaFlex): transformers resamples the learned 16x16 table onto each image's patch grid with `interpolate(mode="bilinear", antialias=True)`, so a grid axis SHORTER than 16 (an extreme aspect under the token budget) is a real downscale. mlx-vlm 0.6.3 uses bicubic there and lands at cos 0.99 / **rms 1.13x** — a scale error, not a rounding one, so it is not a usable oracle. Ours is `qwen_vision.resampleWeightMatrix(.bilinear)` (Pillow's convention, matmul'd on both axes); measured cos 0.999999 on every grid.
- **A patch feature order is per-ARCH and a cosine test on flat colour cannot see it**: LFM2-VL's `convert_image_to_patches` emits `[py, px, c]` with CHANNEL INNERMOST, where Qwen and Muse both put channel outermost. Same shapes, same token count, scrambled image.
- **Two GELUs in one checkpoint**: LFM2-VL's encoder MLP is `gelu_pytorch_tanh` and its projector is plain erf `gelu`. Read `hidden_act` and `projector_hidden_act` separately — one act for both runs and still produces plausible output.
- **For a NaFlex model, TILING is the resolution** (LFM2-VL): a source past `max_image_tokens x max_pixels_tolerance` is resized onto a `cols x rows` canvas of 512px tiles, cut up, and encoded tile by tile plus a thumbnail of the whole image — 1788 tokens against 252 for the single-tile view. Measured on 15px print at 1800x1400: tiled reads all three lines exactly, the untiled geometry reads none of them. The canvas is resampled ONCE and read as windows (`buildPixelValuesRegion`); re-resizing per tile is a different picture. The block is NOT a flat pad run — `lfm2ImageSegment` labels each tile `<|img_row_R_col_C|>` (one contiguous id block, row-major over the MAX grid) and the thumbnail `<|img_thumbnail|>`, and marker order must match the order the encoder concatenated the pieces because the splice is positional. Guards: `tests/test_lfm2_vision.sh`, `lfm2ImageSegment` unit tests, `LFM2_VISION_FIXTURE` parity.
- **Two towers on one surface means the PREPROCESSOR is part of the arch, not just the encoder** (muse vision): muse and Qwen both hand the ViT a `[N, feat]` patch grid, but muse resizes by aspect-closest grid under a MERGED-token cap (Lanczos), emits patches ROW-MAJOR with `[t, c, py, px]` features, and merges CHANNEL-major in `pixel_shuffle` — feeding Qwen's merge-block order in produces a running model that reads a scrambled image. `VisionPreproc.mode` picks all of it; `imageTokenCount` stays shared. Guards: `tests/dump_muse_vision_fixture.py` (executed reference on OUR dequantized weights: pos-embed + final features, cos + rms_ratio) + `tests/test_muse_vision.sh`.
- **A config default only ONE family wants is a per-arch trap — pin every value the forward reads PER LAYER TYPE** (muse first-turn repetition loops, 2026-08-11): sliding layers read `rope_local_base_freq` (Gemma-flavored default 10000) while muse ships ONE theta (500000, `rope_parameters.rope_theta`) and its globals are NoPE — every rotated layer mis-based; deterministic-at-greedy "coherent then loops" = positional-encoding signature. Muse sets `rope_local_base_freq = rope_theta`; guards: config-test assertion + `tests/test_muse_repetition.sh` (replays the real pi capture).
- **A module TREE is the converter's choice, not the arch's** (`lagunaRouterBase`, issue #169): poolside flattens laguna's router to `mlp.gate.weight`, mlx-community's oQ builds keep HF's nested `mlp.gate.proj.weight` (`e_score_correction_bias` is a gate-module buffer in both, so it never moves). Probe, flat name preferred so the reference build binds byte-identically — the `hy3ExpertContainer` pattern.
- **The WEIGHT PREFIX is a property of the checkpoint, not the config keys** (`model.resolveWeightPrefix` probes the loaded map; never re-points archs with their own prefix).
- **A layer-init path that DEMANDS `.scales` can't load a DENSE checkpoint of its own arch**: scales absence is PER-TENSOR (`getLayerScaleOpt` everywhere); every dense contracted weight owes `maybeTransposeForBf16` — never depthwise conv or SSM state. Source scan rejects the mandatory getter.
- **`*_text` siblings**: accept the tag, collapse to base type, prefix by `text_config` presence, force `tie_word_embeddings` for Gemma, add to BOTH visibility allowlists.
- **Multi-converter MoE containers resolve by probe** (`hy3ExpertContainer`), never one hardcoded name.
- **Gemma terminators merge ADDITIVELY** (`ensureGemmaTerminators`, idempotent) — never gated on "config provided no eos".
- **Quant modes resolve PER WEIGHT** (`computeQuantParams`; scales dtype decides fp8 vs affine; `.biases` mandatory under affine, OPTIONAL under non-affine).
- **A per-tensor quant override can live INSIDE the fp family where scales dtype can't see it** (`fpParamsFromGeometry`): solve (bits, gs) from packed geometry; each fp format DEFINES its block size; null when the solve agrees with the declaration or maps to nothing we serve.
- **Affine bits outside {2,3,4,5,6,8} are rejected at config PARSE** (`UnsupportedQuantBits` — warmup death is uncatchable); extend together with `affineParamsFromGeometry` on an mlx bump.
- **A GGUF folder is a SHELF of models**: one `LocalModel` per quant (`id#<file>`), per-quant delete/cancel, sidecar classifiers in sync in BOTH Swift and Zig.
- **DiffusionGemma parity = converged-canvas self-consistency**, never random-canvas logit compare; sliding prefill takes the `"causal"` fast path when `total_kv ≤ sw`. Trace: `MLX_SERVE_DIFFUSION_TRACE=1`.
- **Optional per-token modulation gates entirely on the mask** (`nv_pt==0` → the EXACT unchanged scalar path); pin with uniform-mask self-equivalence.
- **Parity fixtures for deep ViTs/DiTs: dump fp32 on CPU** (MPS fp16 quietly decorrelates); transformers ≥5.x zeroes custom-model rotary buffers — dump scripts assert them non-zero; an oracle that IMPROVES when you remove a transform had that transform silently disabled.
- **TTS**: `TimeDelayNetBlock` = conv + IMPLICIT ReLU; embedding lookups reshape to the TABLE's native width (`getShape`), never a config dim; voice clone = ECAPA embedding as one codec-prefix position, `ref_text` ignored.
