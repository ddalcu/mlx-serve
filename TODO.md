* DSV4 next perf lever (MEASURED, biggest remaining): move the compressor EMISSION onto the GPU. A host read inside the layer loop is a GPU barrier, and it is still **109 ms of the 124 ms DSpark verify** — all of it the 21 ratio-4 layers, which always close a window inside a C=6 block (the ratio-128 layers already defer). Mirror the pending ring as a GPU array, do the masked-softmax window combine there, then reuse the existing `gpuRms` / `gpuRopeTailRows` / `gpuFp8Sim` / `hada_g`+`gpuFp4Sim` pieces and update the ring with `slice_update`. Removes every remaining barrier and lets MLX pipeline the whole 43-layer forward: verify ~50-60 ms, round ~70 ms, ~15 ms/token (from 29). Also pays on batched prefill and on decode's remaining ~5.4 boundary syncs/token. Risks: rollback anchors (`DsparkAnchors`) would need GPU ring copies, and the emission must stay numerically compatible with the host path — the decode-vs-prefill equivalence test is the guard that will scream. Audit with `MLX_SERVE_DSPARK_PROFILE=1`; story in docs/gotchas/engine-mlx.md ("DSpark round-cost round").
