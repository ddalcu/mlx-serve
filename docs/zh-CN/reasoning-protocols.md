# 使用受限 JSON 进行推理

MLX 生成路径依次使用一台有界协议状态机和既有的 JSON 文法。格式差异体现在分隔符 / 头部描述上；HTTP 处理程序共用同一个输出路由器。选择依据是实际的聊天模板、渲染后的提示词尾部和分词器能力，绝不依据检查点名称。

| 格式 | 推理 | 最终入口 |
| --- | --- | --- |
| 裸 think 标签 | `<think>…</think>` | 与之匹配的闭合标签之后的 JSON |
| 带后缀的 think 标签 | `<think:S>…</think:S>` | 要求同样的后缀 |
| Gemma | `<|channel>thought…<channel|>` | 直接 JSON 或 `<|channel>\n` |
| Inkling | `<|content_thinking|>…<|end_message|>` | 带 `<|content_text|>` 的模型消息 |
| Harmony | 助手 `analysis` 频道，以 `<|end|>` 结束 | 助手 `final`/`commentary` 头部 |
| Muse | 助手 `to=self`，以 `<|eom|>` 结束 | 助手 `to=user` 或未指定收件人的消息 |

提示词打开的头部和生成出的头部都受支持，包括重复的频道推理片段。频道未解析完成时，掩码会放行受支持的推理与最终分支。一旦 JSON 开始，所有字节都属于 schema，即使字符串数据看起来像推理标记或工具标记。不受支持 / 动态的头部保留思考关闭时的回退行为；这是一组有界的安全协议拼写，而不是对任意头部或工具收件人的宽松解析器。

分词器候选索引和精确恢复编码在已加载的模型上按标记各缓存一次。普通推理 Token 不需要文法快照；只有跨入 JSON 的候选才会做试探性验证。无效的跨越 Token 会在采样前被掩码，包括那些同时携带闭合符、最终头部和 JSON 的 Token。受限协议失败绝不会停用文法。

`max_tokens` 把推理、结构头部和 JSON 一起计数。在推理期间耗尽它，可能产出空内容并给出长度结束原因。没有为答案预留的额度。早期的循环 / EOS 恢复需要足够的余量来完成剩余的全部状态转移，并至少留一个答案 Token。响应侧的有限推理预算保留既有的思考关闭时的回退行为。工具仍然绕过 schema 路径；受限生成仍然禁用投机。

验证：协议测试覆盖全部六种格式、候选拒绝、代表性状态转移的每一种两 Token 拆分、部分头部恢复、特殊 ID、直接作答、思考关闭入口、UTF-8 进位，以及被截断的载荷区间。HTTP 回归测试在 Chat Completions、Messages 和 Responses 上运行 Qwen，覆盖两种流式模式和思考启用 / 禁用（12 种组合）。其它格式目前只有确定性覆盖；在能够对性能或模型专属兼容性作出任何声明之前，它们仍需要针对已安装检查点的实时验证。
