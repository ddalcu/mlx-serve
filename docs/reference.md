The embedded Qwen4 PLE path accepts indexed safetensors with complete `ngram_embedding.shards.N.{weight,scales,biases}` triplets matching the config's shard count and table geometry. `ngram_embedding.weight_scale` may be absent (identity) or a finite positive BF16 scalar, which multiplies every gathered row (oMLX's oQ packs store the table unscaled, e.g. 1.99e-4); anything else is refused. The table is read through host memory; `--ple-gpu` logs that the embedded layout uses host row gather. The loader leaves other PLE weights in MLX and excludes only the validated table payload from the one resident-weight estimate used by eviction, preflight, and commit.

Norm storage is independent of table layout. For an unmarked embedded pack, the loader checks both `self_attn.indexer.{q_layernorm,k_layernorm}.weight` arrays already loaded in the weights map on every expected full-attention layer, before folding any norms. Each must be a finite BF16/F16/F32 1-D tensor of `indexer_head_dim`; all tensor means must agree near 0 (delta, within ±0.2) or near 1 (folded, within ±0.2). Missing, malformed, mixed, or ambiguous anchors are refused by name. If that happens, set `"qwen4_norm_convention":"delta"` or `"folded"` in that checkpoint's root `config.json` after verifying its norms; a server-wide `--config-overrides` value for this field is refused. The checkpoint-local marker takes priority regardless of table layout, and unmarked external-table packs keep their folded default. Only the ten Qwen4 norm suffixes in `qwen4NormNeedsFold` are folded for `delta`, once in the shared weights map before the Transformer and MTP head use them; the gated linear-attention norm stays unchanged. F16 delta norms receive the +1 before narrowing to BF16.

### GGUF auto-routing

A `.gguf` model path (or a directory containing one) bypasses the MLX safetensors path. The embedded engine is picked from the file's GGUF header metadata (`gguf_meta.preferredEngine`, issue #15): **antirez-style DeepSeek-V4-Flash → ds4**, **every other GGUF → llama.cpp** (the basename heuristic `model_discovery.isDs4GgufBasename` survives only as the Swift client's mirror, `DownloadManager.ggufModelType`). The Swift app surfaces any `.gguf` as a selectable base model and the server auto-routes — no engine selector. Both engines share the same HTTP/chat-template/tool/SSE machinery via per-request dispatch on `LoadedModel.{ds4,llama}_engine`.

GGUF dirs are also **discoverable + cold-loadable** (issue #59 — pulled GGUF repos ship NO config.json): discovery and `probeModelDir` classify a dir holding a non-mmproj `.gguf` as `model_type "gguf"` — GGUF presence WINS over a stray config.json, mirroring `--model` routing — with `bytes_on_disk` = the file `resolveGgufFile` will pick (alphabetically-smallest LLM quant), not the sum of every quant. On demand, `ensureLoaded` routes through the same engine arms as startup: `preloadCpuState` builds a stub CpuState (`buildGgufStubCpuState`; ctx from `LoadParams.ctx_size`, else llama 8192 / ds4 clamp) and sets `LoadRequest.{ds4,llama}_path`. The GGUF path helpers (`isGgufModelPath`/`resolveGgufFile`) live in `model_discovery.zig`, shared by main.zig and the scheduler. Guard: the headless section of `tests/test_llama_gguf.sh` (discover → cold-load → chat → unload → reload) + the GGUF discovery/probe/resolve tests in `model_discovery.zig`.

### MLX GGUF engine (`lib/mlx-serve-gguf`)

A separate repo (submodule at `lib/mlx-serve-gguf`, its own README + tests + `zig build bench`) that serves GGUF files AS IS on the regular MLX path, so they get the native forward (`qwen3_5`, `qwen3_5_moe`, `gemma4`), batching, prefix cache, PLD and scheduler instead of llama.cpp. It reaches MLX through one import, `mlx_host`, which `build.zig` (`addGgufModule`) points at mlx-serve's own root module (so `main.zig`/`tests.zig`/`ios_lib.zig` expose `pub const mlx`): same bindings, same error latch.

- **Routing**: `mlx_gguf.servablePath` (arch `qwen35` / `qwen35moe` / `gemma4`, tokenizer known, every tensor type + name known) is asked BEFORE `isGgufPath` in `main.zig` and `scheduler.preloadCpuState`; a yes falls through to the normal MLX load, a no keeps the ds4/llama routing below. OPT-IN: `mlx_gguf.enabled` is false until `--mlx-gguf` (app: Settings → Engines, `ServerOptions.mlxGguf`); `--engine ds4|llama` keeps it off (the A/B lever vs llama.cpp). Log line: `[gguf] engine: mlx`.
- **The file is the model dir**: `parseConfig`, `loadTokenizer`, `loadChatConfig` ask `mlx_gguf.sidecar` for the JSON a model dir would hold (rebuilt from GGUF metadata, in memory; `generation_config` carries `general.sampling.*`), `loadModelWeights` asks `mlx_gguf.loadWeights`, `scheduler.modelDiskBytes` asks `mlx_gguf.weightBytes`. Nothing is written to disk, nothing is requantized.
- **Weights**: a quantized tensor is a uint8 array `[rows, row_bytes]` of raw ggml blocks named like an mlx-community checkpoint, plus a `<name>.scales` SENTINEL: a bool array whose shape is `[ggml_type + 1]` (or `[type + 1, nk, r]` when the weight's input is in llama.cpp's tiled value-head order). `QuantMode.gguf` makes scales bind and biases optional. `kernels.infoOf(w, sc)` recognises it at the top of `Transformer.qmatmul`, `qmatmulBits`, `rawEmbedding`, `dequantTake` (Gemma 4 per-layer embedding gather) and `gatherExpertMm` (MoE: the bank is `[experts, rows, row_bytes]`, `kernels.gatherLinear` is the `mlx_gather_qmm` drop-in, and `useGatherQmvDecode` declines `.gguf` so the affine-only fused decode kernel stays out). Float tensors load as bf16 (A_log f32). `weights.warmKernels` runs every (type, shape) once at load so the first request doesn't pay the Metal compile.
- **qwen35 layout**: llama.cpp's converter tiles GatedDeltaNet value heads and stores `ssm_a = -exp(A_log)`. The loader moves rows/bytes back to HF grouped order (lossless, rows are whole blocks); only `out_proj` (input side, blocks straddle heads) keeps its bytes and gets its activations tiled inside `kernels.linear`.
- **Gemma 4**: a 1:1 rename of the GGUF tensors (no norm offset, no head reorder), `rope_freqs.weight` is skipped (derived from config), the 12B has no `attn_v` on full-attention layers (`attention_k_eq_v`). Comparing against `--engine llama` on a raw `/v1/completions` prompt needs an explicit `<bos>` on the MLX side (llama.cpp adds it itself, Gemma without BOS is garbage).
- **Kernels** (`src/metal/blocks.h`, one unit decoder per type feeding an emitter, no scratch arrays): matvec for ≤ 8 rows (decode, spec verify, decode batches; a simdgroup's 32 threads run in LOCKSTEP, so its 8 rows x units are striped as one run, and one instance decodes each weight once for up to 5 activation rows), the same kernel with a per-output expert index for MoE (prefill included, 2x behind llama.cpp there past ~75 tokens, needs a gathered tile kernel), a simdgroup-matrix tile mat-mat for ≤ 384 rows, dequantize + MLX GEMM beyond. Thread-local arrays of ~32 floats and non-constant loop bounds both spill GPU registers and cost 4-10x: measured, see the comments before changing them.
- Guards: the module's own `zig build test` (decoders vs ggml fixtures, GPU vs CPU reference), the `mlx_gguf.zig` tests here (`MLX_SERVE_GGUF_TEST_MODEL=<gguf>` for the real-file arm), `tests/test_mlx_gguf.sh` (`MLX_GGUF_MODELS="<gguf> ..."`, 13 assertions per model incl. PLD output == `--no-pld`).

Models with `vision_config` but no vision weights (e.g., text-only quantized Qwen 3.5) gracefully disable vision at init. Swift app flags unsupported archs via `supportedModelTypes` in `HFModels.swift`.

### DiffusionGemma (block diffusion)

`model_type: diffusion_gemma` (google/diffusiongemma-26B-A4B-it, June 2026) reuses the Gemma 4 26B-A4B MoE trunk verbatim — same `forwardMoeWith` gemma4 branch, sigma-MoE router, v_norm, K=V alias on full layers, proportional RoPE — but GENERATION is a canvas-denoising loop (`src/diffusion.zig`), not autoregressive decode. `config.isDiffusion()` (canvas_length > 0) gates everything; `config.isGemma4Layers()` collapses gemma4 + diffusion onto the shared binding/forward arms.

- **Encoder/decoder split over one trunk.** The *encoder* runs the trunk causally (normal prefill, fills the slot's KV cache) using its own per-layer scalars (`model.encoder.language_model.layers.N.layer_scalar` — the only untied encoder weights; `ForwardCtx.use_encoder_scalars`). The *decoder* (`forwardDiffusionDecoder`) re-forwards a 64–256-token canvas of noise tokens BIDIRECTIONALLY each denoising step: q/k/v computed for the canvas only, cache K/V concat-READ (never written), sliding layers sliced to the last `sliding_window − 1` cached positions, no mask at all. `ctx.skip_lm_head` skips the 262K-vocab projection on encoder passes.
- **The loop** (`diffusion.Runner.nextCanvas`, one canvas per scheduler tick): uniform-RANDOM canvas init (no mask token), ≤48 steps, linear temp schedule (t_max 0.8 → t_min 0.4 on countdown), entropy-bound acceptance (sort entropies asc, accept while `cumsum − cummax ≤ 0.1`, renoise the rest), self-conditioning via soft embeddings (`softmax(processed) @ dequantized_embed_table × √hidden` — table dequantized once per request, ~1.5 GB transient), early stop when argmax is stable across `stability_threshold` steps AND mean entropy < 0.005. COMMIT = the argmax canvas; committed tokens are causally re-encoded at the START of the next tick (so an EOS-terminated request never pays for it). User temp < 0.01 → greedy denoiser; ≥ → categorical (temp 1.0 ≡ HF reference). Measured: 256-token canvas in ~10 steps on prose (25.6 tokens/forward), ~30% faster than the mlx-vlm reference.
- **Dispatch**: third engine-style branch (`runPrefillDiffusion` / `runDiffusionDecodeTick`, `Slot.diffusion`) — tokens flow through normal slot machinery, so all four HTTP surfaces + block-wise streaming work unchanged. PLD/drafter/MTP/batching never apply (MoE already non-batchable; `modelBatchable` also gates `isDiffusion`). Hot prefix cache is intentionally NOT consulted (restored snapshots leave cache VIEWS stale; the decoder reads views via denseView before any update would rebuild them) — wire it later by refreshing views post-restore.
- **Weights**: prefix `model.decoder`; experts packed as `experts.gate_up_proj` [E, 2M, X] (gate rows first) → `splitPackedGateUp` slices + MATERIALIZES halves at load; self-conditioning module under `model.decoder.self_conditioning.*`; `model.encoder.vision_tower.*` dropped at load (tower not wired — `has_vision` forced false).
- **Template/EOS**: standard Gemma 4 `<|turn>`/`<|channel>thought` template; EOS set {1, 106, 50}. Raw `/v1/completions` (no chat template) degenerates — reference behaves identically; instruct-only checkpoint trait, not a bug.

### Laguna (poolside Laguna S 2.1)

`model_type: laguna` (poolside/Laguna-S-2.1-NVFP4-mlx, July 2026 — 117.6B total / 8.5B active MoE coder, 256K ctx, 67 GB nvfp4). From-reference port (no upstream mlx-lm support); reference is the self-contained `modeling_laguna.py` (Apache-2.0). Pure attention — no SSM/hybrid — so it rides `forwardMoeWith` (qwen3.5/hy_v3 arm) with the standard KV/prefix-cache/PLD infra unchanged. Weight prefix `model`; `norm_has_offset=false`, `scale_embeddings=false`, `has_pre_ff_norm=false` (qwen/hy3-style RMSNorm + residuals); untied lm_head.

- **Per-layer Q-head count** (`num_attention_heads_per_layer`, `config.layerNumHeads`): 48 heads on full-attention layers, 72 on sliding — KV heads UNIFORM at 8 (cache machinery untouched). `lagunaAttnWith` carries the per-layer count; batched decode never applies (MoE → `modelBatchable` false).
- **Layer mix**: `layer_types` 1:3 full:sliding (`isGlobalLayer` = full_attention). Sliding window 512, reusing the Gemma sliding-mask machinery (`createSlidingWindowMask`/`createSlidingWindowDecodeMask`; full untrimmed KV during prefill, decode trims to the window). head_dim 128 → no fused hd-256 kernel.
- **QK norm**: per-head RMSNorm over head_dim before RoPE (qwen3 pattern).
- **Attention output gate** (`config.laguna_attn_gate`): `self_attn.g_proj` [n_heads, hidden] → `softplus` in fp32 (`logaddexp(0, x)`, numerically stable) → cast to bf16 → per-head scalar × attn output (reshaped [.., H, D]) BEFORE `o_proj`. Gate input is the same normed hidden states as q_proj. Distinct from qwen3-next's sigmoid/doubled-q_proj gate — separate weight, softplus, per-head broadcast.
- **RoPE** (per layer type, `attn_scale = head_dim^-0.5`): full-attention layers use **YaRN** (theta 5e5, factor 32, orig_max 8192, beta_fast 32, beta_slow 1, partial_rotary_factor 0.5 → rotary_dim 64). `computeYarnFreqs` precomputes the HF `_compute_yarn_parameters` denominator array (mlx_fast_rope's `freqs`; angle = pos/freqs); `attention_factor` (1.3466) is applied as an mscale VECTOR ([head_dim] = af on the rotated dims, 1.0 on the pass tail) multiplying post-rope q AND k — exactly the reference's `cos/sin *= attention_factor` on the rotated slice only, NOT folded into the sdpa scale. Sliding layers use default RoPE (theta 1e4, full rotary). Both precomputed on `Transformer` (`rope_freqs_yarn`, `yarn_mscale`).
- **MoE routing**: qwen3_moe WEIGHT NAMING (`mlp.gate` router bf16, `mlp.switch_mlp.*` nvfp4 experts, `mlp.shared_expert.*` bf16 shared) with hy_v3 ROUTING SEMANTICS — DeepSeek-V3 sigmoid scores in fp32, `+ mlp.gate.e_score_correction_bias` for top-10 SELECTION only, weights = the UNBIASED gathered scores, L1-renorm (`norm_topk_prob`), × `moe_routed_scaling_factor` (2.5). Reuses `hy3RoutingChain`/`computeHy3Routing` (compiled via `moe_sigmoid_router`). The route-scale multiplies the routed sum only; the shared expert is ALWAYS added, NO gate (`shared_ungated`) — matches the reference's post-expert scale (linear, never touches the shared branch). nvfp4 experts carry u8 fp8 scales, no biases (bias-less mode). `moe_router_logit_softcapping` is 0 on the shipped checkpoint and >0 is rejected at config parse (untested).
- **Converter naming**: the router base is PROBED (`lagunaRouterBase`) — poolside's NVFP4-mlx build flattens it to `mlp.gate.*`, mlx-community's oQ builds (`Laguna-S-2.1-oQ4e-fast`, `-oQ5e`) keep HF's nested `mlp.gate.proj.*`; the flat name wins when both could match. Those packs are all-affine mixed-bit (4/5/6/8, gs 64/128) solved per weight from geometry, use the `language_model.` weight prefix, and declare a 1M-ctx YaRN (`factor: 128`) where poolside declares 256K/32 — honoured as declared. Their `tokenizer_config.json` points at the sidecar template with an `{% include %}` stub (see the tool-calling gotcha).
- **Dense MLP** on `mlp_only_layers` (layer 0): resolved by a per-layer `mlp.switch_mlp.gate_proj.weight` PRESENCE probe at load (converter-proof — no `first_k_dense_replace` config dependency).
- **Chat/tools**: `chat_template.jinja` PRE-OPENS `<think>` at the generation prompt (thinking default on; emits bare `</think>` when disabled) — handled by the existing template-opened-think path (`promptTailOpensThink`, `splitThinkBlock(opened_by_template)`). Tool calls are GLM-style (`tokenizer_config.tool_parser_type: glm47`): BARE `<tool_call>NAME<arg_key>K</arg_key><arg_value>V</arg_value>…</tool_call>`, no plural wrapper. `parseHy3ToolCalls` was extended to route a bare `<tool_call>` whose body has an `<arg_key` before its close into the GLM parser (Hermes `{JSON}`/`<function=` bodies still fall through). String arg values stay strings; schema coercion types scalars. Format-corpus family `laguna`.
- **Thinking is PROMPT-OPENED but MODEL-GATED**: `enable_thinking` reaches the template (verified ON-vs-OFF divergence at temp 0), which ends the prompt with `<think>` — but laguna closes that block immediately on chat-y turns and on tool-dispatch turns, so `reasoning_content` is legitimately empty there; a reasoning-shaped prompt gets a real block. "Thinking never triggers" on this arch is checkpoint behaviour, not a serving bug — reproduce with a math/puzzle prompt before suspecting the pipeline. The app's default `reasoning_effort: "low"` is a 512-token budget (`responses.effortBudget`) and visibly cuts thinking mid-sentence; `high` is 8192.
- **Sampling / EOS**: `generation_config.json` dropped into the model dir (poolside's recommendation: temp 1.0 / top_p 1.0). EOS `[2, 24]` (〈|EOS|〉, `</assistant>`), parsed generically.
- **Parity**: `tests/dump_laguna_fixtures.py` (instantiate `modeling_laguna.py` at a TINY random config, CPU fp32) dumps per-module oracles (YaRN cos/sin, gated-attention block, sigmoid router, MoE block w/ shared expert); env-gated Zig cos oracles (`LAGUNA_FIXTURES=…`). Pure-unit: config parse ("parses laguna") + `computeYarnFreqs`.
- **v1 scope**: DFlash draft model (spec decode) is future work; PLD works generically.

## OpenAI Responses API (`/v1/responses`)

Pure data in `responses.zig`; HTTP/orchestration in `server.zig`. Supports `POST`/`GET`/`DELETE /{id}`.

- **Envelope** (`buildResponsesEnvelope` + `ResponseEcho`): echoes `tools`, `tool_choice`, `text`, `reasoning`, `usage` (with `cached_tokens` + `reasoning_tokens`), `truncation`, `parallel_tool_calls`, sampling params, `metadata`, etc. Renderers reshape into the strict ResponseResource schema (flat tool form, not nested chat-completions).
- **Streaming SSE**: `response.created`, `response.in_progress`, `response.output_item.added`, per-type deltas/`.done`, `response.completed`, then the terminal `data: [DONE]` sentinel (HTTP SSE ONLY — gated on `ws_mode == null`; a [DONE] frame over WS is misread as the next turn's marker on chained sessions, pinned by Test C/E in `tests/test_responses_streaming.sh`). **Every event needs `sequence_number`** — `sendResponsesEvent` injects it; the POST handler threads a per-request `seq_num`.
- **`background: true` → 400** (honest rejection — there is no queue/poll machinery; accepting it and running synchronously returned status "completed" on a request the caller expects to poll, which llmprobe flags). The WS transport already rejected it at body-build time.
- **Stateful chains**: `ResponseStore` keyed by id. `previous_response_id` replays history; missing → 404. `inputContainsFunctionCallOutput` triggers final-answer mode (tools disabled).
- **Compliance**: `experiments/openresponses` validates strict schema; currently 17/17. `top_level response_format` accepted as alias for `text.format`.
- **Compaction (`POST /v1/responses/compact`)**: pure data, no LLM call. Synthesizes opaque base64 `encrypted_content` over `{"v":1,"msgs":[...]}`. `appendCompactionInputItem` reconstitutes on round-trip. `model` required (422 on missing). Drops tool calls + images.
- **WebSocket transport (`ws[s]://host/v1/responses`)**: same endpoint, opt-in via `Upgrade: websocket`. Each text frame is a `response.create`-shaped JSON; SSE events become single WS text frames via `WsBridge` on `Conn.ws_mode`. **No `[DONE]` on success** (`response.completed`/`.failed`/`.incomplete` is the terminator). Sequence numbers reset per response. `WsLocalCache` holds `store: false` responses for the connection lifetime; failed continuations evict the chain root.

## Generation defaults

`~/.mlx-serve/generation-settings.json` holds global rules, `{"temperature": {"value": 0.8}, "reasoning_budget": {"value": 1024, "ignore_client": true}}`; a model's entry in `model-settings.json` carries the same object under `generation_defaults`, and its `chat_template_kwargs` `enable_thinking`/`reasoning_effort` fill rules it leaves unset. Model rules replace global ones field by field. A rule fills a field the request omits; `ignore_client` makes it replace the request's value. Both files are read per request through `model_settings.Cache` (mtime-checked), so an edit applies to the next request. A malformed profile is logged and ignored, never a refused request.

The `reasoning_budget` rule stands in for `--reasoning-budget`: effort words map against it (`xhigh` is capped by it, `medium` keeps 8192); forced, it replaces the final budget. Enforcement is the ordinary `think_bound`. A forced `enable_thinking`/`reasoning_effort` ignores the request's thinking switches; raw `/v1/completions` has no thinking and ignores those rules. The app migrates only its old server-wide values (`--temp`/`--top-p`/`--top-k`) into the global file, once.

## Ollama-compatible API (`/api/*`)

Drop-in surface for the Ollama client ecosystem (Raycast, Obsidian, Enchanted, Open WebUI, ollama-python/js). Design rule: **NO duplicated inference pipeline** — pure translation in `src/ollama.zig`, thin glue in server.zig.

- **Request path**: `/api/chat`, `/api/generate` (raw:true → `/v1/completions`), `/api/embed(dings)` translate the Ollama body into an OpenAI-shaped body (`translateChatRequest`/`translateGenerateRequest`/`translateEmbedRequest` — always inner-`stream:true` + `include_usage`) and call the EXISTING `/v1` handler. Ollama differences handled in translation: `options.num_predict`→`max_tokens`, `images` (b64 array)→data-URL `image_url` blocks, history `tool_calls.arguments` OBJECT→string, `format` ("json" | schema)→`response_format`, `think`→`enable_thinking`, stream DEFAULTS TRUE, `num_ctx`/`keep_alive`/generate-`context` deliberately ignored.
- **Response path**: an `ollama.Sink` on `Conn.ollama_sink` (the `WsBridge` interception pattern) receives every byte the inner handler writes, re-frames SSE chunks into NDJSON lines (or one aggregate JSON for `stream:false`), converts tool-call `arguments` string→object, maps `reasoning_content`→`thinking`, `finish_reason`→`done_reason`, usage→`eval_count`/`prompt_eval_count`, and translates inner error JSON to Ollama's `{"error":…}`. Keepalive SSE comments are dropped. The sink writes through `Conn.writer()` directly (bypasses the hook); glue MUST clear `stream.ollama_sink` before `sink.finish()`.
- **No-model endpoints** (`handleOllamaEarly`, before scheduler resolution — never trigger a cold load): `/api/version` (build CalVer — parses as a high semver so client feature-gates pass), `/api/tags`, `/api/ps`, `/api/show`, `/api/pull` (native HF pull via cli.zig + `registerByPath`); `/api/create|copy|delete|push|blobs` → explicit 501.
- **Name resolution**: Ollama clients send `name:tag`. For `/api/` paths only, an unknown `model` tries `ollama.resolveName` (strip `:tag` → exact → case-insensitive → unique basename → unique substring) against registry ids before the default-model fallback; `/v1` fallback semantics unchanged.
- **Discovery is two-level**: `discoverModels` also scans `<root>/<org>/<model>` (id `"org/model"`) so `~/.mlx-serve/models` pulls are listable/loadable. GOTCHA (class: two ids, one path, double residency): a path registered under an org/name id must never be re-registered under its basename — `registry.peekByPath` guards the `--model` primary registration and `registerByPath`; any new registration site must check it, or the same weights can load twice and OOM.

## LAN model sharing (`--lan-share` / `--lan-discover`)

v1 is LAN-only (WAN rooms would layer onto the same seams); both halves OFF by default and independent. Design rule: **the proxy is a TRANSPORT** — no scheduler, no MLX, no inference-thread involvement. `src/lan.zig` owns discovery (dns_sd/Bonjour `_mlxserve._tcp`, browser thread) + the peer table + the byte-pump tunnel; server.zig adds three hooks (gate, dispatch interception, /v1/models filter/augment). `serve()` starts/stops it at the ONE chokepoint every serve path flows through, so the advertised port is always the bound port.

- **Share** (`--lan-share <all|id,csv>`, `--lan-name <n>` default hostname): advertise over Bonjour and open exactly the SHARED INFERENCE SURFACE to non-loopback clients — `lan.routeClass` allowlist (the four chat surfaces + embeddings + all five media-gen endpoints + `/api/chat|generate|embed(dings)`; open: OPTIONS, /health, filtered GET /v1/models, /api/version) × a shared-model check (`SharedSet`, symmetric basename-tolerant matching so the app's share names match `org/name` registry ids). Everything else — load/unload, /metrics, the status page, stored responses, WS — is host-local → 403. The gate exists only in KEYLESS mode: with `--api-key` set the existing key semantics rule unchanged. An empty parsed share set = sharing disabled (warn), never advertise-nothing.
- **Discover** (`--lan-discover`): browse peers, fetch their (shared-filtered) /v1/models, mirror entries as `<id>@<peer>` with a top-level `"lan_peer"` badge; a DIRECT request naming one — loopback app, the Agent Sandbox guest over the VM NAT interface, a LAN client — is TUNNELED byte-for-byte with only the model field rewritten to the bare id (`rewriteModelValue` takes the SAME slice `parseModelFromBody` returned, so the decide and rewrite layers can never disagree). Remote-id compares CANONICALIZE JSON's `\/` escape first (`lan.unescapeJsonSlashes` at the handleLanProxy chokepoint; the tunnel splices the canonical bare id so the peer never sees escaped bytes and silently serves its default) — Swift/PHP clients escape every slash, so an org-prefixed id arrives as `ddalcu\/gemma…@peer` and missed the byte-compare (live app 404 "no longer shares this model"; third bite of the load-model `\/` class — any id compared from a RAW body scan must canonicalize). The app's own serializers now also emit `.withoutEscapingSlashes`. The proxy's failure modes are DISTINCT (one "peer offline" 404 covering all three sent the user debugging the wrong Mac): discovery off on THIS server → says so; peer known but model unlisted → instant honest 404; peer unknown → `pokeDiscovery` + poll `lookupRemote` up to 15 s (`LAN_PEER_WAIT_MS`, client disconnect abandons the wait) before the offline 404 — covering a local restart's cold peer table AND a peer Mac mid-reboot (a chat fired during a peer redeploy now waits for rediscovery and succeeds). Never a silent local-default answer; a registered LOCAL id containing '@' wins via the registry peek. `/v1/load-model`+`/v1/unload-model` on a remote id are 200 no-ops (the peer loads on demand and manages its own residency) so client load→generate→unload flows work unchanged. Engagement log: `[lan] proxy <method> <path> -> "<peer>" @ ip:port`.
- **Loops are impossible by construction**: proxying is bounded to ONE hop by the tunnel marker — `lan.tunnel` stamps `X-MLX-LAN: 1` on every request it forwards, and a request carrying that marker is never proxied again (`isTunneledRequest` at the keyless gate and at dispatch; any DIRECT client may initiate the single hop — loopback-ness is not the bound, which is what let the Agent Sandbox guest work, live 2026-07-21). Remote entries never re-export: the list served to a discovery fetch (identified by the same marker, so loopback fetches between two servers on one Mac are covered too) filters out remote stubs, AND `parsePeerModels` skips any entry carrying `lan_peer` (defends against old peers). Self-advertisements are skipped via a random per-process TXT token (`t=<hex>`); a fetch that lands on OURSELVES anyway (stale Bonjour record of a former self: same name+port, different TXT token) is caught by the `X-MLX-LAN-Token` header `/v1/models` responses carry — token match → `error.SelfFetch` → the service is forgotten. Browse REMOVE events and refresh failures route through the same resolve-and-reinstall path, so interface churn and transient fetch failures self-heal (a peer is only dropped when it no longer resolves).
- **Zero dependencies**: mDNSResponder does all mDNS (dns_sd FFI — part of libSystem); outbound sockets are raw libc (`connectTimeout` does the nonblocking-connect dance because a blocking connect to a powered-off host hangs ~75 s); the tunnel's 1 s poll tick doubles as the client-disconnect probe (`conn.peerClosed`) so an abandoned generation tears down on the peer too. The tunnel takes `conn: anytype` (writeAll + peerClosed) — server-independent and hermetically testable against a fake peer socket.
- **Discovery robustness (two live-caught classes)**: (1) dns_sd callbacks fire once PER INTERFACE — resolve/addr waits complete on SUCCESS + `MoreComing` clear, never on the first callback (an lo0 error arriving first must not abort a resolve en0 would have answered), and `AddrOut` collects ALL A records with the fetch trying them LOOPBACK-FIRST — macOS **Local Network privacy** silently blackholes an unapproved process's SYN to LAN addresses (poll timeout, `SO_ERROR=0` — the signature) while loopback is exempt, so a same-machine peer resolved to its en0 record looked permanently unreachable. The app declares `NSLocalNetworkUsageDescription` + `NSBonjourServices [_mlxserve._tcp]` (both plists) so macOS prompts for the real two-Mac case. (2) A transient resolve failure at browse-ADD time must not lose the peer forever (browse never re-announces a live service): the browser keeps a `known` services registry retried every 10 s — the PEER table is cleaned on the first failure (no stale entries) while `known` quietly re-attempts, forgetting a name only after `KNOWN_MAX_FAILS` consecutive failures or when it turns out to be our own advertisement.
- **Swift app**: Settings ▸ LAN Sharing (share toggle + share-all/per-model checkboxes + name + discover toggle + the privacy disclosure — the host SEES tunneled prompts; that's inherent, not a bug). LAN models appear in the tray picker ("On Your Network", tags `lan:<id>`) and in all five media panes (capability-filtered via `server.lanModels(capability:)`; `LanPick` owns the `lan:` persistence format and the shared picker binding; `LanModelPickerRows` renders the section). Chat routes through `server.chatModelId` / `server.chatModelInfo` (LAN selection wins over the local default) — **never read `modelInfo?.name` directly at a new chat surface** or LAN selections silently miss it. Gen services route through `ServerManager.prepareGenModel` (a LAN id passes through; nothing is resolved/loaded/unloaded locally), and panes skip download-gating for LAN picks. Enabling either toggle keeps the server running (headless when no local model is selected); `AppState.ensureServerForLan` is the chokepoint.
- **Guards**: hermetic lan.zig tests (id split/rewrite, routeClass, SharedSet, TXT codec, parsePeerModels, tunnel pump + dead-peer 502-before-bytes), `lanShareDenial` unit test (server.zig), `tests/test_lan_share.sh` (20 live checks incl. the peer-restart rediscovery wait + both fast-fail messages), Swift `LanSharingTests` + the LAN cases in `ServerOptionsTests` (defaults-off emission, restart detection, tolerant decode).

## Upstream chat providers (`~/.mlx-serve/providers.json`)

A provider is any server speaking OpenAI `POST /v1/chat/completions` — a cloud API, another box on the LAN, a local runtime — configured in `~/.mlx-serve/providers.json` (no flag; missing file = none). `src/providers.zig` owns the config, the background probe and the proxy; server.zig adds the same three hooks the LAN has (gate, dispatch, /v1/models augment). Same id grammar as a LAN peer: `<model>@<name>`; a provider name wins over a peer of the same name at dispatch because it is a URL the user typed.

- **Config**: `[{"name","url","api_key","api_key_env","enabled","models":[...]}]` (or `{"providers":[...]}`). `name` is `[A-Za-z0-9_.-]`, `url` is the base (`.../v1`, trailing `/` trimmed), `api_key_env` outranks `api_key` when the variable is set and non-empty, `enabled:false` drops the row before anything reads it. Invalid rows are skipped with a `[providers]` warning; a non-array body is a reload error.
- **Probe**: `GET <url>/models` via `curl` every 60 s; a URL that lists nothing there is retried at `<url>/v1/models` and the slot adopts `/v1` when that answers with a list (`v1Candidate`, logged `using <url>/v1`, visible in `GET /v1/providers`). A URL naming THIS server (loopback host + our bound port, `isSelfUrl`) is refused at reload by name: it would mirror itself and every proxied request lands back here. The app's row validator refuses the same URL against the port it manages. Probes run on its own thread (and right after boot or `POST /v1/providers/reload`). Rows are decided by `rowsFor`: 200 + a usable `data` list → those ids (with `context_length`/`max_model_len`/`meta.context_length` twinned when the provider reports one), narrowed to the declared `models` when that list is non-empty (OpenRouter lists hundreds; a declared id the provider does not list still rides, bare); any other HTTP answer (404 = no model list, empty list, non-JSON, 401) → the declared `models`; no HTTP answer at all → zero rows. Every row carries `"provider":"<name>"`, `owned_by`, `loaded:false` + `state:"remote"` (nothing is resident HERE — the tray's In Memory list is `ServerManager.residentModels`, local rows only), `capabilities:["chat"]`. `GET /v1/providers` reports `{name,url,up,probed,models}` per provider — the app's health dot reads that, never a probe of its own.
- **Proxy**: `<bare>@<name>` on `/v1/chat/completions` only (every other model-gated surface is a named 400: "Provider models are served on /v1/chat/completions only"). `curl -N -i` POSTs the body with the model rewritten to the bare id and `Authorization: Bearer <key>`; the upstream STATUS and Content-Type are relayed under our own head with `Connection: close` (curl already decodes chunking, so the upstream framing headers must not be forwarded), the body streams as it arrives, and a 1 s poll doubles as the client-disconnect probe so an abandoned chat kills curl instead of paying for the whole answer. `error.ProviderUnreachable` is returned before any byte reaches the client → 502 `provider_unreachable`. Any bare id is forwarded (the probe is a snapshot; the provider's own 404 is the honest answer). `load-model`/`unload-model` on a provider id are 200 no-ops like LAN ids. Engagement log: `[providers] proxy "<bare>" -> <url>/chat/completions`.
- **Never shared**: provider models are the host owner's key, so `lanShareDenial` refuses `@<provider>` ids from non-loopback keyless clients and the LAN-filtered `/v1/models` never lists them. Transport is curl (TLS, HTTP/2, redirects, system proxies for free); the Mac App Store build cannot exec it, so providers are DMG/CLI only there — same limit as `mlx-serve pull`.
- **Swift app**: Settings ▸ Providers edits the file row by row (`ProviderEntry`/`ProvidersFile`, keys = the server's; `ProviderEntry.problem` mirrors the server's skip rules) and calls `/v1/providers/reload` on every save. Provider rows parse as remote entries (`ModelInfo.provider`, with `lanPeer` set too so every `<id>@<host>` routing surface works unchanged) and list under "Providers" in the pill, the tray and ⌘L (`ModelPalette.remoteSection`).
- **Guards**: hermetic providers.zig tests (config parse, models parse, `rowsFor` matrix, `-i` head parse, curl status trailer, table lookup, and `proxyChat` against a fake chunked-SSE upstream + a dead port), `tests/test_providers.sh` (two Python stubs: listed vs declared, env-key precedence, SSE relay, the named 400, drop-and-return across reload), Swift `ProvidersConfigTests`.

## Per-model settings (`~/.mlx-serve/model-settings.json`, #269)

Settings that follow the MODEL instead of the process. The server reads the file itself at every load of a model (boot `--model`, GGUF boot arms, `/v1/load-model` cold loads), same ownership split as `providers.json`: the app edits, the server applies. No restart: the app reloads a resident model with `/v1/unload-model` + `/v1/load-model`.

- **File**: an object keyed by the model's absolute path (dir for safetensors, the `.gguf` file for a GGUF quant; trailing `/` trimmed on both sides): `{"/…/Qwen3.8-27B": {"ctx_size": 65536, "kv_quant": "8", "mtp": false}}`. `ctx_size` u32 (0/absent = `--ctx-size`/auto), `kv_quant` the per-request vocabulary (`"off"|"4"|"8"`, `KVQuantConfig.fromJsonValue`), `mtp` bool (`false` = head not loaded, `true` = head loaded AND on by default, the `--mtp` force per model), `mtp_greedy_tail` bool (outranks `--mtp-greedy-tail`; logged `[mtp] greedy tail on|off (source)`, `/props` `settings.mtp.greedy_tail`). Unknown keys ignored; a missing/malformed file is `[model-settings] … ignored` and empty — a typo never stops a load.
- **Alias**: `"alias": "qwen"` names the model in requests. It is not a load setting: `server.resolveRequestModelId` checks it after an exact-id or path miss (then the untagged alias and Ollama short names on `/api/`), for dispatch, the LAN gate, load, unload and `/api/show`. The file is held parsed in `model_settings.Cache` (`g_model_aliases`), re-stated at most once a second and re-parsed only when its size, mtime or inode moved; a duplicate alias logs `[model-settings] alias "q" claimed by …`. No spaces, `@`, `/`, quotes or `mlx-serve` (`model_settings.validAlias`, Swift twin `ModelOverride.isValidAlias`); a name claimed twice goes to the lowest path; an id always beats an alias. `/v1/models` puts `"alias"` on the row, `id` stays canonical; a LAN mirror drops the peer alias (it resolves only there). The app saves an alias-only edit without a reload.
- **Apply**: `model_settings.overrideFor` at each construction site → `scheduler.applyModelSettings` stamps `ModelConfig.ctx_override` / `kv_quant_override` / `mtp_override` / `mtp_greedy_tail_override`; `doLoadOnInferenceThread` resolves `kv_quant_config` / `mtp_enabled` once from those over the flags. Readers: `server.manualContext(config)` (pin, effective context, sizer, both `resolvedContextForLoad` callers), `configuredKvQuantFor(config)` (admission bill, fused-read decision, `defaultKvBits`), `forceMtpFor(config)` at the four `defaultEnableMtp` sites, `Scheduler.submit` slot width. GGUF: the stub's `max_position_embeddings` takes the override. Log: `[model-settings] <path>: ctx=N kv=8 mtp=off`.
- **Report**: `/v1/models` `meta.kv_quant` beside `context_length` / `mtp_loaded`.
- **App**: `ModelSettingsFile`/`ModelOverride` (unknown keys survive a save), `ModelSettingsSheet` from the My Models row (context menu "Model Settings…", a `slider.horizontal.3` button when overrides exist) and from the context-overflow card when the model has an override (`ContextIncreaseTarget`). `AgentEngine.effectiveContextLength` prefers the SERVER's advertised context over the slider.
- **Guards**: `model_settings.zig` unit tests, `tests/test_model_settings.sh` (boot + second model keeps globals + edit/unload/load + malformed file), Swift `ModelSettingsFileTests`.

## Observability (`--metrics`) + optional API key (`--api-key`)

Opt-in, performance-safe. Design contract: **zero cost when off** (a single `?*Metrics` null-check per REQUEST at `finishSlot`, never per token), negligible when on (per-request relaxed atomic adds off the decode path + a 2 s gauge sampler thread).

- **Core** (`src/metrics.zig`): lock-free `Counter`/`Gauge`/`Histogram` (all `.monotonic`). `renderPrometheus` emits `vllm:` (standard — drop-in vLLM/Grafana dashboards) + `mlx_serve:` (Apple-specific: GPU%, memory, live tok/s) names; `renderJson` feeds the index panel. `Metrics.recordRequest(outcome, ...)` runs once per slot, on the inference thread, from `scheduler.finishSlot` or the cleanup drain (first one wins; success ⇒ all histograms/counters; `cancelled` ⇒ only `requests_cancelled_total`, including a disconnect mid-decode; `failed` ⇒ only `mlx_serve:request_failed_total`). A request refused before it owns a slot (context overflow, memory preflight) counts in `mlx_serve:request_rejected_total` via `Metrics.recordRejected`.
- **Wiring**: `--metrics` in `main.zig` allocates one `Metrics` on the main stack frame, publishes it via `server_mod.g_metrics` (+ `defer g_metrics = null` so an early `serve()` failure can't dangle), and every `LoadParams` builder reads it back (`.metrics = server_mod.g_metrics`) into `Scheduler.metrics`. Covers ALL serve paths (MLX/ds4/llama/headless/gen).
- **TTFT is exact, not derived**: `Slot.first_token_ns` is captured directly at prefill completion (`request_start_ts.untilNow`), so a slot finishing mid-tick can't skew it; `e2e = first_token_ns + decode_ns`.
- **A dashboard rate must be DERIVED, never remembered** (Monitoring in `app-web/src/lib/core/monitor-history.ts`). `lastPrefillTps` was a module-level `let` assigned only when the 60 s window contained prefill work, and never reset — so the Prefill tile kept displaying the last prefill speed through an entire decode, and only a page REFRESH cleared it. That refresh-clears-it symptom is the signature of state living in a variable instead of being derived from the current feed. Fix: the console derives rates with `liveRates(samples, feed, now)` (pure, tested in `app-web/test/monitor.test.ts`), with zero carry-forward — Prefill reads 0 when not prefilling, exactly like Decode. The stable "how fast does this machine prefill" answer moved to the sub-line as `803 tok/s avg · 1.5K ms` (cumulative `prefill_tokens_total / prefill_time_sum`, so it can never go stale). **Rule: if a tile survives a condition changing, ask whether a page refresh would show the same value.** Guard: `tests/metrics_panel_test.mjs` (node; run as Phase 0 of `tests/test_metrics.sh`, SKIPs without node) — includes `a page refresh and a live tick agree`.
- **A rate's numerator and denominator must measure the SAME work** (prefill tok/s, 10.6x over-report). `vllm:prompt_tokens_total` bills EVERY prompt token; `prefill_time_seconds` only ticks for tokens actually forwarded. With the hot prefix cache warm, most billed tokens are RESTORED, not computed — so `Δprompt_tokens / Δprefill_time` overstates prefill throughput by `prompt/(prompt-cached)`. Live 2026-07-09: a 35B MoE at a 91-97% token-level hit rate showed **9.8K tok/s** on the panel while its own `[prefill: … tok/s]` log line (which correctly does `(prompt-cached)/ns` via `generate.prefillTokensPerSec`) read 400-1150. Fix: `mlx_serve:prefill_tokens_total` counts FORWARDED tokens (`prompt - cached`, saturating) and is the panel's numerator; `mlx_serve:prefix_cache_tokens_total` counts restores. Invariant `prefill_tokens_total + prefix_cache_tokens_total == prompt_tokens_total` is asserted in both the unit test and `tests/test_metrics.sh` Phase 5 (same prompt twice → the warm request bills its full prompt but forwards ~1 token). `vllm:prompt_tokens_total` keeps its vLLM meaning for dashboard compat. The cache tile now also shows `N% tokens reused`, which is what explains a "low" prefill number on warm turns. **Rule: before dividing a counter by a time histogram, check that every unit in the numerator actually consumed time in the denominator.** (The LIVE gauge below was already correct — it stores the chunk loop's `pos`, i.e. forwarded tokens.)
- **Prefill is live too** (`mlx_serve:prefill_tokens_live`, JSON `prefill_tokens_live`): `prompt_tokens_total` and the `prefill_time_seconds` histogram only advance at request COMPLETION, and generated tokens only accrue during DECODE — so a multi-minute prefill pinned the GPU while the panel read `0` decode / `—` prefill, indistinguishable from a hung server. The prefill chunk loop (`generate.zig`, `GeneratorOptions.prefill_progress`) stores absolute progress into `Scheduler.inflight_prefill_tokens` once per CHUNK (8192 tokens; never per token), `runPrefill`'s `defer` zeroes it on every exit path, and the sampler copies it into the gauge. The panel shows the live rate (Δ over a 30 s window — wide enough to span one chunk on a slow model) and turns the Prefill sub-line into a phase indicator. A SECOND gauge `mlx_serve:requests_prefilling` flips at prefill ENTRY (not at the first chunk), because on a 27B one 8192-token chunk takes ~40 s and the panel would otherwise still read "idle" for that whole span — and because ds4/llama prefill never reaches the MLX chunk loop, so their token gauge stays 0 while the phase flag is still correct. Sub-line: `prefilling` → `prefilling · N tok` once the first chunk lands. Guards: the `prefill progress is exposed live` render test (metrics.zig) + Phase 4 of `tests/test_metrics.sh` (gauge is 0 at rest, >0 mid-prefill, 0 again after).
- **Who and when**: each `/metrics.json` `sessions` entry carries `request_id` (monotonic per process, nonzero; 0 on a cached row) and `client`, one of `claude-code`, `opencode`, `codex`, `omp`, `other`, mapped from the User-Agent product token by `Client.fromUserAgent`; the header itself is never stored or emitted. `mlx_serve:process_start_time_seconds` (JSON gauge `process_start_time_seconds`) changes only on restart.
- **Live tok/s without per-token work** (the data-race fix): the inference thread stores the sum of active slots' `completion_tokens` into ONE atomic (`Scheduler.inflight_generated_tokens`) once per `runDecodeTick` (via `sumInflightGeneratedTokens`, which EXCLUDES finished/cancelled/errored slots — so the last slot finishing drops it to 0 ⇒ "live == total at rest"). The gauge sampler reads that atomic (`metrics.liveGenerationTokens(m, inflight)`) — never touches per-slot fields off-thread.
- **Index page** (`GET /`, `handleStatusPage`): `@embedFile("html/index.html")` sent byte for byte, nothing templated. The file is BUILT from `app-web/` (Svelte 5 + TypeScript, `npm run build`) and committed, so `zig build` stays Node-free; never hand-edit it. The page takes everything from the server it is served by: version from `/api/version`, the API mount from `location.pathname`, models from `/v1/models`, memory from `/props`, and metrics availability from `/metrics.json` (503 = off). Decode/prefill tok/s are ACTIVE speeds (Δtokens ÷ Δphase-time) charted from a browser-side history (IndexedDB `studio.monitor`, 24 h). Design + rules: `app-web/CLAUDE.md`.
- **API key** (`--api-key`, `g_api_key`): when set, every NON-loopback request (OpenAI/Anthropic/Ollama APIs + index page + `/metrics*`) needs the key — `Authorization: Bearer`, `x-api-key` (Anthropic), HTTP Basic (browser pages, key = password; a `WWW-Authenticate: Basic` 401 prompts), or `?api_key=`/`?key=`. **Loopback (127.0.0.0/8, ::1) is TRUSTED and exempt** (`peerIsLoopback` off `conn.stream.socket.address`), so the same-host app + a local browser never need credentials — the key protects network exposure (`--host 0.0.0.0`). `/health` + OPTIONS always open. `apiKeyAuthorized` is pure/unit-tested; `constTimeEql` avoids a timing oracle. NOTE: because localhost is exempt, `curl localhost` won't see the 401 — that's by design (verify with a non-loopback client or the hermetic tests).
- **No admin surface**: the PR-53 admin dashboard / `--admin-key` / cache-eviction POST were deliberately dropped — the panel is open (behind the optional API key) and read-only.

### Server (Zig)
- **Detection**: when `tools` present, server buffers tokens, checks `<tool_call>`, Hermes XML, Gemma 4 `<|tool_call>`, raw JSON. Gemma 4 double-brace args (`{{...}}`) unwrapped before parse. Thinking tokens buffered separately if enabled.
- **Serialization** (`chat.serializeMessagesJson`): `role: "tool"` passed natively (Gemma 4 templates render `<|turn>tool` directly). Tool call `arguments` serialized as JSON strings, not objects.
- **Streaming**: full args sent in one SSE delta (avoids client accumulation bugs). Thinking buffered until close tag, emitted as `reasoning_content`.
- **Fallback** (`chat.fallbackFormatChat`): ChatML, Llama (`ipython` role), Gemma (`Tool result:` in user turn).
- **KV cache**: `reuseKVCache()` token-by-token prefix compare; auto-invalidated after tool calls and pad-only gens. Sliding-window layers keep full buffer; views slice to last `sw` during decode.

### Client (Swift)
- **Agent loop** (`ChatView.runAgentLoop`): up to 150 iters; tools → parse → exec → feed back → repeat. Synthetic user nudge after tool results for some models.
- **History builder**: filters errors/pad-only/summaries, truncates assistant at 500 chars, budget-aware (walks backward, fits within `context_length - max_tokens - system_prompt`), pins first user + first assistant, auto-compacts tool results when tight.
- **SSE parsing**: accumulates tool-call deltas; emits `.toolCalls` on `finish_reason: "tool_calls"`; fallback if stream drops without `finish_reason`.
- **Storage**: `SerializedToolCall` (id, name, args as JSON string) on `ChatMessage.toolCalls`; Codable-persisted; backwards-compat (optional field).
- **Error recovery**: tool errors include sent args + retry hint → enables self-correction.

## Resumable Downloads

`DownloadManager` streams to `<file>.partial` via `URLSessionDataTask`. Resume sends `Range: bytes=<existing>-`; 206 → continue, 200 → truncate+restart. 3 retries with 2s/4s backoff. Cancel preserves `.partial`. UI shows "Resume" when `hasPartialDownload()`. Already-complete files (size matches HF metadata) are skipped.

### Server logs
- **Persisted by default** to `~/.mlx-serve/logs/mlx-serve-<port>.log` on every serving path (`--serve`, `mlx-serve run`); `pull`/`list` never write one. Rotates at 32 MB into a single `.log.1` backup (bounded at 2x). `--log-file <path>` relocates it, `--log-file off` disables. stderr is unchanged, so the app's rolling buffer still works. Implemented as a file sink in `log.zig` (raw libc `write(2)` + a pthread mutex — log calls come from the accept loop, every conn thread and the inference thread, none of which carry an `Io`). The sink is opened after `--log-level` parses (level gates what reaches disk) and before model discovery (so weight-load + auto-context lines land in it). A failure to open warns and falls back to stderr-only; a failed write drops the line rather than killing the server.
- Per-port so the app's server (11234) and a test server never interleave into one file. This is the file to read for a post-mortem — the app's in-memory buffer dies with the app, and a restarted/crashed server takes its history with it (that gap is what made the 2026-07-08 pi `terminated` bug hard to diagnose).
- `--log-level debug` for verbose output
- App captures stderr in a `ThrottledLogBuffer` (1 MB rolling tail, `ServerManager.serverLogMaxBytes`); view via the log button in the menu bar. CONTRACT: the buffer always retains at least `maxBytes` and never exceeds `maxRetained` (= 1.25×) — `append` only re-trims past a high-water mark, because an O(n) `count` + `suffix` on every stderr chunk is invisible at 64 KB and a real main-thread cost at 1 MB. It also tracks its own length (`ThrottledLogBuffer.count`, O(1)) since `String.count` walks grapheme clusters. Full history is on disk (see above) — the tail is just what the window renders.
- Manual: `./zig-out/bin/mlx-serve --model <path> --serve --port 8080 --log-level debug 2>&1`
- Patterns: `jinja error:`, `[cache] reusing N/M tokens`, `[cache] invalidated`, `<- N+M tokens (Xms) [reason]`, `tool_msgs=N`, `[spec-stats] mode=...`, `spec-gate: ngram-score=...`

- Every agent request dumped to `~/.mlx-serve/last-agent-request.json`; replay via curl

### Embedded engines (`lib/<engine>/`)

DSV4-Flash is served by the embedded **ds4** engine (antirez/ds4, since renamed "DwarfStar" upstream), pinned at `lib/ds4/@477c0e8`. `build.zig` compiles `ds4.c` + `ds4_distributed.c` + `ds4_metal.m` (the library path; `ds4_kvstore/web/help/agent.c` are CLI/server-only and not embedded). The Zig MLX path no longer carries a DSV4 forward — `model_type=deepseek_v4` on a `.safetensors` checkpoint returns `error.UnsupportedDsv4MlxFormat`; users load the GGUF artifact through ds4 instead.

- C library API: `lib/ds4/ds4.h` (~200 lines, engine + session model).
- FFI: `src/ds4_ffi.zig` (mechanical mirror of the header).
- Bridge: `src/arch/ds4.zig` (`Ds4Engine` + `Ds4Session` — owns Metal-kernel extraction, tokenizer lookups, and the speculative-decode API).
- Session context: `arch_ds4.clampSessionCtx(--ctx-size)` — honors the user's `--ctx-size` (the app's Settings context slider), floored at ds4's `prefill_chunk` (2048) so an under-sized ctx can't produce junk output; `0`/unset → ds4's default 32768. Carried on the stub `ModelConfig.max_position_embeddings` by `runDs4Serve` and read back in `scheduler.runPrefillDs4` (and the `runDs4Offline` CLI path). NOT subject to the MLX `computeMaxSafeContext` auto-budget — ds4 manages its own KV outside MLX, so the per-token estimate there doesn't model it.
- **An MLX memory/working-set guard must EXEMPT embedded-engine requests (ds4/llama) — class: MLX-only estimate applied to a non-MLX forward path.** The ds4 (and llama.cpp GGUF) stub `ModelConfig` advertises real-looking dims (ds4: 56 heads / 61 layers / hidden 7168) so the MLX per-token estimators bill a full transformer that never runs. The auto-context budget already exempts ds4 (above); the prefill preflight `server.checkAttentionMemory` did NOT — live 2026-07-15 (pi + ds4): an 8.6K-token prompt projected `~25189MB` and got a `400 "requires ~…MB GPU memory but only ~…MB available"`, a prompt the SAME server had just served on the MLX qwen35 engine one model-switch earlier. Fix: `server.mlxMemoryGuardApplies(uses_ds4, uses_llama)` early-returns `true` at the top of `checkAttentionMemory` (the SINGLE chokepoint all four HTTP surfaces route through — one gate covers every current + future call site) so an embedded-engine request skips the MLX estimate entirely; the context-length guard (`prompt_ids.len > getEffectiveContextLength`) still bounds the prompt against ds4's own session ctx. Symptom signature: a `requires ~NMB GPU memory` 400 on a ds4/GGUF model whose prompt is well under its context, at a token count another engine served fine. Rule: any NEW MLX memory guard (working-set, KV, prefill-envelope) must skip when `lm.ds4_engine != null or lm.llama_engine != null`, or route through `checkAttentionMemory`. Guard: the `mlxMemoryGuardApplies` unit test in server.zig (red-on-revert: `TestUnexpectedResult`).
- Build: `build.zig` compiles `lib/ds4/ds4.c` + `lib/ds4/ds4_metal.m` and links Foundation/Metal. Metal kernel sources are embedded via `@embedFile` (`lib/ds4_metal_sources.zig`); at first launch we stage them under `~/.mlx-serve/ds4-metal/<binary-hash>/` and point ds4 at them via its `DS4_METAL_<NAME>_SOURCE` env-var overrides — zero patches to the submodule.
- Convention: each new model-specific engine lives at `lib/<engine>/`, exposes a single-header C API, and gets a thin Zig wrapper at `src/arch/<engine>.zig`. See `CONTRIBUTING.md` for the embedding checklist.

Generic GGUF models (everything except DSV4-Flash) are served by the embedded **llama.cpp** engine via `libllama`.

- Staging: `scripts/fetch-llama.sh` downloads the pinned llama.cpp XCFramework (`LLAMA_TAG`, currently `b11429` = release v0.6.0, whose own tag ships no binaries), thins the macOS slice to a single self-contained arm64 `lib/llama/lib/libllama.dylib` (llama + ggml + ggml-metal merged, Metal shaders embedded), rewrites its install-name to `@rpath/libllama.dylib`, and copies headers to `lib/llama/include`. **Not vendored** — `lib/llama/` is git-ignored and re-fetched by CI / `app/build.sh`. Bump `LLAMA_TAG` to upgrade.
- C shim: `lib/llama_shim/llama_shim.{h,cpp}` — a small, stable C API over the ABI-fragile `llama.h` structs (compiled by clang against the real header, so the ABI is always correct). Mirrors the ds4.h discipline. C++ only to call llama.cpp's C++-linked NextN staging functions (`src/llama-ext.h`, not shipped in the xcframework): the mangled names pin their signatures at link time.
- FFI: `src/llama_ffi.zig` (mechanical mirror of the shim header).
- Bridge: `src/arch/llama.zig` (`LlamaEngine` + `LlamaContext` + `LlamaSeq` — model load, tokenize/detokenize, chat-template string, per-sequence `sync`/`sample`/`specStep`, the batched `LlamaContext.step`). Tests gate on `LLAMA_TEST_MODEL`.
- Sequences: one `llama_context` per model, created at load with `n_seq_max = --llama-cache-entries` (default 4) and `kv_unified = false`, so each sequence owns a full `--ctx-size` KV stream from load. A request claims a sequence at submit (`LoadedModel.session_claims`, bounded by `sessionCapacity`), `scheduler.pickLlamaSeq` picks the free one sharing the longest prompt prefix (else LRU), and `runLlamaDecodeTick` feeds every live slot of the model in ONE batch. A decode discards the previous decode's logits, so each slot samples right after the call that produced its row and carries the token in `Slot.llama_next`.
- MTP (`--llama-mtp-drafts`, default 2): the head is an `mtp-*.gguf` beside the model (`model_discovery.findLlamaMtpSidecar`: same folder, then `MTP/` inside or beside it, unsloth's layout) or the trunk's own NextN layers (`load_mtp`). The shim keeps a second context (`LLAMA_CONTEXT_TYPE_MTP`) in step with the target by replaying every target batch with the target's hidden one position back, drafts greedily, verifies `[id_last, drafts…]` in one target pass by sample-and-match, and trims both contexts to the accepted length; the target needs `n_rs_seq >= drafts` on recurrent archs, else MTP is refused at context creation. Only a slot decoding alone drafts (`llamaDraftsThisTick`). Logs `[spec-stats] mode=llama-mtp`; `[batched] llama.cpp decode engaged (seqs=N)` once.
- Build: `build.zig` `addLlamaLib` adds `lib/llama/include`, links `libllama` (`use_pkg_config = .no` so a Homebrew `llama.cpp` install can't hijack the link), compiles the shim, and adds a dev rpath. Bundling: `release.yml` / `app/build.sh` copy `libllama.dylib` into the app `Frameworks/` (and the CLI tarball `lib/`), rewrite `@rpath/libllama.dylib` → `@executable_path/...`, and sign it through the existing dylib loop — no new executable, so notarization is unchanged.
- Chat templating reuses mlx-serve's Jinja engine: the GGUF's embedded template is adopted into the stub `ChatConfig.chat_template` at load (`Scheduler.doLoadLlamaOnInferenceThread`), then `chat.encodeChatViaLlama` renders via `renderChatTemplate` (which supplies the tool-synthesis fallback) and tokenizes through libllama (`add_special=false`, the template owns BOS).
- Scope: no PLD/drafter/hot prefix cache (MLX-specific); KV quant via `--llama-kv-quant`, prefill batch via `--llama-ubatch`. Tested by `tests/test_llama_gguf.sh` and `tests/test_llama_concurrent.sh` (gated on `LLAMA_GGUF_MODEL`).

## Website & LLM tier list (`website/`)

The GitHub Pages marketing site (deployed by `.github/workflows/pages.yml` on main pushes touching `website/**`; static guard `tests/test_website_pages.sh`). `docs/` is AI/dev docs and is NOT published. Bench numbers live in `benchmarks.md` and the per-run llmprobe reports stay under `~/claude-tmp/` — the CSV/chart pipeline was retired 2026-08-13; the README's one remaining chart is `docs/perf-vs-engines.png`, and the charts the site embeds are its own pinned copies at the `website/` root (og:image URLs are baked — never move those). `website/llm-tier-list/` is the one interactive page:

- The board is ranked by `tierForModel` — the ONE chokepoint, source-scan-pinned — whose `TIER_MODE` is currently `"intelligence"` (published AA index; an unscored model waits in the table rather than being placed on an estimate) because a Wilson board with an empty vote table is an all-U board; **flip it to `"votes"` to restore community ranking, that is the whole change**. Plus community voting (Firebase Auth+Firestore).
- The **quant playground** is a setup calculator (Mac chip × RAM × model × quant × KV quant × context × spec mode → decode tok/s, prefill tok/s, intelligence, RAM fit). Its speed model is a ROOFLINE FIT, not a table: decode = achieved GB/s ÷ bytes-read-per-token, prefill = achieved FLOP/s ÷ 2·active-params, with four efficiency constants fitted to the 26.7.12 bench (`docs/perf-csvs/all-26.7.12.csv`, M4 Max 128 GB, in git history) — `tests/website_tier_list_logic.mjs` REPLAYS those four bench cells plus the 64k ladder decay through the page's own code, so a constant that stops reproducing our bench fails CI. Intelligence is an Artificial Analysis Intelligence Index snapshot (dated in-page); an unscored model is BADGED `est` and inferred from scale — never a fabricated citation.
- **Usable RAM is a fixed reserve, not a percentage** (`usableRamGb`, ONE rule behind both the board's `minRamFor` tier and the playground verdict): a flat 75% is about right at 8 GB and badly wrong at 128 GB, where Metal's own `max_recommended_working_set_size` is ~115 GB (`src/server.zig`'s #64 note) — the 75% rule computed 96 GB and so hid our own 115.4 GB DSV4 mirror from every 128 GB Mac. Past that set but still RAM-resident is a third state, `"tight"`, not "won't fit". The quant ladder carries a `"mix"` rung (0.406 B/weight, from the published `mixed-2-3-8bit` mirror) because large-MoE mirrors do not ship at a uniform width and a uniform-only ladder misreports the hardware needed.

### LFM2-VL (`lfm2_vl`)

LiquidAI LFM2.5-VL (450M/1.6B/3B). The text trunk is the `lfm2` we already serve, unchanged — `layer_types` conv/full_attention, `conv.{in_proj,conv,out_proj}`, `feed_forward.w1/w2/w3`, `operator_norm`/`ffn_norm`, `embedding_norm` as the final norm. `lfm2_vl` adds two things on top and nothing else: a stock `siglip2_vision_model` tower and LFM2-VL's own projector. LiquidAI publish MLX packs themselves (4/5/6/8-bit + bf16) and quantize ONLY the language model — `vision_tower.*` and `multi_modal_projector.*` ship dense bf16 at every width — so the tower is loaded as dense today while `Lin` still resolves `.scales` per tensor for a pack that quantizes it.

**Tower** (`src/lfm2_vision.zig`, 27 layers, hidden 1152, 16 heads hd 72, MLP 4304, LayerNorm eps 1e-6). Vanilla pre-LN ViT: `x += attn(LN1(x))`, `x += mlp(LN2(x))`, then `post_layernorm`. The patch embedder is a plain **Linear** `[1152, 768]` over flattened `[py, px, c]` patches (no conv layout), and attention is unmasked — we encode one image per call, so the reference's packed-sequence mask is all-ones. `vision_use_head: false`, so the attention-pool head is never built. `hidden_act` is `gelu_pytorch_tanh`; the projector's `projector_hidden_act` is plain erf `gelu` — two activations in one checkpoint.

**Position embeddings.** One learned `[256, 1152]` table = a 16x16 grid, resampled to each image's own patch grid by `interpolate(mode="bilinear", align_corners=False, antialias=True)`. Ours does it as two f32 matmuls against `qwen_vision.resampleWeightMatrix(.bilinear)` — Pillow's separable triangle filter, whose footprint widens on downscale, which is exactly torch's antialias. That matters whenever a grid axis is shorter than 16 (an extreme aspect inside the token budget). mlx-vlm 0.6.3 substitutes bicubic here and scores cos 0.99 / rms **1.13x** against the reference, so it cannot serve as an oracle.

**Projector.** `pixel_unshuffle` folds each `downsample_factor` (2) square block of patches into one row (channel-minor within the block, row-major over the reduced grid), then `Linear(4608 -> 2048)` -> GELU -> `Linear(2048 -> 2048)`. Output tokens = `(gh/2) * (gw/2)`.

**NaFlex preprocessing** (`smartResize` / `isImageTooLarge` / `gridLayout`, all pinned against the reference's tables). Sides snap to `patch * downsample` = 32 so the unshuffle never pads, and the area is rescaled into a 64-256 **merged-token** budget preserving aspect (so the pixel bounds carry a `downsample²` factor). It is nearly Qwen's `_smart_resize_image`, differing only in the initial snap being floored at one full factor — which changes the BRANCH for an image thinner than one patch. Python's banker's rounding is load-bearing (`roundHalfEven`; 2000x17 needs `round(62.5) == 62`).

**Tiling.** A source whose snapped area exceeds `max_image_tokens * 32² * max_pixels_tolerance` (2.0) is SPLIT: pick the `cols x rows` grid with `min_tiles(2) <= cols*rows <= max_tiles(10)` closest to the image's aspect, resize the whole image onto a `512 * cols` by `512 * rows` canvas ONCE, cut it into 512px tiles, and append a thumbnail of the whole image at the single-tile geometry. Each piece is its own `chat.ImageData` (`tile_rows`/`tile_cols`/`tile_index`, thumbnail last) and its own tower call. A 1800x1400 photo becomes 2x3 tiles + a 252-token thumbnail = 1788 tokens against 252 for the untiled view; measured on 15px print, tiled reads it exactly and the untiled geometry reads none of it. Re-resizing per tile instead of windowing the shared canvas is a different picture — `buildPixelValuesRegion` is the window.

**Prompt block.** Not a flat pad run. `lfm2ImageSegment` emits `<|image_start|>`, then per piece a marker (`<|img_row_R_col_C|>` for a tile, `<|img_thumbnail|>` for the thumbnail) followed by that piece's pads, then `<|image_end|>`. The row/col ids are one contiguous block laid out row-major over the MAX 10x10 grid, so `base + row * max_tiles + col` locates any of them. None of these ids are in config.json — `ModelConfig.populateLfm2ImageTokens` resolves them by STRING from the tokenizer at load (`tokenizer_config.json` names them: `image_token`, `image_start_token`, `image_end_token`), and a missing marker leaves its id 0, which every consumer reads as absent. Marker order must match the order the encoder concatenated the pieces, because the splice scatters embedding rows into pad slots positionally.

**Guards.** `tests/dump_lfm2_vision_fixtures.py` runs transformers' own `Siglip2VisionModel` plus the projector on OUR pack's weights (`LFM2_VISION_MODEL` + `LFM2_VISION_FIXTURE`; measured pos-embed cos 0.999999 across six grids in both resample directions, tower hidden cos 0.99998/0.99987, projected features cos 0.9997/0.9992 with rms within 0.3%). ### DFlash block-drafter (generic; Muse-Glimmer instance)

DFlash is block-parallel speculative decoding: a small assistant transformer drafts `block_size − 1` tokens in ONE forward, conditioned on the trunk's intermediate hidden states. It is a METHOD, not a model-family feature — transformers ships a generic `DFlashCache` + `DFlashTokenCandidateGenerator`, and any family can publish a `*_assistant` sidecar. Our detection therefore keys on the CONFIG CONTRACT — a sidecar config declaring ALL of `block_size`, `mask_token_id`, `target_layer_ids` (`dflash.isDflashConfigJson`) — never on `model_type`; `--drafter <dir>` stays the one flag and the scheduler probes the sidecar kind (DFlash → `dflash.loadDflash`, else the Gemma cross-attention drafter). `MLX_SERVE_DFLASH=0` skips the sidecar; `--draft-block-size` clamps the config block DOWNWARD only (floor 2).

Assistant shape (no embed table, no lm_head — borrows the trunk's): `encoder.fc [hidden, n_targets·hidden]` + `encoder.output_norm_enc`, N standard llama-style decoder layers (GQA q/k/v/o, WEIGHTED per-head q/k RMS-norms `[head_dim]`, input+post_attention norms, silu MLP), final `norm`. Weight keys are UNPREFIXED (`layers.N.…`). Muse instance: 5 layers, 32 q / 8 kv heads, hd 128, θ 500000, all-sliding 2048, eps 1e-5, block 16, mask id 201818, targets [1, 13, 25, 37, 49]; 5.11 GB bf16 at `meta-models/Muse-Glimmer-30B-assistant` (users pull the original — no ddalcu mirror).

**Weight precision** (`dflash.DflashLinear`, one `apply` for both arms): each round reads the WHOLE assistant, so the assistant's own precision is the per-round cost. A dense bf16 checkpoint is affine-quantized AT LOAD (`MLX_SERVE_DFLASH_QUANT_BITS`, default 8, `0` = dense) and served packed through `mlx_quantized_matmul(transpose=true)` — the quantized layout IS the checkpoint's `[out, in]`, so quantizing REPLACES the dense path's pre-transpose rather than adding a step. A sidecar that already ships `.scales` is served as-is at the width its packed geometry solves to (`transformer.affineParamsFromGeometry`), and asking for dense never unpacks it. A weight whose contraction dim is divisible by neither 64 nor 32 (`dflash.quantGroupFor`) stays dense — per weight, not per model. Only DRAFT quality rides on this: the trunk verify is exact either way, so a bad width costs acceptance, never a token.

**Where the assistant comes from** (`scheduler.drafterFor`, then `dflash.resolveInDirDrafter`): `--no-drafter`/`--drafter <dir>` win, then the per-model `drafter` setting in `model-settings.json` (`off` / `auto` / an absolute dir; a dir without `config.json` falls back to auto), else `<model_dir>/drafter` is probed at LOAD time for the same config contract — the sidecar-or-in-checkpoint shape `mtp.resolveMtpSource` already uses. A merged sidecar makes the drafter a load-time dependency, so a hot model switch brings its own (`--drafter` is launch-only, and the app used to have to restart for it) and no pairing table decides which sidecar goes with which trunk. `--no-drafter` is the opt-out, because an empty `drafter_dir` no longer means "off". `model_discovery.modelKindFromType` maps `*_assistant` to `.drafter` and refuses it as a standalone model, so the subdir never registers itself; the reported `drafter_path` names whatever was actually resolved. Our Muse mirrors ship it at 8-bit/gs64 (2.72 GB vs 5.11 dense) — the width the loader would have quantized to anyway, served pre-packed with no load-time requantization; the bf16 original stays at `meta-models/Muse-Glimmer-30B-assistant` for the fixture parity's dense arm.

**Block size is a HARDWARE decision** (`dflash.resolveBlockSize(config, cli, cli_explicit, wide_lane)`). The block IS the verify width: all `block_size` positions go through ONE trunk forward, and that forward's cost is a step function of its width. MLX routes transposed qmm by `get_qmv_batch_limit(K, N)` (10 on the Muse shapes) — below it the weight-reuse `qmv` runs, at/above it the 32x32-tiled `qmm_splitk` does, wasting half a tile at width 16. Our split-K verify lane (`transformer.vqmmLaneFor`) covers M 2..7 and the NAX m16 tile covers M 8..16 on G17 only, so 8..16 on older GPUs has no lane at all. `wideVerifyLaneAvailable()` false ⇒ the block is capped at `NO_WIDE_LANE_BLOCK_CAP` (5) and the boot log says `capped (no wide verify lane)`. Explicit `--draft-block-size` clamps against the CONFIG block, never the cap — the escape hatch in both directions. Measured on Muse 4-bit / applegpu_g16s, 160-token generations, serial reference in the same boot: block 16 → 0.92x, 8 → 1.16x, 7 → 1.43x, 6 → 1.79x, **5 → 1.97x**, 4 → 1.81x, 3 → 1.77x. Round profile at block 5 (`MLX_SERVE_DFLASH_TRACE=1`, which inserts eval barriers to attribute a fully lazy round — diagnostic only): verify 50.2 ms / assistant 6.2 / draft head 2.9 / append 0.9 / accept 0.2 / scheduler gap 0.01.

**Draft-only lm_head** (`MLX_SERVE_DFLASH_DRAFT_HEAD_BITS`, `dflash.DEFAULT_DRAFT_HEAD_BITS` = 0, i.e. DEFAULT OFF): the block's draft argmax otherwise reads the full trunk head (202048×6656) on top of the verify's own read of it. `bind` re-encodes it once through `mtp.requantizeRows` — the SAME chunked requantizer the MTP head uses, extended to accept a dense source — and only when that shrinks the read (a bf16 head counts as 16 bits/weight). Verification never routes through it, so the emitted distribution is untouched. It defaults OFF because at the resolved block the head is under 2 ms of a ~60 ms round and the acceptance it costs exceeds the bytes it saves: 3-bit 55.4 tok/s / 2.19 accepted per round vs trunk head 57.8 / 2.37. The lever was a win at block 16 (10 ms of a 175 ms round) — a draft-side lossy default is a ratio between a byte saving and an acceptance cost, and both sides move when the block does.

**Sampled requests** draft greedily and accept through the one-hot rule, and that is the MEASURED choice, not a v1 shortcut: on Muse 4-bit there is no temperature penalty (temp 0 → 1.98x / 55.1% per-draft; temp 0.7 → 1.98x / 57.7%, 3 reps x 4 prompts, same-boot serial reference). `MLX_SERVE_DFLASH_SAMPLED_DRAFTS=1` draws each draft from the request's own filtered distribution (`filteredProbsBlock`, one filter pass + one categorical over all m rows) and accepts through the full Leviathan ratio with the residual taken against the true q — exact, and a LOSS (1.87x / 54.5%): expected acceptance is `p(argmax q)` greedy vs `1 − TV(p,q)` sampled, and this assistant's argmax tracks the trunk while its distribution shape does not. Per-request spec cells swing ~10% run to run at temperature; 3+ reps before believing a temperature claim.

### Exact draft trees on NAX (27B dense, DFlash2)

With a DFlash drafter bound, a row-exact trunk (`ModelConfig.rowExactDecode`) verifies a 16-row draft tree whose every row carries the one-row step's bits, so drafts on and off emit the same bytes. The pieces (ported from TensorFold, MIT, NOTICE):

- **Lane matmuls** (`lane_qmm.zig`): every group is one fixed 16-row `matmul2d` (32 rows past 16), then `C = s*P + b*XS` in group order. 4-bit codes feed the op as `uint4b`, 8-bit as bytes, and 5/6-bit are widened to bytes per group in threadgroup memory. `Transformer.tileLaneWeights` and `DflashModel.tileLaneWeights` re-order each weight into column tiles **in its own buffer** at bind (no copy stays resident). From then on only `lane_qmm` reads it: up to 128 rows through the lane kernels, past that through `PREFILL`, a port of MLX's `qmm_t_nax` on the tiled layout that gives MLX's bits. `tileInPlace` takes bits and group size from the caller, because shapes alone cannot tell 4-bit g64 from 8-bit g32. q|k|v are one joined matmul on these trunks (`fa.qkv`).
- **GDN** (`gdn_decode.recurTree`): a prework launch (conv, silu, q/k norm once per head and row) and a tree walk with one dv row per simdgroup, restart states in registers, `StT` rounding per token as serial decode does. Both read qkv/a/b/z as columns of the joined in-projection. The commit replays the kept path from the round's input state and copies the conv window in the same launch (`replay`).
- **Rounds** (`generate.dflashTreeRound`): a best-first tree over the drafter's lattice, or, when 24+ context tokens back a continuation that fills the tree, that continuation as a chain with no assistant forward (`pld_index.backedCopy`).

27B 4-bit on an M5 Ultra, same session vs TensorFold 0.5.0 (llmprobe `--runs 2`): decode 245 vs 241 tok/s, prefill 1936 vs 1691, and 8k/16k rungs 179-196 / 177-181 vs 166 / 163. The 512 rung is at parity within run-to-run noise. 6-bit decode is 190 vs 166 and 8-bit 168 vs 159.

### Quantized-KV attention through matmul2d (`qkvAttnMppKernel`)

`--kv-quant 4|8` attention at head dim 256 runs through Apple's `matmul2d` tensor op on the machines that have the verify-qmm tile (M5 matrix units, M4-family shader code). 32-token KV pages dequantize into threadgroup tile memory, one thread per query-row group (rows pad to multiples of 8), with an online softmax and split-KV partials merged at the end (`qkvMppSplits`). It is tried first inside both packed kernels and declines outside its window (`qkvMppWins`): 4 to 8 query rows from 2048 KV tokens, 2 to 3 rows from 8192, a single decode row from 16384. Below the window the older packed kernels serve: decode at one row, and the verify kernel only while `gqa x t_q <= 12` rows (`qkvVerifyRowsPay`), dense past that. `MLX_SERVE_KV_ATTN_VERIFY=1` keeps the old kernels for an A/B. Structure after Inco Splash (NOTICE). Guards: `tests/test_kv_quant_fused_equivalence.sh`, the kv4/kv8 columns of `tests/test_smoke_matrix.sh`.

### OS memory reserve (`--os-reserve-gib`)

Every memory plan (load preflight, auto-context, prefill admission) subtracts a reserve for macOS from available memory before it bills anything: an eighth of RAM, never under 2 GB or over 8 GB (`server.osReserveBytes`). `--os-reserve-gib N` sets it explicitly and `0` turns it off; the app's "Keep a memory reserve for macOS" setting passes its number (Off = 0) and omits the flag on Auto. It exists because wired GPU memory starves the kernel before Metal reports an error: a 16 GB Mac panicked with 14 MB free. It works with the sibling bill (`scheduler.PromiseLedger`): a restored prefix shares the cached buffers until its first append, so concurrent admits are billed against what earlier admits were promised and have not allocated yet, plus a 2 GB margin.

### Workload-fair hot-cache eviction (#378)

One model, two workloads: an agent conversation and a batch sweep of documents share `LoadedModel.prefix_cache`, and plain LRU let the sweep evict the conversation every time (more entries made it worse). Every entry now carries a `cache_key`, derived per request by `server.requestCacheKey` from the first of: `prompt_cache_key` (OpenAI's routing field; Codex sends it, a scripted pipeline can), `metadata.user_id` (Anthropic; Claude Code embeds its session id), the system prompt (OpenAI `messages[0]` system content incl. text parts, Anthropic `system`, Responses `instructions`), else 0 = anonymous. `/v1/completions` keys on `prompt_cache_key` only.

When an entry must go (count cap, byte budget, `evictLruToAdmit`), `lruIndexExcluding` counts eligible entries per key (the incoming request's key counts as one more on the append path), keeps only the key(s) with the most, and takes the LRU among them; a tie between groups is plain LRU. A sweep therefore evicts its own documents, an unkeyed sweep is one anonymous group that evicts itself, and one workload alone is byte-identical to before. Matching is still by token prefix, the SSD tier's schema and the SSD-first idle spill (`oldestIdleIndex`) are untouched; a disk restore re-enters RAM under the restoring request's key. `[hot-cache] evicted LRU entry (...; key=<hex>; ...)` names the victim's key.

### SSD-first prefix cache

Qwen4_exp uses SSD-first automatically when its disk tier is enabled. Any MLX
architecture with a restorable prefix cache uses the same path when
`--no-prefix-cache-ram --prefix-cache-disk <size>` selects SSD-only mode:
RAM holds model weights plus active requests, while completed reusable prefixes
remain only on SSD.

At 1M context on a 128 GB M5 Max the budget is weights ~70 GB + one session's
entry ~24 GB (~24 KB/token: 12.3 KB of 8-bit KV, 3.8 KB of QSA indexer history,
SSM checkpoints, pooled banks) + transients 3-7 GB against a ~107.5 GB ceiling.
RAM therefore holds the model and ONE session; the SSD is the capacity tier and
`--prefix-cache-disk` is the real limit (~100 GB ≈ four 1M sessions). A disk hit
streams the entry back in seconds against ~25 minutes of re-prefill.

One predicate, `prefix_cache.ssdFirstActive`, requires the env switch and a disk
tier, then admits either `ModelConfig.ssdFirstCapable()` or explicit SSD-only
mode. Scheduler mirrors the result onto both cache tiers; every mechanism reads
that field, never a model type.

| mechanism | what it does |
|---|---|
| 1 flush the LIVE cache | `capturePendingDisk` records the live snapshot, full token record, checkpoints and spec snaps at commit, BEFORE the RAM byte-budget trim; the flush prefers that record. Refcount-shared, consumed once. |
| 2 background writer | `src/kv_disk_writer.zig`: one thread, FIFO, ~1 GiB host-byte permit, prefix-scoped epoch fence at the tier's one directory-removal site, failures attributed to their entry. The inference thread keeps the device→host readback and hands over bytes; `meta.json` is submitted after its chunks so the index lands LAST; every file is tmp+rename. |
| 3 per-chunk write-through | `Generator.WriteThroughHook` at each completed prefill chunk (`MLX_SERVE_SSD_WRITE_THROUGH=0`): RAM-backed mode banks one disk chunk per boundary for crash salvage; SSD-only mode drains every completed chunk available at that boundary so a finished turn is fully persistent. |
| 4 checkpoint-bearing chunks | SSM checkpoints ride OUTSIDE the per-flush byte budget, beside the chunk that closes their position, so a hybrid entry restores from its first flush. |
| 5 budget semantics | `server.ssdFirstPrefixCacheMem` floors RAM at one session at the working context (the entry IS the live KV) and `--prefix-cache-mem` becomes the IDLE allowance (0 = none idle), logged once at load. Disk budget = `min(operator cap, free − min(64 GiB, 10% of volume))`, 1 GiB store floor, re-read via `volumeSpace` before every store. |
| 6 evict-on-idle + root-wide LRU | `HotPrefixCache.spillIdleEntries` at end of request: every idle entry is written; past the allowance the durable ones are shed first, then the rest (naming why). `DiskTier.sweepSiblings` walks the other fingerprints under `<base>`: aged strays go, LRU past one budget's worth. |
| 7 chunk sharing + restore by move | A prefix-diverging turn hard-links the donor's LANDED chunks (manifest v6, `MLX_SERVE_SSD_CHUNK_SHARE=0`); a full-prefix hit checks the entry out so the first append donates in place (`MLX_SERVE_RESTORE_MOVE=0`). |

The prefill width is not part of this: it is a per-request decision
(`chooseRequestPrefillChunk`, gated on `ModelConfig.perRequestPrefillChunk()`).
`volumeSpace` hand-declares darwin's `struct statfs` (std has no binding in this
Zig) with a plausibility guard so a wrong layout fails SAFE to the operator cap.

**Assistant context survives the prefix cache** (`prefix_cache.DflashSnap` / `DflashCommit` / `DflashTarget`). A restore forwards no trunk layers, so it produces no captures and the context would start EMPTY on every reused prefix — measured 92.6% → 66.5% per-draft acceptance and 80.2 → 60.9 tok/s on a full-prefix hit, i.e. the multi-turn case paid for the cache twice. The context snapshot rides `Entry` beside the KV, its bytes folded into `kv_bytes` so `--prefix-cache-mem` and eviction cover it (~20.5 KB/token here vs the trunk's ~53.2). Every failure path degrades rather than errors — no payload, SSD tier, snapshot failure, or a base past the trunk cursor all return `LookupResult.dflash_base = null` and leave the caller's cache untouched (start blind) — which is safe precisely because the state is DRAFT-side. The scheduler adopts only when `base + step == matched` EXACTLY, since `nextDflash` asserts `dctx.absLen() == anchor_pos`.

Protocol per round (`generate.nextDflash`):
1. **Context**: trunk hiddens at the OUTPUT of layers `target_layer_ids` (HF `hidden_states[i+1]`) for the tokens the trunk just verified — captured via `ForwardCtx.capture_layers` (standard forward path ONLY; `DflashModel.bind` refuses MoE/hybrid/module-owned/bert trunks by name so the seam can never be silently ignored). Concatenated on features in config order → `encoder.fc` → RMS norm → per-assistant-layer K/V (k-norm + RoPE at the tokens' ABSOLUTE positions) appended to the per-request context cache (`Generator.dflash_ctx`, a plain dense KVCache + `base_pos`). Prefill builds it chunk-by-chunk; on hot-prefix reuse the context starts late at `base_pos = matched` (sliding-window semantics, same rule as the MTP history). Invariant at every round boundary: `dflash_ctx.absLen() == trunk cache.step`.
2. **Noise block**: `[anchor(t1), mask_token × (block−1)]` through `Transformer.rawEmbedding` — the RAW table rows, no normed-embeddings RMS and no emb_scale (the un-foldable muse embed norm is exactly what makes this hook possible).
3. **Assistant forward** (`dflash.forwardBlock`): Q from the block only; K/V = cached context + fresh block K/V. Block K/V are written into the cache's SPARE CAPACITY and truncated straight back out after the forward — the reference's `crop(-block_size)` with zero copies; context K/V are computed once, ever. Masks: block↔block bidirectional; sliding layers see context within `|q−k| < window` (additive bias via `mlx_where`, built only when something is actually masked); full layers see everything.
4. **Drafts** = argmax of trunk `lm_head(assistant_hidden)[:, 1:]` — the anchor row is DROPPED (the reference applies the bare Linear; softcap/output_multiplier are monotone so draft argmax is unaffected). Greedy drafts v1; sampled requests use the shared one-hot Leviathan acceptance.
5. **Verify** = standard spec invariant: input `[t1, d1…]` width `block`, `cache.step = prompt+emitted`, t1 not in cache, correction from ORIGINAL `verify_logits[accepted]`. The verify forward doubles as the next round's context producer (capture_layers set on it).
6. **Rollback** on partial accept is an offset-only `cache.truncate` — legal because bind restricts targets to the pure-KVCache standard path, where a position's K/V depend only on earlier positions; NO re-forward runs — the next round's context is the verify captures sliced to the committed prefix (the reference's `hidden_states[:, :n_accepted]`).

Wiring: `enable_drafter` is the request-level switch for BOTH sidecar kinds (a model loads at most one); priority MTP > dflash > gemma drafter > PLD (`specInitWiring`/`specTickMode`); every existing spec gate (logprobs>0, grammar, vision, hybrid) applies unchanged; `[spec-stats] mode=dflash`. Server-side, every drafter-loaded gate must read `lm.dflash` beside `lm.drafter` — pinned by a source scan in dflash.zig after four per-surface `use_drafter` re-derivations silently decoded serial (live 2026-08-10, the per-site-wiring class).

Muse measurements. 8-bit trunk, same-boot medians, 400-token generations, block 16 (2026-08-10): echo 31.0 tok/s vs PLD 26.2 vs serial 15.6 (1.99x, avg 4.7–6.7 accepted/round vs PLD's 3.23); agent-ish 24.3 vs 18.0 vs 15.9 (1.53x); creative 17.0 vs 16.4 vs 15.7 (+8%) → default-on when the sidecar loads, no runtime acceptance gate needed (unlike the Gemma drafter). 4-bit trunk, 160-token generations, block 5 + trunk draft head (2026-08-10, the shipped defaults): echo 2.19x serial, agent 2.15x, creative 1.68x, 57.9 vs 27.0 tok/s pooled, 2.37 accepted/round — the same stack was 1.01x before the block cap, because a 4-bit serial step halved while a width-16 verify did not. Levers measured and CLOSED: cross-round pre-draft (scheduler gap is 0.01 ms — nothing to overlap), prefill capture cost (−5.2%/+2.3%/+0.3% at 1128/5525/16185 prompt tokens), adaptive block size (every content class peaks at 5 once the draft head is fixed), assistant micro-opts (halving the assistant's read outright is not faster). Full stories: `docs/gotchas/engine-mlx.md`. Parity vs the executable transformers reference (fp32 CPU, `tests/dump_dflash_fixtures.py` → `DFLASH_FIXTURES` env-gated test): encoder cos 0.999994, draft rounds cos ≥ 0.9999 with rms_ratio 1.000.

### Ling 3.0 (`bailing_hybrid`)

inclusionAI Ling 3.0 (`BailingMoeV3ForCausalLM`): a KDA + MLA hybrid MoE. Shipped tiny: 24 layers, hidden 1536, 16 heads hd 128, vocab 157184, 131K ctx, 128 experts top-8 at 512 + ONE ungated shared expert at 512, dense MLP (4608) on layer 0 (`first_k_dense_replace`). `layer_group_size` 4 ⇒ layers 3/7/11/15/19/23 are full attention (`full_attention_interval`, so `isLinearLayer` needs no new predicate); the other 18 are KDA. Weight prefix `model`, embedding `model.word_embeddings` (quantized — `getNamedWeight` takes the table's name as a RUNTIME argument so the weight/scales/biases lookups cannot drift), untied `lm_head`, norms `input_layernorm`/`post_attention_layernorm`, attention under `attention.` not `self_attn.`. Router bf16 `mlp.gate.weight` + bf16 `mlp.gate.expert_bias` (the routing chain runs f32 and promotes it; the zero-init fallback for `moe_router_enable_expert_bias: false` is f32), experts stacked `mlp.experts.{gate,up,down}_proj`, shared `mlp.shared_experts.*`. Mirror: `rapid-mlx/Ling-3.0-tiny-MLX-4bit` (affine 4-bit gs64, 4.2 GB).

**KDA (Kimi Delta Attention)** rides the GatedDeltaNet path with three differences, each its own config field. (1) The forget gate is per KEY CHANNEL, not per head: `f_proj` is [hidden → H·Dk] and the fused kernel indexes `g` by the key channel (`kda_vector_gate` → the `_vec` kernel variant; `gdnKernelSource(vectorized, capture_seq)` generates all four kernels from one recurrence so the math exists once). (2) The gate FORMULA is the bounded-sigmoid arm of fla's kernel — `g = exp(bound · σ(exp(A_log)·(a + dt_bias)))`, bounded in (exp(bound), 1) — which REPLACES `-exp(A_log)·softplus(·)` rather than clamping it; reading `kda_lower_bound` as a clamp gives a plausible, silently wrong recurrence. (3) The output gate is a plain sigmoid (`y_norm · σ(g_proj(x))`), not swish. Load-time normalizations keep the hot path identical to qwen3.5's: the three separate q/k/v projections and three depthwise convs are CONCATENATED on the output-row axis (exact — affine groups run along the input axis and depthwise channels never mix), and `A_log` [H] is EXPANDED to [H·Dk] so the gate chain is pure elementwise over flat arrays. The blocked prefill kernel declines on a vector gate (it reads a per-head gate); q/k scaling is already KDA's (`l2norm(q)·Dk^-0.5`).

**MLA** is the DeepSeek-V3 shape in its NAIVE (un-absorbed) form: `q_a_proj`(256) → `q_a_layernorm` → `q_b_proj` → [128 nope | 64 rope] per head; `kv_a_proj_with_mqa` → [512 latent | 64 shared rope key] → `kv_a_layernorm` → `kv_b_proj` → per-head [128 nope | 128 value]; the rope key is MQA and broadcast across heads so the cached K is a plain `[B,H,S,192]`. RoPE covers the rope slice ENTIRELY at θ 6e6 and rotates ADJACENT PAIRS (`rope_interleave` → mlx `traditional`; the reference de-interleaves both operands before a halves-rotation, and a consistent permutation of q and k leaves q·k unchanged, so the traditional kernel is exact, not an approximation). Scale is `qk_head_dim^-0.5` (192, not head_dim) — `query_pre_attn_scalar` and `prefillScoreHeadDim` both carry it, and `prefillMemoryNeeded` takes the score width SEPARATELY from the stored width for the same reason (billing the composed [heads, chunk, seq] score tensor against `head_dim` 128 declares it fused and bills zero). Per-head sigmoid output gate from `attention.g_proj` (`head_wise`; `element_wise` is refused by name). Output projection is `attention.dense`. The KV cache is ASYMMETRIC (K 192, V 128) — MLX's SDPA has a fused vector kernel for exactly that pair at decode and falls back to the composed path at prefill widths; the quantized-KV fused kernels assume one width for both, so MLA never opts into them. Un-absorbed costs ~10x the absorbed form's cache, which is affordable only because 6 of 24 layers attend at all.

`--kv-quant 4|8` serves this arch: the affine write path solves each of its six buffers' packed and scale widths from ITS OWN operand (K 192 → 48 u32 / 3 groups, V 128 → 32 / 2), and truncation slices the value scale/bias views against the value scales' shape. The fused quantized-KV READ kernels still assume one width for both, so MLA never opts into those — it reads `denseView`.

Memory: `ModelConfig.kvBytesPerToken()` is the ONE KV bill — `attnCacheLayerCount()` (linear layers hold a fixed-size recurrent state, not a per-token cache) × kv_heads × (K width + V width). The old uniform `layers × 2 × kv_heads × head_dim` over-billed this arch 3.2x and pinned auto-context to under a third of what fits. Both the auto-context sizer and `prefillMemoryNeeded` read it, source-scan-pinned at the call site.

MoE routing is hy3's sigmoid+bias chain with DeepSeek's group limit inserted between the bias and the top-k (`n_group` 8 / `topk_group` 4, `noaux_tc`), which `groupLimitedRouting` already implemented for dsv4 — `computeHy3Routing` dispatches to it on `moe_n_group > 1`. That chain deliberately returns f32 weights and it is the CALLER's job to land them in the activation dtype; skipping the cast promoted the residual stream to f32 at the first MoE layer (visible only as a `[dtype-trace] residual widened` line, and it promotes every weight on read for the rest of the forward).

Chat: `chat_template.jinja` with `<role>SYSTEM|HUMAN|ASSISTANT|OBSERVATION</role>` turns, `<|role_end|>` (156895) as the sole terminator, and GLM-style tool calls (`<tool_call>NAME<arg_key>K</arg_key>\n<arg_value>V</arg_value></tool_call>`) that the existing glm-family parser already handles. `thinking_option` defaults to 'on' and the generation prompt opens `<think>` — `defaultEnableThinking` opts in so the vendor's default mode is reachable from a request that names no preference. Refused by name at config parse rather than served wrong: low-rank KDA gates (BOTH spellings — `no_kda_lora: false` and `use_kda_lora: true`), `element_wise` attention gating, a non-sigmoid `score_function`, a `kda_lower_bound` of 0 or more, a `qk_head_dim` disagreeing with nope+rope, an absent `q_lora_rank`/`kv_lora_rank`, NoPE MLA (`use_mla_nope`), a linear-attn head count of its own (`num_kv_heads_for_linear_attn`), `linear_silu: false`, and the norms the forward does not implement (`value_norm`, `up_proj_norm`, `use_nGPT`). An ABSENT `kda_lower_bound` is not a refusal — it SELECTS fla's other arm, the softplus gate, which the shared chain computes elementwise and therefore serves per-channel unchanged (`kdaUsesBoundedGate`). `kda_safe_gate` is a launch detail of the reference kernel, not a formula: both arms are evaluated in f32 here. Guards: the config-parse test in model.zig, the vectorized-gate kernel equivalence + `kdaGateChain` tests and the asymmetric-KV test in transformer.zig, `kvBytesPerToken` in server.zig, and `tests/test_bailing_hybrid.sh`.

A draft kept to fewer rows than drafted indexes q by the drafted stride. When the context already holds the continuation (an echo, an edit, a repeated block: `mtpLookupIndex`, match of 8+ tokens, the one of the last 8 occurrences that agrees furthest back: `matchBest`) the round copies it instead (`dflashCopyRound`, no assistant forward, up to 15 drafts; `CopyStats` learns the hit rate per match length; `MLX_SERVE_DFLASH_COPY=0` turns it off), which needs verify windows past 8 rows: hcPre, the routed-expert decode kernels and the latent attention take up to 16 rows (`HC_PRE_MAX_ROWS`, `MOE_DECODE_MAX_ROWS`); the KDA step runs 9-16 rows as two 8-row launches (`kda_recurrence.MAX_WINDOW`) and a row window keeps each expand deferred into the next `hcPre`. Parity: `glm5_next verify windows of 2..16 rows` (`GLM5_REAL_MODEL`, the pack itself). `[spec-stats] mode=dflash` reports `plain=`, `skipped=`, `probes=`, `acc_pos=` (conditional acceptance by draft position) and `rows_hist=`; `--log-level debug` prints each round's confidences and outcome (`[dflash-round]`). Parity: `glm5_next DFlash capture` (one-shot, chunked and per decode step against the reference's own layer means, cosine and RMS ratio); live: `tests/test_glm5_next.sh` [10] with `GLM5_DRAFTER`.

**Selection.** A query at absolute position below `dense_end = (topk/kpool + 1) * kpool - 1` (2051) has every earlier pool in budget, so its attention is plain causal; prefill runs those rows on lifted keys (`glmHeadMm` into per-head K/V, MLX sdpa) and the rest through the indexer (pooled keys, NAX scores in chunks of `2^27 / P` rows, argpartition, chronological sort, expansion with the query's partial tail pool), then the NAX sparse latent kernel. One decode query runs `decodeSelect`: a fused kernel pools each key from the cache rows and scores it (lane = indexer head), then one threadgroup radix-selects the top 512 pools and writes the expanded token list in order. Decode attention folds the 64 heads into the GEMM's M (`latentAttendFolded`): MLX's sdpa declines a GQA factor past 32 and its fallback reads the keys once per head.

**Decode.** Per sublayer the critical path is one `hcPre` dispatch: 16 threadgroups each take a K-slice of all 24 mixes, the last to arrive reduces them, collapses, applies the sublayer's RMSNorm and writes post/comb; the expand is deferred and the next `hcPre` rebuilds each stream element as `expand` would (same fma order and rounding). KDA layers run oMLX's one-token step (conv, l2 norms, low-rank gates, gated delta rule, gated norm in one dispatch per layer); MoE layers oMLX's gate/up and down + combine kernels with the shared expert inside. Ubench (M5 Max, short context): 18.99 -> 17.2 ms per forward; marginals KDA 5.3 ms (34 layers, near the 8-bit weights' bandwidth floor), MoE 7.2 ms (floor ~5.3), DSA 1.95 ms, mHC 1.25 ms.

**Indexer cache.** Each token's indexer row is key | gate; the row that completes a pool (position % 4 == 3) stores the pool's key in its gate half (`glm5.withPooledKeys`, from the up-to-3 cached rows before the forward), so selection reads pooled keys as a strided view instead of re-pooling the whole cache every token (`cacheLayoutNamespace` = `glm5-pooled-keys-v1`). Below the indexer budget nothing reads that cache, so the attention output depends on it explicitly (`glm5.withDependency` over `mlx_depends`); without that, the rows stayed one lazy chain across tokens until the first read past 2051. Decode projections `embed_q`/`unembed` run oMLX's per-head qmv (`glm5.headQmv`), the attention scale folded into `embed_q`'s rounding.

## ANE prefill rules

Moved verbatim from CLAUDE.md on 2026-09-02 (size cap). Stories: `docs/gotchas/engine-mlx.md`.

- **ANE compile STAGING must stay in $TMPDIR** (aned can't read home paths); cache entries in `~/.mlx-serve/ane-cache`. **A single deep-K ANE conv is a 2.6x cliff**: K-chunk past ~4.6k inputs in-graph; ONE compiled tile width (`denseMLPMaybeAne`), tails run GPU; `msv_ane_model_eval` returns 1 on SUCCESS.
- **fp16 plane row pitch must be ≡ 0 mod 32 — off-grid tiles compile fine then fail EVERY eval** ("Program Inference error"; the v2 share-0.35 collapse). `aneShareRows` floors to 32; both C emitters refuse by name.
- **The ANE tile is sized by `effectivePrefillChunk`, never the pin alone** (scan-pinned) — a bare-pin tile is built-but-never-dispatched. **ANE prefill is M4-AND-BELOW** (`anePrefillAllowed`; M5 Max measured a LOSS; `MLX_SERVE_ANE_FORCE=1`).
- **Channel mode is the default split** (`MLX_SERVE_ANE_MODE`, shares channel 0.45 / row 0.40): output-channel slices at ffn'=k, GPU rest via axis-0 packed VIEWS (bit-exact), boundaries on `CHANNEL_ALIGN` 128, down partials ADD at the seam. A failed channel eval recomputes the WHOLE layer.
- **ANE I/O planes shared per SHAPE CLASS within a unit** (evals serial; 3 surfaces replace 224; never memset at bind). **MoE gets GDN-ONLY coverage** (shared expert ~5% ceiling; +3.9% at 16k).
- **Media gen offloads through the SAME channel seam, opt-in** (`--ane-image` `krea.aneEnsure`; `--ane-video` `Model.buildAne`; `--ane-audio` `Engine.buildAne`; all read `ane.media_offload`, decided by `ane.planMediaOffload`): ONE compiled 256-row tile (`ane.MEDIA_TILE_ROWS`) looped over every request through the one seam `ane.mediaMlp`, so every request size shares one program set (disk fixed per model and share, no cold compile for a new size). A partial last tile is zero-padded onto the ANE when `tail > 256 x (1 - share)` (`ane.mediaTilePlan`), else it runs the full GPU MLP, submitted with the complement BEFORE the tile loop. Against a whole-request tile on M4 Max: Krea -0.6%, ACE 180 s tie, H3 -1..2%/step, ACE 30 s -7% (140 ms of 2 s). Bar = perceived content, never bytes (Krea cos 0.9993 same fox; H3 cos 0.9987 same shot). Share tables: "Media offload share" below.
- **The fp16 range scale is the load-bearing part** (`ane.OUT_PLANE_SCALE` 256): the ANE graph computes fp16 throughout, so `act = silu(gate)*up` AND the down-conv output must stay under 65504. Fold it into the `up` copy (linear into the product, exact through per-row int8) and multiply back on read — never into `gate`, which sits under a nonlinearity.
- **A per-request staged model rebuilds the engine per request** (H3: cold 32 s / warm 8 s, 4.9 GB int8).
- **An ANE build under 1 GiB internal free disk is REFUSED** (`BUILD_DISK_FLOOR_BYTES`, probe `/private/tmp`). **The compile cache prunes by LINEAGE then by BYTES** (`bridge_cache_prune`): the builder names its group (seam + layers×hidden×ffn) and variant (share) via `msv_ane_cache_lineage`; same-group other-variant entries go first (a share sweep once stacked 7.9 GB for five values), then LRU past a cap = min(`MLX_SERVE_ANE_CACHE_CAP_GB` 40, volume free + cache − `CACHE_DISK_RESERVE` 8 GB). A fixed cap above free space was no cap: a full disk ships SILENT PARTIAL COVERAGE (`ready: N/M` under-count is the tell).
- **The media gate bills the BUILD PEAK too** (`mediaGateRefusal`: total-RAM bill, then int8 copy + `buildPeakBytes` = 4 × hidden × ffn × f32 against what is available now under a 4 GB `SWAP_FLOOR_BYTES`). The total-RAM gate alone admitted 6.8 GB on a 32 GB M1 Pro beside a 14.7 GB pack and swapped ~380 MB inside the ranked request with nothing logged.
- **A compile session's budget is the INTERNAL free disk at boot (~260 MB/program); in-session retries are futile** — a cold build CONVERGES across boots (converge-then-measure).
- **A killed ANE server leaks staging (8–20 GB/boot); the framework OWNS `$TMPDIR/<identifier>`**: `msv-ane.pid` markers, first create reaps dead owners; deleting a LIVE program's staging is unsafe (only weights blob + MIL text deletable post-load). Guard: `tests/test_ane_prefill.sh`.
- **fp16 planes are 1-ulp different from f32; byte-identity is not the ANE bar** — per-program cos/rms parity + perceived-content greedy equivalence.
- **GDN input projections ride ONE fused ANE conv** (`msv_ane_gdn_create`: qkv + z stacked; `gdnProjMaybeAne` seam; combined-proj archs stay GPU; `MLX_SERVE_ANE_GDN=0`); EACH seam logs its own engagement line.
- **int4/sub-byte ANE weights are a NO-GO on macOS 26.x aned** (bisected) — ANE copy stays int8, billed per model (`engineBillBytes` + `gateAllows`, headroom 12 GB). Probe convs need ROWS≥32.
- **A pinned second ANE is DEFAULT on M3 Ultra (+7.1%), opt-in elsewhere; a SILENTLY ignored affinity hint is undetectable in-process** (`MLX_SERVE_ANE_DUAL`): `kANEFAneInstanceHint` AND `kANEFProcedureVariantHint` together at compile+load+eval; instance 0 keeps `@{}`; verify with `macpow --dump | grep ANE0_`. Per-unit planes; input packed once then memcpy'd.
- **The ANE program is a procedure BANK (runtime caps ~121 handles)**: symbol indices READ from `procedureInfoForProcedureIndex:` on the `_ANEModel` behind `-model` (NOT `inputSymbolIndicesForProcedureIndex:`, which answers 0 and fails every procedure >0 as a swallowed slowdown; `eval_failures` is the tell). Cap `MLX_SERVE_ANE_BANK_MAX_BYTES` 2 GiB, halves down a ladder; never a coverage decision.
- **The ANE split's optimum is per SILICON** (`ane.defaultShare`; M4 channel 0.45 → 311/304, 0.50 regresses; M3 Ultra 0.45 ≈ nothing, 0.35 +8.5%/+13.7%). A share change needs its own A/B, never interpolation. fp16 down-conv wears the (1/16..x16) pow2 wrap.


### Media offload

Moved from AGENTS.md on 2026-10-04 (size cap).

- **A denoise step is the ANE case the LM prefill seam never was** (opt-in, LOSSY: `--ane-image` Krea, `--ane-video` H3, `--ane-audio` ACE-Step; ONE value `ane.media_offload` set in `main()`): batch job at the compute roofline; ONE compiled 256-row tile, looped (`ane.mediaMlp`), serves every step AND every request size, so the ANE cache never grows per size. Tables: `docs/reference.md`.
- **The media share is CALIBRATED once per (chip, model), then STICKS** (`ane.planMediaOffload` → `calibrate`): block 0 alone, compiled at the probe's seed, timed on the ANE and GPU over the same 4096 rows, the GPU fed the dtype the MLP really sees (bf16 ones read ACE's f32 GPU 27% fast); later builds reuse the set's `calibrated share=` tag (`ane.cachedShare`; an explicit `--ane-split` never is), since re-solving recompiled + pruned on size and probe jitter.
- **The ANE compile cache is capped by FREE DISK and pruned per LINEAGE** (`msv_ane_cache_lineage`: same seam+shape, other share → gone on the next cold compile; byte cap = min(40 GB, volume room − 8 GB reserve)): a fixed cap above free space is not a cap, and two small-disk boxes shipped `ready: N/M`. The gate bills the build's f32 transient against a 4 GB swap floor (`mediaGateRefusal`), refusing by NAME.
- The seam is the channel-mode one (`ane.packUnitPlanes`/`readPlane`/`dequantToHostF32` shared with `transformer.zig`): ANE holds gate/up channels [0..k) + the matching down K-slabs, GPU the complement, partials ADD. H3's fc1 is FUSED, so its complement is TWO row views (`aneBuildRest`).
- **The ANE graph is fp16 END TO END, so a partial-sum seam must SCALE** (`ane.OUT_PLANE_SCALE` 256, folded into the `up` copy at build time, multiplied back on read — exact: per-row int8 puts it in the row scale, and `up` is linear into `silu(gate)*up`). Unscaled, H3 saturated to INF from block 36 and rendered BLACK; Krea only lost precision (cos vs GPU 0.996 -> 0.9993).
- **A LoRA-attached block DECLINES** (`aneBlockEligible` in both): the adapter is summed at forward from the FULL activation, half of which never leaves the ANE program. Turbo binds `blocks.N.mlp.fc1/fc2`, so H3's fast path is GPU-only until the LoRA is folded into the int8 snapshot.
- **GPU work built AFTER a blocking ANE wait is serial, and a small piece of it is LAUNCH LATENCY, not rows** (`ane.mediaMlp`). Every GPU piece goes out with the complement BEFORE the loop; a partial tile pads onto the ANE only past `tail > T x (1 - share)` (`ane.mediaTilePlan`).
- **H3 stages the DiT per REQUEST, so the ANE build is paid per request**. Caching the engine across requests is owed.

### Media offload share (2026-09-10)

The LM prefill share is a per-silicon table because the seam races a live decode; a denoise step is a batch job, and its optimum is per **(chip, workload)**. Balance point `s* = A / (A + G)`: A = the ANE's rate on our int8/fp16 MLP program (11.8 TFLOPS, the same 16-core engine on every M1–M4), G = the GPU's rate at this model's MLP shape, which `ane.probeGpuTflops` times with one quantized matmul at a fixed `MEDIA_PROBE_ROWS` (4096). That solve is only the SEED: `ane.calibrate` compiles block 0 alone at it, runs MEDIA_PROBE_ROWS worth of its ANE tiles on a helper thread while the GPU evaluates its complement over the same rows (fed the dtype the MLP really sees: ACE and Krea stream f32), and `calibratedShare` balances the two timings on a 0.01 grid. It costs 0.3-0.7 s once per model. `solveShare` clamps to [0.25, 0.85]; `channelSliceWidthUnits` floors to `CHANNEL_ALIGN`. The plateau near the peak is ~6% wide (M4 base), so landing near is enough. Unknown silicon (M5+, unreadable brand) keeps 0.45. `--ane-split` / `MLX_SERVE_ANE_SPLIT` always wins. Calibration runs ONCE per model: every later build reuses the share of its most recently used compiled set (`ane.cachedShare`, the entry's `calibrated share=X` lineage tag; an explicit share or an uncalibrated seed tags plain `share=X` and is never reused; a build-time cache hit re-tags the entry). A re-solve per build recompiled + pruned the whole set on every request size and on probe jitter.
